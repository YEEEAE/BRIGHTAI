الخلفية الحالية جزء ثابت من الهوية وليست موضع إعادة تصميم. حافظ حرفيًا على العقد التالي:

## 4) النتيجة التصميمية المطلوبة

أنشئ نظامًا موحدًا لأسطح القراءة والأقسام فوق الفيديو، باستخدام التوكنات والمكونات الحالية، بدون dependency جديدة وبدون تغيير framework.

### 4.1 أسطح القراءة المحلية

أنشئ/وحّد variants دلالية، مثل:

- `media-reading-surface--hero`: رسالة الهيرو والإجراءات الأساسية.
- `media-reading-surface--section`: عنوان القسم ووصفه ومحتواه المترابط.
- `media-reading-surface--prose`: المقالات والوثائق والنصوص الطويلة.
- `media-reading-surface--compact`: callout أو تعريف قصير.
- `media-reading-surface--proof`: الثقة، الشعارات، المقاييس، والأدلة.
- `media-reading-surface--cta`: الدعوات النهائية والنماذج المختصرة.

يمكن تغيير الأسماء لتناسب conventions الحالية، لكن يجب أن تكون دلالية ومركزية وليست selectors متفرقة لكل صفحة.

المواصفات:

- استخدم `--surface-on-media` والتوكنات التابعة له كمصدر حقيقة.
- سطح داكن كحلي شبه شفاف يضمن التباين على أسوأ إطار أبيض وأسود للفيديو.
- border داخلي خفيف، radius متسق، وshadow ملوّن هادئ عند الحاجة.
- blur محلي فقط وعلى عدد محدود من الأسطح؛ لا تنشئ عشرات compositor layers في viewport واحد.
- في `prefers-reduced-transparency: reduce` استخدم سطحًا opaque بالكامل بلا blur.
- في print أزل الفيديو والشفافية والـblur، وحافظ على نص أسود/أبيض واضح حسب عقد الطباعة.
- لا تجعل كل بطاقة داخل سطح قسم كبير تحمل طبقة زجاجية ثانية بلا داعٍ. استخدم طبقة واحدة واضحة ثم عناصر داخلية أخف.
- اجعل الشعارات والأيقونات الداكنة قابلة للتمييز عبر surface/plate محلي أو نسخة لون مناسبة، بدون تغيير العلامات الرسمية أو ادعاء اعتماد.

### 4.2 بنية الأقسام وإيقاع الصفحة

- أزل الارتفاعات الثابتة أو `min-height` المفرطة عن أقسام المحتوى العادي. استخدم `min-height` فقط عندما تخدم قصة بصرية حقيقية.
- اجعل ارتفاع القسم ناتجًا من المحتوى مع padding responsive متزن.
- استبدل stacked margins بعقد `gap` واحد داخل section container.
- حافظ على max-width عام 1200–1440px، وعلى readable measure للنص المستمر بحد يقارب 60–65ch.
- على الجوال: padding أفقي لا يقل عن 16px، ولا عنصر نصي يبدأ خارج viewport، ولا heading بعرض أكبر من حاويته.
- اجعل عناوين الأقسام ووصفها ومحتواها وحدة بصرية واحدة، لا عنوانًا في بطاقة وإجابته في بطاقة بعيدة.
- استخدم grid responsive ينهار إلى عمود واحد طبيعيًا. لا تستخدم transform أو negative margin يسبب قصًا في RTL.
- اضبط `text-wrap: balance` للعناوين و`text-wrap: pretty` للفقرات المدعومة، مع fallback سليم.
- ثبّت اتجاه RTL والخصائص المنطقية. اعزل الإنجليزية والأرقام بـ`dir=ltr`/`bdi` عند الحاجة.
- كل targets التفاعلية المهمة 44×44px على الأقل، مع focus visible واضح.

### 4.3 إعادة كتابة المحتوى

حسّن النصوص فعليًا، ولا تكتفِ بتغيير CSS:

- لكل قسم، استخرج رسالة أساسية واحدة واكتبها كأول جملة مباشرة.
- اجعل أول 40–60 كلمة تجيب عن سؤال القسم بوضوح وتخدم GEO.
- متوسط الجملة 15–20 كلمة، وفكرة واحدة لكل جملة.
- الفقرة 3–4 جمل كحد أقصى، وموضوع واحد لكل فقرة.
- جزّئ الكتل الطويلة إلى عنوان وصفي + جواب مختصر + نقاط أو خطوات عند وجود 3 عناصر أو أكثر.
- استخدم العربية الفصحى المبسطة بلمسة سعودية مهنية. لا تكثر العامية، ولا تستخدم لغة تسويقية فضفاضة.
- استبدل العبارات العامة مثل «حل شامل» و«تقنية متطورة» بوظيفة أو نتيجة محددة قابلة للإثبات.
- لا تختلق أرقامًا أو شهادات أو أسماء عملاء أو claims امتثال. أي claim غير موثق يُحذف أو يُخفف إلى صياغة دقيقة.
- حافظ على المصطلحات القانونية والتقنية الضرورية، وعرّفها عند أول ظهور. لا تبسّط نصًا قانونيًا بطريقة تغيّر معناه؛ أضف summary مبسطًا واترك النص الأصلي عند الحاجة.
- اجعل روابط CTA وanchor text مفهومة خارج السياق: ممنوع «اعرف المزيد» أو «اضغط هنا». مثال: «استعرض حلول حوكمة AI» أو «اقرأ دليل PDPL للذكاء الاصطناعي».
- لا تغيّر intent الصفحة أو الكلمة الأساسية أو H1 بلا سبب موثق. حافظ على SEO metadata وcanonical وhreflang وJSON-LD وFAQ/Article/Breadcrumb schemas.
- حافظ على IDs والروابط الداخلية وdata attributes التحليلية وعقود الاختبارات، إلا إذا كان تغييرها ضروريًا وتُحدّث كل المراجع والاختبارات بدون إضعافها.

## 7) معايير القبول الرقمية

### الخلفية والتباين

- `pnpm bg:verify` ناجح.
- `pnpm bg:contract` ناجح.
- `verify-background-contract.mjs` = 95/95.
- `verify-contrast-on-media.mjs` PASS لكل text token المعتمد على إطار أسود وأبيض.
- `globalScrim = 0`، `multipleVideos = 0`، `noVideo = 0`، و`duplicateVideoRequests = 0` لكل المسارات المشمولة.
- `bareTextOnMedia = 0` و`bareTextOnMediaNodes = 0` بعد تصحيح أي false positives في الحارس باختبارات مثبتة، لا بتجاهل العناصر.

### الاستجابة والوصول

- فحص 100% من routes × 8 viewports لكل app الممكن تشغيله.
- فحص كل template مع `--reduced-motion` و`--print` و`--zoom=2` و`--shots`.
- `horizontalOverflow = 0`.
- لا H1 أو paragraph أو CTA يبدأ خارج viewport عند 360px.
- H1 واحد ظاهر لكل صفحة عامة.
- لا محتوى أساسي مخفي إذا تعطلت JavaScript أو reveal.
- لا clipping لمعلومات أو أزرار أو روابط.
- كل CTA/action أساسي 44×44px على الأقل.
- contrast يحقق WCAG 2.2 AA: 4.5:1 للنص العادي و3:1 للنص الكبير والعناصر الرسومية.
- keyboard وfocus وEscape والقوائم تعمل، وaxe بلا critical أو serious في العينة الكاملة الممكنة.

### المحتوى وSEO

- كل قسم يملك رسالة أساسية واضحة في بدايته.
- لا فقرة مستمرة تتجاوز readable measure المتفق عليه.
- لا generic link text.
- لا claims جديدة غير موثقة.
- `pnpm seo:gate` و`pnpm seo:schema` و`pnpm seo:hreflang` ناجحة.
- canonical وhreflang وJSON-LD وbreadcrumbs وsitemap لا تتراجع.

## 8) مخرجات التسليم الإلزامية

1. التعديلات المحلية مكتملة وقابلة للمراجعة.
2. تقرير Markdown جديد داخل `docs/audits/` يتضمن:
   - before/after حسب عائلة الصفحات.
   - الملفات المالكة لكل إصلاح مشترك.
   - نتائج Chrome على 360 و1440.
   - نتائج layout-audit الخام والملخصة.
   - contrast ratios الفعلية.
   - قائمة النصوص المهمة التي أُعيدت صياغتها ولماذا.
   - أي نص قانوني/تقني تم flag له بدل تغييره.
   - regressions التي اكتُشفت وكيف أُغلقت.
3. JSON audit متطابق حسابيًا مع تقرير Markdown.
4. screenshots قبل/بعد منظمة حسب route family والمقاس.
5. تحديث `.agents/mind/01-mind-latest.md` بأعلى الملف بسجل منظم: التنفيذ، الملفات، الأرقام، التحقق، النتيجة، والمشاكل المفتوحة.
6. في الرد النهائي: اذكر النتيجة والأرقام أولًا، ثم الملفات، ثم التحقق، ثم ما بقي مفتوحًا. لا تقل «اكتمل كل شيء» إذا بقي app أو route family غير مفحوص.

## 9) قواعد القرار

- أصلح السبب المشترك في layout/component/token قبل route override.

- الأولوية: وضوح الرسالة → التباين → إعادة التدفق → الإيقاع → الزخرفة.
- أي قرار يضعف ظهور الخلفية أو يغير أبعادها مرفوض.
