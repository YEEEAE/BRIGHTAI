## 0. حدود الواقع المثبت

الصفحة موجودة في المصدر `src/pages/products/[product].astro`؛ العنوان الحالي **AIGAS Human Gate** مع صيغة «تصور المنتج» ووسم الحالة «مخطط · غير متحقق تشغيلياً». يعرض `ProductExperience.astro` أربع مراحل شرح ضمن `approval-flow` ومثالًا موضّحًا لانتظار/قبول/رفض؛ وتضبط `interior-motion.ts` الحالات **داخل المتصفح**. لا يثبت ذلك وجود API أو موظفين مخوّلين فعليًا أو سجل قرار موثوق أو تنفيذ مسار محكوم. حالات الأزرار تبدأ مع `disabled` في HTML قبل التهيئة؛ لم يُنفّذ تحقق Browser مستقل لهذه النسخة أثناء إعداد هذه الوثيقة.

هذه الوثيقة **مواصفة تصميم ومحتوى** ولا تفوّض تعديل الكود أو الرئيسية/الهيدر. التزم `AGENTS.md` وProject Mind؛ المسارات الداخلية المقترحة للمؤسسة غير موجودة بالضرورة.

## 1. أهداف تجربة الصفحة

1. يميز الزائر بين شرح مفهوم Human-in-the-Loop وبين خدمة موافقات تُنفذ فعلًا.
2. يفهم أن **المهمة تحتاج توقفًا حقيقيًا** إلى أن تكتمل مراجعة مخولة.
3. يعرف فوائد SoD والموافقة متعددة المراحل والتفويض المقيد والتصعيد.
4. يدرك أن الرفض والانتهاء لا يسمحان بإكمال العملية، وأن الحظر الإلزامي لا ترفعه موافقة.
5. يصل إلى استفسار واضح دون إرسال بيانات إنتاج أو الإيهام بتجربة مفعّلة.

## 2. عقد التصميم والهوية

- هوية BRIGHT AI المعتمدة: خلفية داكنة، بنفسجي `#8052FF`، زعفراني `#FFB829`، أخضر `#15846E` ضمن نظام الألوان؛ اللون لا يحمل معنى أمنيًا دون نص.
- عنوان رئيسي واضح بالعربية، مع `bdi` لأسماء المنتج والمعرفات والتوقيت، وبخط عربي مقروء؛ لا تكرار لأساليب تصميم الصفحات الأخرى.
- كل حركات الموافقة والرفض وتبديل الأقفال **تعليمية**، وسم ثابت «توضيح تعليمي · لا اتصال بخدمة».
- نصوص `aria-live` تعلن النتيجة النهائية فقط؛ أزرار تفاعلية باللوحة، وضوح Focus، لا الاعتماد على hover.
- `prefers-reduced-motion` يعرض حالة نهائية فورية؛ المحتوى موجود في HTML دون JavaScript؛ وعند تعطيله تُعرض المراحل كنص.
- لا تضع عنوان API أو Data/Live Status أو Client Name أو شهادة امتثال غير موثقة.
- لا تعدّل الهيرو أو الهيدر أو الرئيسية المحمية دون توجيه مالك جديد صريح.

| `DEMO_APPROVED` | موافقة توضيحية لمهمة خيالية محددة | رسم قفل يفتح مرة واحدة | لا تعرض تنفيذًا فعليًا أو سماحًا خارجيًا |
| `DEMO_REJECTED` | رفض توضيحي؛ تبقى العملية متوقفة | توقف خط المسار | لا تعرض نجاحًا أو متابعة |
| `DEMO_EXPIRED` | انتهت المهلة الافتراضية؛ أوقف المسار | تغيّر لون ومسار | لا تحويل إلى قبول صامت |
| `DEMO_UNAUTHORIZED` | هذا الدور غير مخول للاعتماد | رسالة نصية مفهومة | لا تسمح لزر Demo بتغيير هوية مستخدم |
| `DEMO_SOD` | مقدم الطلب لا يعتمد طلبه في السياسة التي تشترط الفصل | سهم محجوب | لا تعارض النص الحقيقي للقيد |
| `DEMO_SCOPE_CHANGED` | تغيّر العمل بعد الموافقة؛ يلزم طلب جديد | تفصل بصمة العملية عن الإذن | لا إعادة استخدام grant |
| `DEMO_OFFLINE` | المثال لا يتصل بمحرك حقيقي | بطاقة ثابتة | لا عرض Loader يوهم اتصالًا فعليًا |

## 6. بوابة المؤسسة المستقبلية — ليست مسارًا منشورًا

**تمييز:** هذه مواصفة مستقبلية، وليست صفحة موجودة. الروابط الداخلية/الأسماء التالية تصميمية وتحتاج اعتماد هيكل المسارات وAuth.

| شاشة مقترحة | بيانات الحد الأدنى | الإجراءات المخوّلة | الحالة/الرفض |
|---|---|---|---|
| Inbox / طلبات بانتظار المراجعة | معرف الطلب، الغرض، الوقت المتبقي، المرحلة | استعراض فقط إذا `approval.request.read` | بدون صلاحية → 403/لا إفشاء |
| Request Detail | البصمة والسياق والسبب والسياسة والمراجعون | قبول/رفض *فقط* بدور مخول وتحقق SoD | `EXPIRED`, `CANCELLED`, `ALREADY_DECIDED` تمنع الإدخال |
| Decision Form | نص سبب القرار ومجاله ومرجع السياسة | تأكيد قرار مع step-up إذا تطلبت السياسة | لا يوجد «موافق» افتراضي؛ لا اعتماد ذاتي |
| Escalation & Delegation | نطاق/سبب/وقت/صاحب التفويض | تصعيد أو تفويض ضمن المجال | منع تفويض أعلى من سلطة الموكّل |
| Evidence Timeline | الفاعل والتوقيت والمرحلة والنتيجة | قراءة/تصدير محدود | إخفاء المحتوى الحساس وتعقب الوصول |
| Integration Status | حالة نقطة الإيقاف ومعرف العملية | تحقق حالة grant دون كشف السر | لا مساواة `APPROVED` مع `EXECUTED` |
| Policy Configuration | نسخة سياسة ومراحل ونصاب ومهلة | تحضير/مراجعة/اعتماد متعدد الأطراف | منع التغيير الصامت للسياسات النافذة |

**قواعد عرض الحالات الحقيقية المستهدفة:** `PENDING`, `IN_REVIEW`, `APPROVED`, `REJECTED`, `EXPIRED`, `CANCELLED`, `AUTHORIZED`, `CONSUMED`, `ENFORCEMENT_FAILED`. قد تحتاج حالة workflow أدق في API، وأي اختلاف يراجَع مع Product/Engineering. لا يجوز إعادة ترميز `EXPIRED` إلى `APPROVED` أو إلغاء معلومة فشل الإنفاذ.

## 7. توزيع أدوار الواجهة

- **Requester:** إنشاء/استعراض طلباته، إلغاء ضمن سياسة؛ لا اعتماد ذاته عند SoD.
- **Reviewer:** قرار ضمن نطاق صريح؛ لا إجراء خارج دوره أو طلبه.
- **Approver of higher tier:** المرحلة الأعلى بعد تحقق سريان المرحلة السابقة.
- **Delegation administrator:** تفويض نطاق أصغر وبمدد صالحة، مع سجل الأفعال.
- **Auditor:** قراءة أدلة مرخصة دون قدرة إصدار موافقات.
- **Integration service:** إنفاذ/استهلاك grants عبر مصادقة service identity منفصلة؛ ليست أزرار متصفح.

## 8. حالات الطلب وأزرارها الفعلية المستهدفة

| حالة الطلب | أزرار ممكنة حسب الدور | أزرار ممنوعة |
|---|---|---|
| `PENDING` | استعراض، إلغاء مخول، توجيه | تنفيذ الآن |
| `IN_REVIEW` | قبول/رفض مخول، تفويض/تصعيد بحسب السياسة | self-approve مخالف لـSoD، تنفيذ |
| `APPROVED` | عرض السبب والنسخة؛ محاولة تحصيل grant من خدمة موثوقة | قبول ثانٍ عشوائي، تغيير النطاق |
| `REJECTED` | عرض، طلب جديد بموافقة منفصلة إذا سمحت السياسة | Continue/Execute |
| `EXPIRED` | عرض السبب، فتح طلب **جديد** إذا جاز | Reopen silently، Execute |
| `CANCELLED` | عرض | Reapprove/Execute |
| `AUTHORIZED` | تحقق/استهلاك ذري بواسطة service | استهلاك من المتصفح أو خدمة أخرى |
| `CONSUMED` | عرض أثر الإنفاذ | إعادة تنفيذ grant |
