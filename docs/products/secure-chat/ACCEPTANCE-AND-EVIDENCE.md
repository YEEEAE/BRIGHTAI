## 0. مبدأ القرار وحالة المنتج

**الحالة الحالية: `NOT_VERIFIED` لجميع المعايير التشغيلية.** هذه قائمة قبول وليست تقرير تنفيذ. لا تحسب الرسائل التوضيحية الجاهزة أو أزرار المثال أو تنقيح الشاشة شهادة نجاح لحماية طلب/استجابة من نموذج حقيقي.

حالات تقييم كل معيار:

- `PASS`: دليل من نفس الإصدار والبيئة وطريق التنفيذ، أُعيد فحصه ووافق عليه مختص.
- `FAIL`: تحقق مُجرى أظهر مخالفة أو خللًا.
- `BLOCKED`: لا يمكن إكمال التحقق لغياب بيئة/صلاحية/بيانات اعتماد؛ لا يُحسب نجاحًا.
- `NOT_VERIFIED`: لا يوجد دليل تشغيل صالح يغطي المعيار بعد.
- `N/A`: استثناء نطاق محدد معتمد لا يعطل حدًا أمنيًا إلزاميًا.

## 1. متطلبات MVP المانعة للإطلاق

1. محادثة حقيقية مع نموذج **مصرح به** في منطقة معالجة معتمدة، وليس نموذجًا موصوفًا في صفحة تسويقية.
2. سياسة No-Training بعقود وتكوين وأدلة تشمل موردي AI؛ لا بيانات عميل قبل استيفائها.
3. `SC-02`: طبقات حماية المدخل والمخرج تعمل قبل التسليم، بما في ذلك مسار البث، ولا تتوقف بغياب رخصة Firewall التجاري.
4. `SC-03`: عزل tenant/session، وخصوصية نص الموظف عن Tenant Admin افتراضيًا، وBreak-glass مضبوط ومراجع.
5. `SC-04`: منع خروج متن المحادثة إلى Security Audit/Logs/Traces أو GA4، وسجل أمان أدنى مستقل دون Ledger.
6. `SC-05`: المشاركة والتصدير مغلقان افتراضيًا مع DLP وموافقة مناسبة عند تفعيل استثناء.
7. `SC-06`: سقف استهلاك متحقق وتوجيه مزود/منطقة لا يُتجاوز، ورفض آمن عند عدم توفر مسار مسموح.
8. `SC-07`: عدم إدخال RAG أو إدارة ملفات أو أدوات تنفيذية كمزايا MVP من غير اعتماد نطاق جديد.
9. جميع عمليات `API-CONTRACT.yaml` التي ستعلن للعامة/للمؤسسات مراجعة للأمان والصلاحيات ونسخ العقود؛ المسارات هنا غير منشورة حتى يتم تنفيذها.
10. توفر أدلة نشر فعلية لخيارات SaaS أو On-Premise أو Air-Gapped **كل وفق النطاق الذي سيباع**.

| ترخيص Ledger غير موجود | Audit أمن أساسي مستمر | غياب سجل أمان لازم |
| مشاركة بلا سياسة | 403 أو منع مماثل | رابط عام أو وصول غير مفوض |
| تصدير مادة حساسة | فحص DLP وموافقة ونطاق | تنزيل غير منقح |
| وصول الحصة أو انتهاء 48 ساعة | رفض دون استدعاء مزود/سحب رسوم | طلب جديد أو فواتير تلقائية |
| تكرار POST بمفتاح Idempotency | نتيجة واحدة وتسوية استخدام صحيحة | رسالتان أو رسوم مضاعفة |
| إعادة تشغيل SSE بعد الإلغاء | عدم مواصلة إفشاء/تحميل تكلفة غير مصرح | استجابة مستمرة خارج صلاحية |
| نسخ بيانات جلسة إلى Analytics | عدم تسجيل المحتوى/PII | تسرب في GSC/GA4/Telemetry |
| محاولة رفع ملف أو RAG | مسار غير متاح ضمن MVP | قبول ملف أو معالجة embeddings |
| تعطيل الإنترنت عن Air-Gapped | استمرار الخدمات المحلية المصرح بها فقط | اتصال Cloud ضروري أو تسرب خارجي |

## 5. ضوابط أدلة القبول

كل دليل مقبول يتضمن: `evidence_id`، `feature_id`، `acceptance_id`، إصدار الكود وصورة البناء، بيئة التنفيذ والنطاق المصرح، تاريخ ووقت مع منطقة، حسابات اصطناعية وأدوار اختبار، نسخ السياسات والنموذج/المزود، خطوات إعادة التحقق، النتيجة المتوقعة والفعلية، روابط لقطات/Traces **منقحة**، والمراجع الذي اعتمد النتيجة.

**ممنوع وضع** محتوى محادثة حقيقي أو أسرار أو رموز وصول أو بيانات مواطنين/مرضى في حزمة الأدلة أو تقارير PoV.

شكل سجل الأدلة المرشح:

```yaml
evidence_id: EV-SC-EXAMPLE
acceptance_id: AC-SC-01-01
feature_id: SC-01.01
release_sha: NOT_VERIFIED
environment: NOT_VERIFIED
policy_version: NOT_VERIFIED
provider_approval: NOT_VERIFIED
steps_ref: null
observed_outcome: NOT_VERIFIED
redacted_artifact_ref: null
reviewer: null

```

هذا **مثال بنية فقط**، وليس سجل نتيجة اختبار.

## 6. ربط Proof of Value بمعايير القبول

- `POV-SC-01..20` من `48H-TRIAL-SPEC.md` تمثل تحققًا مؤسسيًا محدد المدة، ولا تحل محل اختبارات قبول أمنية شاملة قبل الإطلاق.
- قياس الاستخدام والتحكم بالمزودين مرتبط بالقبول `SC-06.*`؛ عدم عرض قيم مالية نهائية لا يعفي من إثبات عمل الحدود المعتمدة لكل تجربة.
- نتائج PoV لا تعني اكتمال SaaS أو On-Premise أو Air-Gapped خارج البيئة التي جرى عليها الإثبات.
- محاكاة الموقع العام مفيدة للتواصل لكنها لا تستبدل أي معيار تشغيلي.

## 7. خطة إصدار وأدوار الموافقة

| المرحلة | الحد الأدنى | المخرج | قرار |
|---|---|---|---|
| Design Review | عقود API ودورة البيانات والأمن وNo-Training | قرارات ومعمارية معتمدة | Authorize build |
| Implementation | Backend/Kernel/Identity/Models/Metering حقيقي | نسخة Build موثقة | Authorize security review |
| Security Review | Tenant/AuthZ/DLP/Fail-Closed/SSE/Secrets | أدلة عدم تجاوز وسجل ثغرات | Reject or remediate |
| Privacy Review | محتوى/تدقيق/حذف/مشاركة/استثناء | اعتماد أدوار ومشروعية | Approve scope only |
| Pilot | بيئة معزولة وموافقة عميل وPoV فعلي | تقرير مُنقح بنتائج صريحة | Go/No-Go |
| Release | جميع متطلبات P0 PASS والمعوقات المغلقة والموافقات موثقة | ترخيص وإصدار وعقد | Release approval |

## 8. قاعدة القرار النهائي

**NO-GO** إذا بقي معيار P0 إلزامي غير مثبت أو فاشلًا، أو لم يثبت منع التدريب لدى المزود، أو ثبت تجاوز حدود المستأجر/المحتوى/الميزانية، أو تغير scope بإدخال RAG/الملفات دون اعتماد. لا يُسمح بالاكتفاء بشارة UI أو جدول ميزات مخطط لها في إصدار إنتاجي.

**GO** يتطلب إثبات متطلبات نطاق الإصدار، ومراجعة أمنية وخصوصية وتشغيلية وتجارية معتمدة، والتوافق مع `FEATURE-STATUS.yaml`، وتسليم وثائق العميل الصحيحة. هذه الوثيقة وحدها لا تمنح اعتماد GO.

## 9. قضايا تحتاج اعتمادًا قبل أي إطلاق

- نموذج وموفر ومنطقة معالجة موقعة ومسموح استخدامها.
- سياسة حفظ ومدة احتفاظ/نسخ احتياطية/طلب حذف/Legal Hold.
- صلاحيات الوصول الاستثنائي وفصل المهام ومدته وسبب الاستخدام.
- حدود استهلاك ورسوم أو تقدير تكلفة ناتج عن دراسة معتمدة.
- سياسة فحص المخرجات في SSE وضمان عدم تسرب chunk غير مُجاز.
- طريقة نشر SaaS/On-Premise/Air-Gapped وقياسات أداء فعلية حسب النطاق.
- من يشرف على معايير الامتثال النظامي بحسب قطاع العميل دون ادعاء شهادة.
- تاريخ إطلاق أو Pilot مستقل وتوثيق من صاحب الصلاحية.
