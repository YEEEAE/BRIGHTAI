# AIGAS Secure Chat — إغلاق باب الإرسال والخصوصية والحصص (محلي)

> **التاريخ:** 2026-11-08 · **HEAD المرجعي وقت العمل:** `1681d45e` · **الحالة:** `SOURCE_PRESENT` فقط؛ لا `RUNTIME_VERIFIED` ولا `APPROVED`.
> هذا المستند يوثّق تعديلات محلية وخطة تحقق. لا يثبت نشرًا أو اعتمادًا، ولا يغيّر أي بيئة أو قاعدة بيانات.

## 1. فصل الحالات

| الحالة | المعنى في هذه الدفعة |
|---|---|
| `SOURCE_PRESENT` | مسار الإرسال/الحصص/الإلغاء وسياسة المحتوى موجودة في كود الخادم والواجهة بعد هذه الدفعة |
| `SCHEMA_PRESENT` | `0009` مطبّق (جداول الطلب/الإلغاء/المحتوى). `0016` و`0027` **مسودتان محليتان غير مطبقتين** |
| `CONFIGURED` | لا. `APPROVED_MODELS=[]`، ولا حصة معتمدة، ولا موصل مزود، ولا `AIGAS_SC_LIMITS_APPROVAL_REF` |
| `RUNTIME_VERIFIED` | لا. لم يُشغّل build/HTTP/DB/E2E في هذه الدفعة |
| `APPROVED` | لا. لا اعتماد مزود/نموذج/منطقة/احتفاظ/عدم تدريب ولا اعتماد إطلاق |

## 2. ما أُغلق في الكود

1. **الحصة صارت بوابة إغلاق لا خيارًا.** سابقًا كان `usagePolicy()` يعيد `null` عند غياب `AIGAS_SC_LIMITS_APPROVAL_REF`، فيتجاوز `reserve()` كل الحدود ويسجّل حجزًا بلا قياس. الآن:
   - `usagePolicyStatus()` تفصل `USAGE_POLICY_NOT_CONFIGURED` و`USAGE_POLICY_INVALID` بلا رمي في مسار عرض النماذج.
   - `usagePolicy()` ترمي `503 USAGE_POLICY_NOT_CONFIGURED` أو `USAGE_POLICY_INVALID`، و`reserve()` لا يحجز بلا سياسة معتمدة.
   - `listModels()` لا يعلن `available` إلا بثلاثة شروط معًا: نموذج `READY` + سياسة حصة معتمدة + دالة `aigas_sc_usage_window_v2` موجودة وقابلة للتنفيذ.
2. **لا أرقام استخدام وهمية.** تبقى `usage.tokens=null` و`cost='غير متاح'`، وتُعرض الحدود فقط إذا كانت معتمدة. أُضيف `usage.quotaStatus` كوصف حالة لا كرقم.
3. **حالات الواجهة صريحة:** `NO_APPROVED_MODEL`, `PROVIDER_NOT_CONFIGURED`, `MODEL_APPROVAL_EXPIRED`, `USAGE_POLICY_NOT_CONFIGURED`, `USAGE_POLICY_INVALID`, `USAGE_POLICY_NOT_READY`, `USAGE_LIMIT_REACHED`, `PROVIDER_TIMEOUT`, `REQUEST_CANCELLED`, `PROVIDER_UNAVAILABLE`. زر الإرسال يبقى معطّلًا بخاصية `disabled` المحسوبة من الحالة، لا عبر CSS.
4. **الخصوصية على مستوى القاعدة:** `0027` (مسودة محلية) يلغي أي سياسة `tenant_id` فقط على `aigas_sc_conversations` و`aigas_sc_messages`، ويضع سياسة مشارك واحد (`tenant_id + user_id` من GUC المعاملة)، ويفعّل `FORCE ROW LEVEL SECURITY` حتى لا يتجاوز مالك الجدول السياسة، ويسحب كل الصلاحيات على جدولي المتن من `aigas_runtime/authenticated/anonymous`، ويفشل الترحيل إذا بقيت سياسة غير مقيدة بالمؤلف أو صلاحية `SELECT`. واستُثني الجدولان أيضًا من منح ومولّد سياسة `0025`، فإعادة تشغيله لا تعيد وصولًا مؤسسيًا إلى المتن.
5. **لا مسار حفظ أو قراءة متن.** لا RAG/Files/Share/Export/Streaming، والرد يُعاد كاملًا بعد فحص الخروج. Audit يحمل `correlationId/policyVersion/idempotencyKey` فقط.

## 3. مراجعة `0016_aigas_sc_user_token_quota.sql` محليًا

- **ما تفعله:** دالة `SECURITY DEFINER` واحدة تُرجع عدادات دقيقة/24 ساعة ورسوم رموز للمستخدم والمؤسسة، `search_path=pg_catalog, public`، وتشترط تطابق GUC المؤسسة/المستخدم مع الوسيطين ووجود عضوية.
- **لماذا `v2`:** النسخة `v1` في `0009` تُرجع رسوم رموز واحدة للمؤسسة؛ `v2` تفصل حصة المستخدم عن المؤسسة. الكود يستدعي `v2` فقط ويفشل مغلقًا عند غيابها (`SECURE_CHAT_SCHEMA_MISSING`).
- **نقاط المراجعة قبل التطبيق:** مالك الدالة بعد التطبيق (يفضّل مالك قاعدة البيانات لا دور التشغيل)، صراحة `REVOKE ... FROM PUBLIC`، ومنح `EXECUTE` لدور التشغيل المسمى فقط (كما في `0019`)، والتحقق من أن `aigas.sc_*` لا تُضبط من أي مسار عميل.
- **قيود مقصودة:** تُحتسب الطلبات `FAILED/UNKNOWN/CANCELLED` بكامل `reserved_tokens` لمدة 24 ساعة (متحفظ). لا تُحتسب تكلفة مالية ولا سعر مزود. الحصة لكل مستخدم/مؤسسة فقط، لا منتج/مزود/قسم.
- **لا تطبيق على `production`.** لا `CREATE/GRANT` في هذه الدفعة.

## 4. سيناريو تحقق ببيانات اصطناعية (يتطلب موافقة موقّعة)

**الموافقات المطلوبة قبل التنفيذ (منفصلة عن هذه الدفعة):**
1. مالك المنتج: اعتماد إطلاق تجربة داخلية محدودة.
2. الأمن/الخصوصية: مراجعة سياسة المحتوى والحصص و`0027` وAudit.
3. مالك قاعدة البيانات: فرع staging قابل للاستعادة + تطبيق `0016` ثم `0027`.
4. مالك النموذج/المزود: اعتماد `model/provider/region/retention/no-training` وكتابة القيم في `models.mjs` مع `approval.reference` و`expiresAt`.

**البيانات:** حسابان اصطناعيان في مؤسستين، ونصوص مثل `"اختبار اصطناعي 1"` فقط. يُمنع أي بريد/هاتف/اسم/مستند عميل.

| # | الخطوة | النتيجة المتوقعة |
|---|---|---|
| S1 | قبل تهيئة الحصة: `GET /app/api/secure-chat/models` | `available:false`, `availabilityCode:USAGE_POLICY_NOT_CONFIGURED`, `models:[]` |
| S2 | إرسال بلا نموذج | `503 NO_APPROVED_MODEL`، ولا حجز في `aigas_sc_requests`، وAudit بلا متن |
| S3 | بعد اعتماد النموذج وقبل تطبيق `0016` | `USAGE_POLICY_NOT_READY`، وزر الإرسال معطّل |
| S4 | بعد `0016` + `0027` وسياسة حصة معتمدة | `available:true` ونموذج واحد فقط |
| S5 | إرسال نص اصطناعي | `requestId` واحد، حالة `SUCCEEDED`، `usage` من المزود، ولا صف في `aigas_sc_messages` |
| S6 | إعادة إرسال نفس `requestId` | `409 REQUEST_ALREADY_SEEN`، ولا استدعاء ثانٍ للمزود |
| S7 | إلغاء أثناء التنفيذ | `REQUEST_CANCELLED` وقد تبقى الحصة محجوزة؛ لا رد جزئي |
| S8 | تجاوز حد الطلبات | `429 USAGE_LIMIT_REACHED` + `Retry-After` |
| S9 | حساب المؤسسة الثانية | لا يرى نماذج/طلبات/سجلات المؤسسة الأولى |
| S10 | محاولة قراءة متن colleague | `SELECT` مرفوض أو صفر صفوف؛ لا مسار API |
| S11 | بحث في `aigas_audit_events` | لا يوجد متن/بريد/هاتف؛ فقط `action/correlation_id/policy_version/idempotency_key` |

**أدلة مطلوبة:** لقطات حالات الواجهة، استجابات HTTP معقمة، `EXPLAIN`/عدّادات الطلبات، نتيجة `has_table_privilege` بعد `0027`، وعينة Audit معقمة. لا تُدرج مفاتيح أو DSN.

**Rollback:** لا يوجد اعتماد إنتاجي؛ عند فشل staging يُعاد الفرع من نقطة الاستعادة، وتُعاد `0027` قبل أي إعادة تشغيل لـ`0025`.

## 5. ما بقي مفتوحًا

- `APPROVED_MODELS=[]` يبقى فارغًا: لا مزود/نموذج/منطقة/شروط عدم تدريب معتمدة، ولا مفاتيح موصل.
- `0016` و`0027` غير مطبقتين؛ لا `aigas_sc_usage_window_v2` ولا سياسة مشارك على الفرع المفحوص.
- لا `RUNTIME_VERIFIED`: لم يُشغّل build/HTTP/Neon write/E2E؛ التحقق يحتاج بيئة معتمدة وخطوة مخوّلة منفصلة.
- لا حفظ/استرجاع/مشاركة/تصدير/ملفات/RAG/streaming، ولا وصول إداري إلى المتن.
- أصحاب الموافقة: مالك المنتج + الأمن/الخصوصية + مالك قاعدة البيانات + مالك النموذج. لا إطلاق Beta قبل أدلة تشغيل وأمن فعلية.
