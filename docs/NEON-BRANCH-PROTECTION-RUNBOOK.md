# Runbook — حماية فرع Neon، النسخ الاحتياطي، الاستعادة والتراجع

> **الغرض:** خطة تشغيل معتمدة لفرع قاعدة البيانات قبل أي ترحيل أو تفعيل إنتاج.
> **الحالة:** `PLAN ONLY — NOT EXECUTED`. لم يُنشأ فرع، ولم يُغيَّر إعداد حماية، ولم تُطبَّق أي مهاجرة ضمن هذه المهمة.
> **تاريخ:** 2026-11-03 | **المرجع:** مشروع Neon `young-frog-60183055` (قراءة فقط)، وخطة `docs/DATA-ACCESS-AND-RLS.md`.

---

## 1. الحالة المرجعية عند الفحص (قراءة فقط)

| البند | ما رُصد | الأثر |
|---|---|---|
| عدد الفروع | فرع `production` وحيد | لا بيئة اختبار معزولة؛ أي مهاجرة تُجرَّب على نفس الفرع أو لا تُجرَّب |
| حماية الفرع | **غير مفعّلة** | الكتابة/الحذف المباشر ممكن تقنيًا لأي دور مصرح |
| الجداول | 31 جدول AIGAS، RLS على 31، سياسات على جدولين | العزل الفعلي من شروط `tenant_id` لا من RLS |
| بيانات العمل | صفر سجلات عمل، ولا مستخدمين/جلسات Auth | النسخ/الاستعادة الحالية بلا بيانات عمل، لكن ذلك **لا يستمر** بعد التفعيل |
| دور `DATABASE_URL` | `neondb_owner` بـ`rolbypassrls=true` | يحتاج تحويلًا إلى دور تشغيل مقيد (`0019`) بعد اعتماد |
| الشبكة والمنطقة | `region_id=aws-us-east-2`، `block_public_connections=false`، `allowed_ips=[]` | لا إثبات إقامة سعودية، وسطح اتصال عام مفتوح يحتاج تقييدًا من المشغّل |
| Data API | `active` على `public` بدور `anonymous` | وصول عميل مباشر يحتاج تعطيلًا أو سياسة معتمدة |
| حماية الفروع | `protected:false` | لا حماية لفرع `production` |
| مهاجرات محلية غير مطبقة | `0013`–`0023` (بحسب `docs/CURRENT-IMPLEMENTATION-REGISTER.md`) | تحتاج دورة اعتماد واختبار قبل الإنتاج |

> الأرقام أعلاه لقطة مؤرخة؛ يجب إعادة جردها قبل التنفيذ. لا تفترض بقاءها.

## 2. الأدوار والاعتماد (فصل واجبات)

| الدور | المسؤولية | لا يملك |
|---|---|---|
| مالك المنصة (Owner) | اعتماد إنشاء الفروع، نوافذ التنفيذ، والتراجع | تنفيذ تغييرات على بيانات العملاء بلا مراجعة |
| مشغّل قاعدة البيانات (Operator) | تنفيذ الخطوات المعتمدة وإرفاق الأدلة | اعتماد نفسه؛ ولا اعتماد مهاجرة كتبها هو وحده |
| مراجع أمني/خصوصية | مراجعة RLS/GRANT/Data API وسياسة الاحتفاظ | تنفيذ تغييرات إنتاج منفردًا |
| مطوّر | فتح طلب تغيير مع خطة تراجع وأثر | أي كتابة على `production` |

**قاعدة الاعتماد:** أي مهاجرة على `production` تحتاج: (1) مسودة ملف SQL في المستودع، (2) تجربة على فرع تطوير، (3) دليل نتيجة التجربة، (4) موافقة Owner + Operator مستقلين، (5) نافذة تنفيذ معلنة، (6) خطة تراجع/roll-forward. لا يوجد «تنفيذ سريع» يتجاوز ذلك.

---

## 3. الطوبولوجيا المستهدفة

```
production    ← محمي، بلا كتابة مباشرة، يخدم الخدمة فقط
  └─ staging  ← فرع تطوير طويل العمر (بيانات اصطناعية فقط)
       └─ pr-<id> / migration-<name>  ← فرع مؤقت لكل تغيير، يُحذف بعد الاعتماد
```

- بيانات `staging` تكون **اصطناعية**؛ لا تُنسخ بيانات عملاء حقيقية إلى فرع غير إنتاجي إلا بقرار استثنائي موثق.
- كل فرع مؤقت يُنشأ من `production` في لحظة معتمدة، ويُحذف بعد الدمج/الرفض.
- تحديد مدة صلاحية للفروع المؤقتة لمنع تراكم نسخ تحتوي بيانات.

## 4. إعدادات حماية الفرع المطلوبة (تُنفَّذ من لوحة Neon/المشغّل)

| الإعداد | القيمة المستهدفة | السبب |
|---|---|---|
| فرع `production` | `protected` | منع الحذف/إعادة التعيين العرضي |
| حسابات الكتابة | دور تشغيل واحد مخصص (`aigas_runtime`) بعد `0019` | عدم استخدام مالك الجداول في الخدمة |
| وصول التطبيق | `NOBYPASSRLS` + منح أدنى | جعل RLS طبقة ثانية لا بديلًا |
| Data API | تعطيل على `public` أو تقييده بدور وسياسة معتمدة | سطح وصول عميل مباشر |
| `neondb_owner` | إدارة فقط، لا تشغيل خدمة | يبقى تجاوز RLS محصورًا بالإدارة |
| الاتصالات العامة | `block_public_connections` معتمد + `allowed_ips` أو Private Link | المشروع الحالي يسمح باتصالات عامة بلا قائمة IP |
| منطقة المشروع | قرار مالك/قانوني (الحالي `aws-us-east-2`) | لا ادعاء إقامة بيانات سعودية قبل نقل/إثبات |
| نسخ الاتصال | توزيع عبر Secret Store فقط | لا DSN في المستودع/الوثائق |

> **لم يُنفَّذ أي من الإعدادات أعلاه.** تفعيل الحماية أو تغيير الأدوار إجراء مشغّل خارج نطاق الوكيل.

---

## 5. النسخ الاحتياطي قبل التغيير

1. سجّل نقطة بداية: اسم الفرع، LSN/وقت، مهاجرة الرأس الحالية.
2. أنشئ نسخة/نقطة استعادة معتمدة **قبل** أي مهاجرة (حسب آلية Neon المتاحة للخطة).
3. تحقق أن النسخة قابلة للاستعادة وليست «نسخة ناجحة» فقط: استعدها في فرع منفصل وافحص.
4. سجّل الأدلة في سجل تغيير (بلا DSN أو أسرار).

**لا يُعتبر نجاح Backup دليل استعادة.** الدليل هو استعادة فعلية في بيئة معتمدة.

## 6. اختبار الاستعادة

```text
# أوامر توضيحية — تحتاج اعتمادًا ومشروعًا/فرعًا محددين. لم تُنفَّذ.
neon branches create --project-id <PROJECT> --name restore-check-<date> --parent production
# ضع DATABASE_URL المؤقت لفرع الاستعادة في جلسة المشغّل فقط (لا في ملف متتبع)
psql "$RESTORE_URL" -c "select count(*) from public.aigas_tenants;"
psql "$RESTORE_URL" -c "select count(*) from public.aigas_audit_events;"
```

معايير قبول الاستعادة:

- عدد الجداول والمهاجرة الرأس يطابقان المتوقع.
- قراءة جداول المؤسسة تعمل بالدور المقصود، والكتابة ممنوعة حيث يجب.
- لا يظهر مستأجر آخر في أي استعلام.
- بعد التحقق: احذف فرع الاستعادة أو اتركه وفق سياسة احتفاظ معتمدة.

## 7. Rollback

| الحالة | الإجراء المعتمد |
|---|---|
| فشل قبل تطبيق المهاجرة | إلغاء النافذة؛ لا تغيير |
| فشل جزئي داخل معاملة | `ROLLBACK`؛ لا حالة وسيطة |
| مهاجرة مطبقة وسلوك غير صحيح | **Roll-forward** بمهاجرة تصحيحية؛ أو استعادة كاملة من نقطة معتمدة |
| استعادة كاملة | إعلان توقف كتابة، استعادة، تحقق، ثم إعادة الخدمة |
| تراجع كود فقط | نشر النسخة السابقة مع الحفاظ على المخطط المتوافق |

- لا تُشغّل «Down migration» على `production` دون ملف مراجَع واختبار على فرع.
- أي استعادة تُبطل نسخًا احتياطية لاحقة تعتمد على الفرع المستعاد؛ يجب توثيق ذلك.
- بعد الاستعادة، **دوّر** نسخ الاتصال وأي أسرار تأثرت (انظر `docs/DATA-PRIVACY-AND-SECURITY.md` §9).

## 8. دورة المهاجرة المعتمدة (لكل ملف `migrations/*.sql`)

1. مراجعة الملف: idempotent، داخل معاملة، بلا `DROP` غير مبرر، وبتعليقات اعتماد بشرية في الأعلى عند الحاجة.
2. تجربة على فرع تطوير، مع فحص قبل/بعد (عمود/قيد/فهرس/عدد صفوف).
3. مراجعة RLS/GRANT المصاحبة: هل المهاجرة توسّع سطح وصول؟
4. موافقة Owner + Operator، ونافذة تنفيذ.
5. تنفيذ على `production` بمعاملة واحدة، ثم فحص لاحق مسجل.
6. تحديث `docs/CURRENT-IMPLEMENTATION-REGISTER.md` بحالة المهاجرة الفعلية.

المهاجرات `0018`/`0019` (منح/دور التشغيل) و`0013`–`0017` و`0021`–`0023` ما زالت **غير مطبقة**؛ ترتيب تطبيقها جزء من خطة الإطلاق وليس من هذه المهمة.

---

## 9. ما لم يُنفَّذ (عوائق صريحة)

- لم يُنشأ فرع تطوير أو استعادة، ولم تُغيَّر حماية `production`.
- لم تُطبَّق أي مهاجرة، ولم يُحوَّل `DATABASE_URL` إلى `rls`‑مفعّل أو دور مقيد.
- لم تُقرأ بيانات عملاء (لا توجد)، ولم تُنشأ بيانات.
- لا يوجد دليل استعادة فعلي، ولا اختبار اختراق، ولا مراجعة مستقلة.
- تفعيل الحماية والأدوار وData API يحتاج مشغّلًا مصرحًا واعتماد مالك.
