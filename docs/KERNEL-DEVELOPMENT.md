## API and integration contract

- `GET /app/api/kernel/`: Bearer token required; returns only the authenticated user's memberships, selected tenant and five product states. Optional `?workspace=<uuid>` is a selection request checked against actual DB memberships on each request, never authority. No membership returns empty onboarding; non-member selection returns 403.
- `POST /app/api/kernel/`: same-origin JSON `{ "name": "..." }`, Bearer token required. Only users with zero Kernel memberships may create a new workspace. A transaction and user-specific advisory lock prevent duplicate onboarding. It creates the tenant, OWNER membership, five FOUNDATION access rows and minimal audit together. Existing members receive 409. No role or tenant ID input is accepted.
- `GET /app/api/kernel/members/`: Bearer token required; same `?workspace=` selection contract. Returns the members of the server-verified tenant only, ordered OWNER → ADMIN → MEMBER, with role label, join date and account status. Co-member email is returned to OWNER/ADMIN only; a MEMBER viewer receives `email: null`. Non-member selection is 403; no workspace is 403 `NO_WORKSPACE`. Read-only: no invitation endpoint, no role mutation and no self-escalation path exists. `invitation.available` is always `false` with a stated reason.
- `GET /app/api/kernel/health/`: anonymous liveness only. Returns `status` plus `checks.auth` / `checks.database` / `checks.schema` codes (`READY`, `AUTH_SETUP_REQUIRED`, `AUTH_UNAVAILABLE`, `DB_SETUP_REQUIRED`, `DB_UNAVAILABLE`, `SCHEMA_MISSING`, `NOT_CHECKED`). No host, version, row count, SQL error text or credential is returned, and it does not assert product, trial or compliance readiness.
- `GET /app/api/kernel/` also returns `summary { members, events }`, `activity` (latest eight tenant audit rows with display labels; no request bodies or emails) and `canManageMembers`. Every aggregate is filtered by the server-verified `tenant_id`; no browser-supplied tenant or role is trusted.
- Errors: 401 identity missing/invalid; 403 selection/origin denied; 400 input invalid; 409 existing membership; 503 Auth/DB configuration or availability failure. Errors contain no secrets. Responses use no-store; app HTML is noindex, and `/app/` routes are excluded from the generated sitemap.
- Reuse `authenticate`, `tenantGuard`, `requireRole` and `audit` in future server handlers. Keep operations scoped by server-verified identity and tenant. Audit is essential security metadata, **not** the Ledger product or a tamper-proof evidence system.

A product's card state comes only from `aigas_product_access`: `ENABLED` → «مفعّل للمؤسسة», `DISABLED` → «معطّل من المشغّل», `FOUNDATION` → «قيد التأسيس». The link to `/app/{product}/` appears only when the route is in the server allowlist **and** the state is not `DISABLED`; the page and its API still verify identity, membership and role on every request. The allowlist now contains the five product routes that have server-side guards (Firewall, Ledger, Human Gate, Risk Engine, Secure Chat); it is a code constant, never client input, and adding a route does not itself enable a product. No subscription or trial is activated by an access record, and the workspace never claims one is.

Order for subsequent implementation: Firewall → Ledger → Human Gate (wave 1), then Risk Engine → Secure Chat (wave 2). Paths: `/app/firewall/`, `/app/ledger/`, `/app/human-gate/`, `/app/risk-engine/`, `/app/secure-chat/`. These paths are reserved and are not linked until implemented.

## Published `/app/` 404 — local diagnosis (2026-11-01)

Live checks on 2026-11-01: `/`, `/products/`, `/kernel/` return 200 (Cloudflare, `cf-cache-status: HIT`), while `/app/`, `/app/kernel/`, `/app/api/kernel/` and the six product paths return 404 with `cf-cache-status: MISS` and no origin response. The current local build is healthy: `node --env-file=.env dist/server/entry.mjs` returns `302 /app/ → /app/kernel/`, `200` HTML for `/app/kernel/` and `401` JSON for `/app/api/kernel/`.

Root cause: 29 public pages set `prerender = true`, so Astro writes them to `dist/client/*/index.html`; every `/app/*` page and API route sets `prerender = false` and therefore exists only in the Node server artifact (`dist/server`). `dist/client` contains zero `/app/` HTML. The live host is serving the static `dist/client` output only, so prerendered pages resolve and every server-rendered route 404s. This is a hosting/domain mismatch, not a missing route or a routing bug in the app.

Safe local fix (owner action, not performed here): either point the domain at the Node service that runs `node ./dist/server/entry.mjs` (the committed `render.yaml` start command) and confirm a fresh deploy, or, if the site must stay on a static/edge host, approve an SSR-capable adapter migration (`@astrojs/cloudflare`) as a dependency and hosting change. Do not "fix" this by prerendering `/app/*`: those pages read the authenticated session and must stay server-rendered. Cloudflare must not cache `/app/*`; the app already sends `Cache-Control: private, no-store` and `X-Robots-Tag: noindex, nofollow`.

Also note the runtime contract for the host: the standalone server needs `DATABASE_URL`, `NEON_AUTH_BASE_URL` and `NEON_AUTH_JWKS_URL` in its environment. Missing variables surface as `DB_SETUP_REQUIRED` / `AUTH_SETUP_REQUIRED` through `/app/api/kernel/health/`, not as a 404.

- `POST /app/api/kernel/members/?workspace=<uuid>`: `operation: link` with `organizationId` (Kernel OWNER plus verified native Auth owner); or `operation: register` with `invitationId` (Kernel OWNER/ADMIN plus native inviter owner/admin). Registration validates organization, inviter, expiry and role against Auth tables. A partial native creation can be recovered from the Auth invitation list without creating another invitation.

After explicit native acceptance, `POST .../members/` with `{operation: 'accept',invitationId}` revalidates the accepted Auth invitation, mapped organization, current inviter's Kernel authority and native member row before inserting MEMBER and audit atomically. No self-promotion, ADMIN grant or ownership transfer endpoint exists.
