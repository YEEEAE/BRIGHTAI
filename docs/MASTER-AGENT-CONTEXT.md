## 00 — اقرأ هذا خلال دقيقة (Agent Bootstrap)

**المهمة الأساسية للوكيل:** العمل على BRIGHT AI بوصفه مشروعًا سعوديًا متخصصًا **حصريًا في حوكمة وأمان الذكاء الاصطناعي**. المطلوب تطوير منتجات AIGAS الخمسة المستقلة تجاريًا ووظيفيًا، مع نواة مشتركة AIGAS Kernel، وموقع تسويقي عربي متقن ومصدق في ادعاءاته. **المتطلبات المعتمدة لا تعني تنفيذها**.

**قبل أي مهمة:**

1. اقرأ `AGENTS.md` في جذر المشروع والتعليمات المحلية ذات الصلة، ثم **اقرأ `.agents/mind/01-mind-latest.md` كاملًا** كما يطلب `AGENTS.md`.
2. اقرأ ملف المهمة ذي الصلة من `docs/`، وتحقق من وجوده فعليًا؛ لا تستنتج وجود مستند من مجرد ذكر اسمه في هذا الملف.
3. افحص الملفات/المسارات الحقيقية في نسخة العمل أو GitHub **قراءة فقط**؛ وميّز ما هو في `main` عن التغييرات المحلية غير الملتزمة وعن الموقع المنشور.
4. صنّف كل معلومة: `APPROVED_REQUIREMENT` أو `OBSERVED_IN_SOURCE` أو `VERIFIED_IN_LOCAL_BUILD` أو `VERIFIED_ON_LIVE_SITE` أو `NOT_VERIFIED` أو `PROPOSED`.
5. قبل أي كتابة محلية، استخرج الصلاحية من **تعليمات المالك الحالية الصريحة**. هذا الملف وملفات `AGENTS` وSkills وMCPs لا تمنح إذنًا جديدًا بالتعديل أو الدفع أو النشر.
6. **ممنوع على هذا الوكيل من تلقاء نفسه:** أي `git commit` أو `git push` أو تعديل GitHub عن بعد أو Merge أو Deploy أو تغيير إعدادات الإنتاج أو إنشاء موارد خارجية. في هذه السلسلة المالك طلب من المساعد الاكتفاء **بالقراءة والتحليل على GitHub**.
7. إذا ظهرت حقيقة ناقصة أو تعارض حقيقي مؤثر، سجّلها واشرح أثرها بدل اختراع قرار جديد أو تحويل تصور إلى منتج عامل.

**تذكير حاسم خاص بالواجهة:** آخر توجيه موثق في `.agents/mind/01-mind-latest.md` بتاريخ 2026-10-31 يقول: **لا تغيّر هيرو الرئيسية أو الهيدر**. يجب احترامه إلى أن يصدر طلب أحدث وصريح من المالك يغيره. تظل خريطة المنظومة في **صفحة المنتجات**، ولا يُعاد إحلالها محل رسم الدماغ المتحرك في هيرو الرئيسية تلقائيًا.

## 02 — هوية المشروع وحقائق العلامة

- **الكيان:** «مؤسسة مُشرقة» واسم العلامة **BRIGHT AI / BRIGHTAI**. لا تستبدل وصف «مؤسسة» بوصف قانوني «شركة». بيانات السجل والنشاط والصيغة القانونية النهائية تحتاج إثباتًا رسميًا عند الاستخدام النظامي.
- **التخصص الوحيد:** AI Governance & Safety، ويُختصر **AIGAS**. ليس وكالة ذكاء اصطناعي عامة، ولا وكالة مواقع، ولا منتج دردشة عامًا فقط.
- **السوق المستهدف:** السعودية، الجهات الحكومية والقطاع الخاص بأولوية متساوية. المحتوى يراعي المتطلبات الفعلية للقطاع دون تعميم اللوائح.
- **اللغة العامة:** عربية سعودية طبيعية مفهومة؛ أسلوب مباشر وعملي لا مبالغات ولا ترجمة حرفية. الصفحات الحكومية والقانونية: عربية مهنية رسمية تناسب السياق.
- **الواجهات/المستندات الموجهة للعملاء:** عربية وRTL، مع استخدام مصطلحات إنجليزية دقيقة عند الضرورة. أسماء الـAPI والمعرفات والرموز البرمجية يمكن أن تبقى بالإنجليزية.
- **الموقع:** `https://brightai.live/`. الشعار المعتمد الوحيد **الصورة ذات الدرع الأزرق**، والمصدر التقني الموحّد `src/data/brand.ts` و`src/components/BrandLogo.astro`.
- **الوعد المسؤول:** تحكم واضح، مخاطر يمكن تقييمها، موافقة بشرية عند الحاجة، وأدلة قابلة للتحقق؛ دون شهادات أو قدرات أو ضمانات مخترعة.

### صياغات محظورة دون أدلة

- «معتمد من سدايا / الهيئة الوطنية للأمن السيبراني / حاصل على ISO 42001».
- «يضمن الامتثال» أو «يمنع 100% من Prompt Injection» أو «آمن بالكامل».
- «خدمة تعمل في الإنتاج» بناءً على مخطط أو صفحة تسويقية أو Mock.
- «عملاء حكوميون حاليون» أو «براءة اختراع» أو «شراكات» بلا إثبات يخص BRIGHT AI.
- أسعار أو عروض أو نسب دقة أو SLA أو عدد مستخدمين أو زمن استجابة أو منطقة معالجة محددة من دون اعتماد أو قياس.

## 03 — المنظومة التجارية والمنتجات الرسمية

```text
مؤسسة مُشرقة / BRIGHT AI
└─ AIGAS — AI Governance & Safety
   ├─ AIGAS Kernel          [مكوّن أساسي مشترك؛ لا يُباع منفصلًا]
   ├─ AIGAS Firewall        [منتج مستقل: FW-*]
   ├─ AIGAS Risk Engine     [منتج مستقل: RE-*]
   ├─ AIGAS Human Gate      [منتج مستقل: HG-*]
   ├─ AIGAS Ledger          [منتج مستقل: LD-*]
   └─ AIGAS Secure Chat     [منتج مستقل: SC-*]
```

| المنتج | مسؤولية محددة | لا تخلطه مع | الموجة المستهدفة |
|---|---|---|---|
| **AIGAS Firewall** | تطبيق سياسات حقيقية على حركة AI **المتكاملة معه فقط**؛ Allow/Warn/Redact/Approval/Block، DLP، دفاع طبقي ضد Prompt Injection | الادعاء بأنه يراقب أي ChatGPT أو AI في المؤسسة دون تكامل | الأولى / P0 |
| **AIGAS Ledger** | إنشاء وتخزين أدلة تشغيلية قابلة للتحقق من السلامة والتوقيع والتصدير مع عزل واحتفاظ وضوابط صلاحيات | سجل نشاط UI بسيط أو تخزين كل نصوص المستخدمين افتراضيًا | الأولى / P0 |
| **AIGAS Human Gate** | موافقات بشرية مع صلاحيات وفصل واجبات وتصعيد وإغلاق آمن ونتائج قابلة للتدقيق | زر شكلي «موافقة» غير متصل بقرار تنفيذ فعلي | الأولى / P0 |
| **AIGAS Risk Engine** | سجل استخدامات وأصول AI، تقييم مخاطر قابل للتفسير، دورة حياة وضوابط ومراقبة | الاعتماد على درجة مخاطر بلا تفسير أو معيار معتمد | اللاحقة / P1 |
| **AIGAS Secure Chat** | محادثة مؤسسية أساسية محكومة باختيار النماذج والسياسات والخصوصية | RAG، قاعدة معرفة مؤسسية، رفع ملفات عام إلزامي أو مشاركة عامة افتراضية | اللاحقة / P1 |

**قواعد لا تفاوض عليها:**

1. المنتجات الخمسة **قابلة للاشتراك/الترخيص مستقلًا** أو في باقات اختيارية. لا يلزم شراء منتج آخر ليعمل المنتج المحدد ضمن وظيفته المعتمدة. Kernel مشمول بالقدر الضروري ولا يُفوتر بشكل مستقل.
2. كل ميزة تتبع مصدرًا واضحًا: `Product → Capability ID (FW/LD/HG/RE/SC) → Requirement → Code → Evidence → Release status`. التفاصيل الدقيقة في `PRODUCT-MASTER-CATALOG.yaml`.
3. المنتجات قد تتكامل اختياريًا؛ مثل Firewall يحيل حالة لـHuman Gate ويسجل الحدث في Ledger، **لكن التكامل ليس شرط شراء إجباريًا**.
4. لا يُعرض أي منتج للجمهور على أنه `AVAILABLE` أو `BETA` حتى توجد أدلة تشغيل وأمان وموافقة نشر مناسبة. **الوضع المثبت في المستندات حتى الآن: التشغيل غير متحقق**.
5. MVP الأول: **Kernel + Firewall + Ledger + Human Gate** كمنتجات أساسية مستقلة، ثم Risk Engine وSecure Chat وفق الأولويات والجاهزية.

### MVP Evidence Gates

- **Firewall:** طلب حقيقي يمر عبر نقطة تكامل؛ تنفذ السياسة القرار بالفعل مع دليل لمسار السماح والحجب والتصعيد، مع عدم تجاوز Hard Deny.
- **Ledger:** حدث فعلي يولّد دليلًا ذا سلامة قابلة للتحقق ويمكن تصديره والتحقق منه مستقلًا.
- **Human Gate:** طلب اعتماد حقيقي لصاحب صلاحية، والقرار يغيّر التنفيذ الفعلي مع فصل الواجبات وتوثيق الاستجابة.
- **Kernel:** عزل وصلاحيات وسياسات وواجهات وتراخيص وحماية مفاتيح بحسب النطاق الضروري؛ وليس مجرد رسم معماري أو API Stub.
- **Global:** لا قبول مع ضعف جوهري في الخصوصية والأمن ووضوح البيانات، أو تجربة تشبه التشغيل دون تشغيل.

## 04 — العمارة والتكاملات وخيارات النشر

**نمط معماري مقصود:** AIGAS Kernel يقدم الحدود المشتركة للهوية والسياسات والأحداث والترخيص والتهيئة؛ المنتجات وحدات مستقلة من منظور العميل والعقد وMVP. يُفضّل الفصل المنطقي وحدود الخدمات الواضحة مع عدم فرض Microservices ثقيلة مبكرًا بلا حاجة مثبتة.

**التكاملات:** REST/OpenAPI وSDKs باللغات المناسبة، موصلات ومنافذ API/Proxy، وإمكانات MCP/Agent Tool Governance بحسب مراحل المنتج. **لا تدّعِ التكامل خارج ما ثبت وربط العميل به**. أدوات AI Agents تنفذ فقط عبر أذونات موثوقة؛ المخرجات اللغوية ليست سلطة مستقلة.

**أنماط النشر المعتمدة كمتطلبات:**

| النمط | شروط رئيسية |
|---|---|
| SaaS | عزل المستأجرين في البيانات والملفات والمفاتيح والنسخ والصفوف والـCache والسجلات؛ إقليميًا وتعاقديًا حسب المتطلب المعتمد |
| On-Premise | تشغيل داخل بيئة العميل؛ وصول دعم محدود بموافقة وصلاحيات مؤقتة موثقة؛ تحديثات موقعة ومجدولة |
| Air-Gapped | **صفر اعتماد إلزامي على الإنترنت**، وهوية/تراخيص/مفاتيح/نماذج AI محلية وإدارة وتحديثات موقعة دون باب خلفي؛ لا تدّعِ إمكانية تشغيل نموذج محلي دون تحقق الموارد |

**Infrastructure Sizing — القرار 107:** مواصفات أساسية لكل منتج، ثم تقييم حسب المستخدمين ومعدلات الطلب والتكاملات والاحتفاظ بالأدلة والنسخ الاحتياطي وRPO/RTO والتوفر العالي وشبكة العميل وGPU للنماذج المحلية؛ تحقق قبل التفعيل وربط المتطلبات بالعقد، **من دون ضمان أداء بلا قياس**.

**Migration — القرار 108:** قوالب واستيراد وتكاملات معتمدة لأصول AI والسياسات والمستخدمين ومسارات الاعتماد، فحص جودة/مطابقة صلاحيات، Dry Run، مراجعة فروقات، موافقة العميل، خطة تراجع، سجلات مصادر؛ **لا تفعّل سياسات حظر أو موافقات مؤثرة تلقائيًا قبل الاعتماد**. دعم مسار استيراد محلي للبيئات المعزولة، وعدم نقل بيانات غير لازمة.

## 05 — نموذج الأمن والخصوصية وحوكمة AI

### الخصوصية والبيانات

- **No Training:** لا تُستخدم محادثات العملاء أو مستنداتهم أو بياناتهم الوصفية أو أدلتهم لتدريب النماذج؛ التزام العميل والموردين والتعاقدات، **بلا استثناءات تسويقية مبهمة**.
- **Data Minimization:** تسجيل الحد الأدنى؛ Ledger يسجل Metadata أولًا، وأي حفظ لمحتوى حساس يخضع لموافقة وضوابط صريحة واحتفاظ مشروع.
- **Saudi-first Data Residency:** أولوية الإقامة والمعالجة المعتمدة بالمملكة، وأي نقل/معالجة خارجية يخضع للتحقق النظامي والتعاقدي والموافقة المطلوبة؛ لا يُختار مزود أو منطقة من عند الوكيل.
- عزل البيانات وتشفيرها أثناء النقل والتخزين، ومفاتيح BYOK / managed حسب الاتفاق؛ تدوير المفاتيح دون كسر التحقق من الأدلة السابقة.
- حق التصدير والخروج والحذف الآمن مع مراعاة Legal Hold؛ لا حذف لأدلة ملزمة بسبب رغبة تسويقية أو تغيير خطة.

### السياسات والصلاحيات

- RBAC + ABAC + Separation of Duties؛ SSO/Entra محليًا/سحابيًا حسب البيئة وMFA، إدارة هوية منفصلة للبيئات المعزولة.
- تسلسل السياسات من المنشأة إلى القسم والمنتج والمستخدم، مع نسخ معتمدة واستثناءات موثقة ومقيدة؛ **Hard Deny لا يُتجاوز بتقييم AI أو بسياسة أدنى**.
- Human Gate ينفذ مراجعة بحسب الخطر والجهة المخولة؛ Timeout يطبق قرارًا افتراضيًا آمنًا حسب السياسة.
- Ledger يثبت التسلسل/السلامة ويتيح التحقق؛ لا يجوز وعد «عدم قابلية التغيير مطلقًا» دون نموذج تهديد وإثبات تقني مناسب.
- الوصول الداعم من فريق BRIGHT AI: موافقة عميل، MFA، أقل صلاحية، مدة محددة، قابل للإلغاء ومدقق. لا دعم سري ولا Remote Backdoor خصوصًا Air-Gapped.
- API Gateway/WAF/DDoS وحدود طلبات/مستأجرين ومكافحة إساءة الاستخدام، واختبار سلوك التدهور دون خرق السياسة.

### الأطر التنظيمية

## 08 — قواعد التسويق وSEO وAEO وGEO وAI Search

**هدف الموقع:** جلب طلب سعودي ذي صلة وبناء معرفة موثوقة عن حوكمة وأمان AI، لا إنتاج صفحات حشو أو وعود تجارية قبل الجاهزية.

- فئة البحث الأولى السعودية، بنوايا `informational / problem-aware / solution / commercial / transactional / comparison`.
- المحتوى المكتوب بلغة سعودية واضحة، مع صياغة مؤسسية مناسبة للصفحات الرسمية؛ للبحث التقني استخدم المصطلح العربي والإنجليزي عند الحاجة.
- كل صفحة لها Search Intent مستقل، H1 محدد، Title/Description وCanonical، وروابط داخلية سياقية؛ لا تنشئ عشرات الصفحات لنفس الكلمة.
- المحتوى القابل للفهرسة يظهر في HTML حتى لو فشلت JavaScript، والرسومات تُشرح نصيًا، وStructured Data تعكس الواقع فقط.
- AEO وGEO ليست أدوات سحرية؛ ادعمها بإجابات صريحة، أصالة المحتوى، تعريفات، مصادر، مصطلحات متسقة، وخبرة قابلة للإسناد؛ **لا ضمان للظهور في AI Overviews أو ChatGPT**.
- لا تُخترع Search Volume أو KD أو زيارات أو Conversion Rates. بيانات الطرف الثالث تقديرات ويُحدد تاريخها ومصدرها، وغياب GSC لا يعني غياب اهتمام المستخدمين.
- عدم استخدام صور/نصوص أو ديموهات مأخوذة من جهات أخرى دون حق استعمال واضح.

### قرار التحليلات الأحدث — يحسم التعارض القديم

**كلاهما معتمد للموقع العام:**

1. **Google Search Console (GSC)**: الفهرسة، كلمات البحث، مرات الظهور، النقرات، الأداء العضوي.
2. **Google Analytics 4 (GA4)**: زيارات الموقع العام والتفاعل والأحداث المصرح بها فقط.

وسم GA4 المرصود في المصدر: **`G-9LMB4PGTWJ`**، داخل `src/layouts/BaseLayout.astro`. **وجود الوسم لا يثبت جمع بيانات فعلية أو اتصال حساب Analytics أو صحة Consent Mode**؛ يجب فحص ذلك من الأدوات/الحسابات المتاحة ومن متطلبات الخصوصية عند الحاجة. **لا تجمع المحتوى الحساس من منتجات AIGAS في Analytics**، ولا تُضف Pixels أو أدوات تتبع أخرى دون موافقة.

> أي عبارة قديمة في تقرير أو برومبت تقول «Search Console فقط / لا GA4» أصبحت **منسوخة** بقرار المالك الأحدث. لا تحذف الوسم تلقائيًا بسبب تلك العبارة القديمة.

```text
  → VERIFY ACTUAL RESULTS + NOTE LIMITATIONS
  → REPORT WHAT WAS DONE / NOT DONE / STILL BLOCKED
```

1. اكتب لنفسك Brief من سطرين: المطلوب، والشيء غير المصرّح به.
2. وثّق تاريخ/فرع/Commit أو SHA المرجع إن كان ذلك مؤثرًا؛ لا تقارن بيانات من أزمنة مختلفة كأنها نسخة واحدة.
3. افحص حالة العمل المحلي والتغييرات غير الملتزمة قبل أي تحرير **إذا كان التحرير مفوضًا**؛ لا تمس التغييرات الموجودة للمالك.
4. صنّف الفجوات: `P0` خطر/توقف جوهري، `P1` مطلوب للإطلاق أو وظيفة أساسية، `P2` تحسن غير حاسم؛ لا تفرض التصنيف إذا لم توجد أدلة.
5. عند بناء تصميم أو محتوى، انتبه إلى أن الملف الذي يصف الميزة لا يعني وجود كودها أو تكاملها.
6. لا تنشر أي شيء أو تعدل موقعًا أو مستودعًا أو Figma خارج نسخة العمل المصرح بها.
7. تحقق بما يكفي لتبرير العبارات النهائية؛ `Build PASS` وحده لا يثبت الأداء والأمان والإتاحة الإنتاجية.

## 13 — معيار الأدلة والتسمية المحايدة

| الحالة | الاستعمال الصحيح | مثال |
|---|---|---|
| `APPROVED_REQUIREMENT` | تم اعتماده كهدف/شرط | تشغيل Air-Gapped دون اعتماد إلزامي على السحابة |
| `OBSERVED_IN_SOURCE` | ظهر في ملف مصدر محدد | وسم GA4 في BaseLayout |
| `VERIFIED_IN_LOCAL_BUILD` | نجح اختبار محدد على نسخة معينة | `npm run build` بتاريخ ونسخة محددين |
| `VERIFIED_ON_LIVE_SITE` | ظهر في تجربة حية محددة | ظهور هيرو الجسيمات على `brightai.live` في مراجعة سابقة |
| `NOT_VERIFIED` | لا توجد أدلة كافية | توفر Firewall تجاريًا أو انتهاء اعتماد سياسة خصوصية |
| `PROPOSED` | تحسين مقترح لم يقرّه المالك | تصميم جديد لهيدر الجوال أو صفحة جديدة |
| `BLOCKED` | متعذر لأسباب محددة | غياب صلاحية أو إثبات متطلب للبيانات |

**ممنوع تحويل `OBSERVED_IN_SOURCE` إلى `VERIFIED_ON_LIVE_SITE`، أو `APPROVED_REQUIREMENT` إلى `IMPLEMENTED` تلقائيًا.**

لأي ميزة أو صفحة أو مؤشر، اربط بشكل موجز: `requirement_source`, `source_path`, `evidence_type`, `verification_date`, `current_state`, `known_limitations`, `next_action`.
