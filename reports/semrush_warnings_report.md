- حدد هل الحجب مقصود أم عرضي (side effect من قاعدة عامة)

### الخطوة 2: تعديل robots.txt
اكتب ملف robots.txt محدّث يتضمن:

```
User-agent: *
# السماح بالموارد الضرورية للعرض
Allow: /frontend/js/runtime-config.js
Allow: /frontend/js/api-gateway.js
Allow: /frontend/js/ai-scolecs-app.js
Allow: /assets/css/text-ratio-fix.css
Allow: /frontend/css/ai-scolecs-inline.css
Allow: /frontend/js/*.js
Allow: /frontend/css/*.css
Allow: /assets/css/*.css

# حجب الملفات الحساسة فقط
Disallow: /frontend/js/runtime-config.js  # أزل هذا إذا موجود
# [باقي قواعد الحجب المقصودة]

Sitemap: https://brightai.site/sitemap.xml
```

### الخطوة 3: تقييم الأمان
لكل مورد من الخمسة المحجوبة:
- هل يحتوي على بيانات حساسة (API keys, secrets)؟
- إذا نعم: أزل البيانات الحساسة من الملف واستخدم environment variables بدلاً
- إذا لا: اسمح بالزحف مباشرة

### الخطوة 4: التحقق
- اختبر ملف robots.txt المعدّل مع Google's robots.txt Tester
- تأكد أن Googlebot يستطيع الوصول لجميع الموارد الخمسة
- تأكد أن الملفات الحساسة فعلاً (env configs، admin routes) تبقى محجوبة

### الخطوة 5: ملف runtime-config.js
ملف runtime-config.js غالباً يحتوي على إعدادات runtime قد تشمل API keys. المطلوب:
- راجع محتوى هذا الملف
- إذا يحتوي على أسرار → أنشئ نسخة عامة (public config) بدون الأسرار وقدمها لـ Googlebot
- إذا لا يحتوي على أسرار → اسمح بالزحف مباشرة

## القيود
- لا تفتح ملفات حساسة فعلاً لمحركات البحث
- حافظ على أمان الموقع
- تأكد من أن التغيير لا يكسر أي وظائف حالية
- اشرح كل تغيير والسبب وراءه

أخرج:
1. ملف robots.txt المعدّل كاملاً
2. قائمة بالتغييرات وسبب كل تغيير
3. أي تعديلات مطلوبة على الملفات نفسها (إن وجدت)
