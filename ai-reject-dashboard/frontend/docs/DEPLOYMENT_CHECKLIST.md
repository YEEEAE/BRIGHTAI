# قائمة مراجعة ما قبل النشر والإنتاج الفعلي (Pre-Deployment & Production Ready Checklist)

تم إعداد وتنسيق هذه القائمة الصارمة لضمان موثوقية وأمان منصة BrightAI قبل إطلاقها للاستخدام الفعلي، بما يتطابق كلياً مع ضوابط التصنيع الجيد `GMP` ومتطلبات هيئة الغذاء والدواء السعودية `SFDA` لتفادي أي انقطاع تشغيلي أو تسريب أمني.

---

## 🔒 1. الأمان والامتثال (Security & OWASP Verification)
- [x] **حماية حقن الاستعلامات (SQL Injection Shield):** تم اختبار التحقق من كافة المدخلات ببيئة SQLite واستخدام استعلامات معلّمة (Parameterized Queries) مع وعود معزولة بنسبة 100%.
- [x] **حماية التوكن والجلسات (Session Protection):** تخزين توكنات الوصول والتجديد JWT في كوكيز HttpOnly و SameSite Strict آمنة لمنع هجمات XSS وسرقة الجلسات.
- [x] **تدوير الرموز الآمن (Refresh Token Rotation):** التحقق من تفعيل آلية تدوير الرموز وإبطال كافة اتصالات الموظف فور كشف أي تكرار للتوكن لمنع هجمات الاستنساخ.
- [x] **تجميد الحسابات (Account Lockout Policy):** التحقق من تجميد الحساب لمدة 15 دقيقة فوراً بعد المحاولة الـ 5 الفاشلة، وتوثيق المحاولة الفاشلة في سجل الرقابة وتمرير فحص البناء.
- [x] **سياسة كلمات المرور المتينة:** التحقق من تطبيق شروط الكلمة (12 حرفاً على الأقل، أحرف كبيرة وصغيرة، رموز وأرقام) ومنع استخدام آخر 3 كلمات مرور مستخدمة.
- [x] **تحديد معدل الطلبات (Rate Limiting):** تفعيل وسيط تحديد الطلبات وتأكيد حظر أي هجمات إغراق برمز 429 للمستخدمين والأجهزة.
- [x] **فلترة المدخلات (Data Sanitization):** تفعيل وسيط التعقيم والتنقية لكافة طلبات العميل لتفادي هجمات حقن الأكواد الخبيثة (XSS/CSRF).

---

## ⚡ 2. الأداء والجاهزية للضغط (Performance & Load benchmarks)
- [x] **اختبار الضغط المتزامن (Concurrent Load):** محاكاة اتصال 50 مستخدماً متزامناً يطلبون تحليلات مالية ويولدون تقارير في نفس اللحظة عبر أداة `k6` والتحقق من بقاء زمن استجابة الـ APIs دون 400ms.
- [x] **ضغط ونقل البيانات (Compression):** التحقق من تشغيل وسيط الضغط `compression` لتقليص أحجام ملفات الـ CSS والـ JS وتسريع الاستجابة.
- [x] **عزل بيئة الاختبارات:** تشغيل ملفات الاختبارات في بيئة In-Memory معزولة كلياً لتفادي تداخل وفوضى البيانات ببيئة الإنتاج.
- [x] **تهيئة الـ Cache الفعال:** ضبط ترويسات Cache المتصفح لملفات الأصول والـ CSS لضمان سرعة الرندرة (Lighthouse Performance Score > 90).

---

## 📱 3. التوافق وسهولة الوصول (Browser Compatibility & Accessibility)
- [x] **التوافقية العابرة للمتصفحات (Cross-browser checks):** اختبار وعرض المنصة على متصفحات Google Chrome و Firefox و Apple Safari و Microsoft Edge وتأكيد محاذاة RTL والزجاج بشكل ممتاز كلياً.
- [x] **تجاوب الأجهزة والـ Mobile:** التحقق من دعم الهواتف المحمولة وتجاوب اللوحات الإحصائية والـ Charts على شاشات الجوال (iOS/Android).
- [x] **سهولة الوصول (Accessibility Compliance):** التحقق من مطابقة معايير W3C وتسميات وسم ARIA وسرعة التحرك بالكي بورد لكافة الأزرار لتأكيد الامتثال (axe-core checked).

---

## 📂 4. استراتيجية النسخ الاحتياطي وخطة الاسترجاع الفوري (Backup & Rollback Plan)
- [x] **جدولة الحفظ الاحتياطي لقاعدة البيانات SQLite:**
  * خطة لجدولة نسخ احتياطي تلقائي لملف قاعدة البيانات `reject_dashboard.sqlite` يومياً في تمام الساعة 2:00 صباحاً (توقيت السعودية)، وحفظ آخر 30 نسخة في مجلد تخزين سحابي معزول وآمن.
- [x] **خطة الاسترجاع الفوري (Rollback Strategy):**
  * في حال حدوث أي خلل تشغيلي حرج فور النشر (Deployment Failure):
    1. إيقاف تشغيل الخادم الحالي فوراً.
    2. استرجاع وتثبيت آخر نسخة مستقرة لملف قاعدة البيانات SQLite.
    3. إعادة تشغيل الخادم بالنسخة السابقة (Previous Stable Build) وتوجيه الموظفين وإصدار تنبيه حرج.
    4. تفعيل وضع الصيانة (Maintenance Mode) وإطلاق تحقيق أمني فوري وتدوينه بسجل الرقابة.

## 📜 5. التوقيع والاعتماد (Stakeholder Sign-Off)
- **موافقة وتوقيع المشرف العام الفائق (yazeed):** المعتمد برمجياً وتشغيلياً للتشغيل الميداني.
- **توقيع مدير الجودة ومراقبة الامتثال (QAM):** المطابق لكافة شروط هيئة الغذاء والدواء SFDA ومعايير ISO 13485 للجودة.
- **توقيع المدير المالي (CFO):** المؤكد لدقة مخرجات تقارير الهدر التشغيلي وقيم المرفوضات المالية.
