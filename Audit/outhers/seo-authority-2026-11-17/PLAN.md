# خطة التنفيذ للاعتماد

الحالة PROPOSED. لم تُنفّذ تعديلات SEO أو محتوى في هذه المهمة.

## ترتيب العمل

1. **تثبيت المصدر:** اعتماد SHA ثابت، وتصحيح توازن وسوم PDPL فقط. تشغيل build ثم routes. نجاح نسخة البداية لا يعتمد النسخة الحالية.
2. **حسم الإرث:** مراجعة legacy-migration.csv، بما فيه الإنجليزية والمؤلفون. القرار لكل رابط: إبقاء مع استعادة مصدر موثوق، دمج301 إلى أقرب محتوى،أو404/410 مبرر. لا تحويل شامل إلى الرئيسية.
3. **توحيد الزحف:** بروفة جدول التحويلات على GET/HEAD/query،ثم تطبيقه في أصل أو حافة مخوّلة. حسم sitemap القديم قبل تحديث إرساله.
4. **التحويل:** CTA واضح للمختبر الاصطناعي العام؛ والاستفسار عن التشغيل حتى إثبات الرحلة المصادقة. فتحmailto ليس إرسالًا أو استلامًا.
5. **التحرير:** مراجعة32 دليلًا بقاعدة: جواب40–70 كلمة،تعريف،ثابت ومشروط،خطوات،حدود،مصادر وأسئلة حقيقية. البداية بالحوكمة وPDPL والمخاطر والسياسة،ثم دفعات4–8 مقالات.
6. **Schema والتواريخ:** مصدر واحد للتواريخ الحقيقية. الحفاظ على Organization/WebSite/Article/Breadcrumb؛FAQ مرئي فقط. لا Offer أوRating أوCertification مختلق.
7. **الأداء والوصول:** trace للعناصر المسببة للمشكلات في browser-lab.json،ثم أصغر إصلاح ممكن وثلاث مقارنات متطابقة. لا تغييرHero أوهوية بلا سبب مقيس.
8. **السلطة:** قوالب فعلية ومراجع قابلة للاستشهاد،ثم بحث أصلي بمنهج وعينة وحدود وموافقة جمع بيانات. لا تواصل خارجي أو شراء روابط ضمن التنفيذ المحلي.

الملفات والسبب فيfile-plan.csv،والمخاطر وقبول كل تعديل فيissues.csv. SQL وAPI ومنطق الصلاحيات والتجارب خارج النطاق. لا تعديل.env أوworkflows أوrender.yaml. تغييرات الحافة والنشر وإرسالSearchConsole والمراسلات تحتاج تفويض العملية نفسها.

## معايير الإغلاق

- build وroutes على SHA النهائي دون تجاوز اختبارات أو إخفاء فشل.
- canonical/title/description/H1/Schema مطابق للصفحات النهائية.
- sitemap واحد متسق،وكل URL فيه عام وقابل للفهرسة و200.
- لا رابط داخلي ميت أوسلسلة تحويل أووجهةCTA404 في النطاق المعتمد.
- لا ادعاء تشغيل أوشهادة أوعميل أوتقييم أوتكامل غير مثبت.
- تقرير بعد التنفيذ يحدد الملفات والأسباب والاختبارات وما لم يثبت.
