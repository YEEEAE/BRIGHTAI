# البيانات المنظمة وتجربة التحويل والسلطة

## Schema map المقترح

| العائلة | الموجود في بناء البداية | القرار |
|---|---|---|
| الموقع | Organization وWebSite | الحفاظ على #organization و#website وربط publisher بهما |
| الصفحات الداخلية | BreadcrumbList | المسار الظاهر يطابق canonical النهائي |
| مركز المعرفة | CollectionPage | ربط الأدلة الفعلية؛ لا SearchAction لواجهة غير موجودة |
| 32 دليلًا | Article | توحيد @id وmainEntityOfPage والمؤلف المؤسسي والتاريخ الحقيقي |
| 28 صفحة FAQ | FAQPage | فقط الأسئلة والأجوبة المرئية؛ لا وعد بنتيجة بحث منسقة |
| 5 تصورات منتجات | Product بلا Offer أوReview | مراجعة WebPage/about عند التحرير؛ لا حقول بيع أو تقييم مختلقة |
| التواصل | كيانات الموقع وBreadcrumb | ContactPage فرصة وصفية؛ لا ادعاء إرسال ناجح |
| الثقة والتعريف | كيانات الموقع | لا LocalBusiness بعنوان أو مواعيد أو شهادات غير مثبتة |
| demo/private/API | المحاكاة noindex؛ API ليس مقالًا | الحفاظ على الفصل والاستبعاد من sitemap |

كل الكتل في schema-map-current.json. تحليل JSON ونجاح العقود لا يثبتان أهلية Rich Results أو صحة الادعاء التجاري. كتل @graph في الصفحات القديمة تحتاج مراجعة مستقلة قبل استعادتها. Google يقصر FAQ rich results على المواقع الحكومية والصحية المعروفة ذات السلطة؛ وجود FAQ تجاري مرئي ليس مخالفة بحد ذاته. [المصدر](https://developers.google.com/search/blog/2023/08/howto-faq-changes?hl=en).

## UX conversion plan

| الصفحة | حاجة الزائر | CTA أساسي | CTA ثانوي | دليل القبول |
|---|---|---|---|---|
| الرئيسية | فهم النطاق والحدود | استكشف المختبر العام | دليل الحوكمة | القيمة واضحة أول الشاشة؛ لا رابط404 |
| الدليل المعلوماتي | فهم المفهوم | قائمة المراجعة المناسبة | دليل داعم | الإجابة لا تختبئ خلف نموذج تسويق |
| الدليل الإجرائي | إعداد سجل أو سياسة | تحميل قالب حقيقي بعد مراجعته | متى يلزم مختص؟ | ملف قابل للفتح بإصدار وحدود واضحة |
| المنتج | تمييز المحاكاة عن التشغيل | المحاكاة الاصطناعية | اسأل عن النطاق | لا سعر أو حماية أو تشغيل غير مثبت |
| القطاع | فهم سياق الجهة | ناقش حالة استخدام | الدليل القطاعي | لا نسخ صفحات مدن ولا امتثال شامل |
| مركز المعرفة | إيجاد الدليل | اقرأ الدليل | معاينة أو موضوع مرتبط | بحث وحالة فارغة وروابط HTML |
| التواصل | اختيار قناة ومعرفة النتيجة | قناة واحدة تعتمدها الجهة | بريد بديل | فتح mailto ليس استلامًا |

الأدلة الـ32 تملك فهرسًا؛ لا حاجة لبناء TOC جديد. بعض المقالات الكبيرة تضيف فهارس داخلية أيضًا؛ توحيدها فرصة لتقليل التكرار بعد مراجعة بصرية. البحث المحلي يملك label وحالة لا نتائج، واختبارات البحث والتنقل الست نجحت. التواصل الحي بعرض390 لم يظهر تجاوزًا أفقيًا؛ لم يُرسل نموذج أو رسالة.

الإسناد المؤسسي الحالي يُحفظ. المطلوب مسؤولية مراجعة فعلية ونطاق وتاريخ، لا شخص أو مؤهل مختلق. قارئ الشاشة الفعلي، الرحلات المصادقة، إتمام الإرسال، وجود CRM، وتعريف الاستفسار المؤهل: NOT VERIFIED. نجاح axe لا يغطيها.

## Backlink authority plan

1. **الأيام1–30:** قالب سياسة موظفين وسجل AI وقائمة تقييم مورد، بإصدار وإسناد وترخيص وحدود. البداية من الصفحات القائمة؛ لا شبكة صفحات تنزيل رقيقة.
2. **الأيام31–60:** بروتوكول بحث عن جاهزية الحوكمة في السعودية؛ تحديد المجتمع والعينة والأسئلة والتحيز وموافقة جمع البيانات قبل التنفيذ.
3. **الأيام61–90:** نتائج مجمعة قابلة لإعادة الحساب، ومنهجية وقاموس بيانات، ثم اقتراح مساهمة علمية أو ورشة مناسبة.
4. **أداة تفاعلية:** حصر فجوات بمنهج ومدخلات وحدود واضحة؛ لا درجة امتثال أو اعتماد تنظيمي.
5. **Digital PR:** زاوية خبرية من نتيجة أصلية مع حدودها؛ لا شراء روابط أو وعد dofollow أو ترتيب.

backlink-prospects.csv قائمة اكتشاف أولية بأسباب الملاءمة والمساهمة وطريقة التواصل ومخاطر السبام. نطاق رسمي ليس دليل قبول مساهمة أو وجود جهة اتصال. يلزم التحقق من القناة الحالية قبل أي تواصل. لا مراسلات أو روابط أو شراكات نُفذت.

المؤشرات: روابط تحريرية ذات صلة لأصل مفيد، زيارات إحالة متفاعلة واستفسارات موثقة. referring domains وspam score وDA وDR الحالية: NOT MEASURED. OpenSEO أعاد صفر مشاريع؛ لم يُنشأ مشروع ولم تُصرف credits. هذا لا يثبت غياب الروابط الخلفية.

## حدود GEO/AEO

جواب40–70 كلمة شرط تحريري طلبه المستخدم، وليس معيار ترتيب رسميًا. لكل دليل تراجع الإجابة والتعريف والحقائق الثابتة والشروط والخطوات والحدود والمصادر والأسئلة. لا تُطبق صيغة المقال على API أو نموذج التواصل.

لا زيادة اقتباس مضمونة، ولا Schema خاص يضمن الظهور، ولا llms.txt بديل عن الزحف. Google يذكر عدم وجود متطلبات إضافية خاصة للظهور في AI Overviews وAI Mode، وأن الأهلية لا تضمن الظهور. [المصدر](https://developers.google.com/search/docs/appearance/ai-features).
