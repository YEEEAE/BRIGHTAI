# مراجعة الهوية والبحث وصفحات `/en/`

**الحالة:** مراجعة محلية مكتملة ضمن المصادر والنتائج المتاحة؛ لا اعتماد قانوني، ولا تحقق من سجل تجاري، ولا تعديل أو نشر على الأنظمة الخارجية.  
**النطاق:** مرجع المشروع `docs/MASTER-PROJECT-BLUEPRINT.md`، `src/data/organization.ts`، `src/data/brand.ts`، صفحة `src/pages/about.astro`، المسارات الحية السبعة في `/en/`، الأصول العربية المقابلة، ونتائج بحث ويب مختارة.

## خلاصة القرار

- الاسم المتداول وفق مرجع المالك: **مؤسسة مُشرقة BRIGHT AI**. تكتب العلامة المختصرة **BRIGHTAI** دون مسافة في مواضع العلامة/النطاق. الاختلاف الكتابي وحده لا يثبت كيانًا آخر أو اسمًا قانونيًا مسجلًا.
- **AIGAS**: اختصار *AI Governance & Safety* واسم المجال/منظومة المنتجات؛ ليس المؤسسة ولا شهادة أو اعتمادًا.
- نتيجة البحث المختبرة تُظهر تزاحمًا حقيقيًا مع BrightAI أخرى في مجال الذكاء الاصطناعي والبنية التحتية، منها `bright.ai`، ومع `brighter.ai` في إخفاء الهوية المرئية، وكذلك استعمال AIGAS من جهة بريطانية مختلفة (`aigas.org.uk`). لا يكفي هذا البحث لإثبات أولوية الاسم أو تسجيله أو حصرية العلامة.
- غياب كيان موثق، عنوان، سجل، مؤهلات أشخاص، عملاء، نتائج، شهادات، أو شراكات يمنع نشرها كحقائق. التفاصيل الواجب تأكيدها موضحة في `EXTERNAL-FILE-DRAFTS.md`.
- صفحات `/en/` السبع تُخدم حيًا بحسب فحص GET، لكنها غير موجودة كصفحات مصدر في `src/pages/en/`. الخريطة القديمة تعرضها؛ ووجودها الحي لا يثبت أنها جزء من البناء الحالي.
- **لا تضف hreflang الآن.** صفحات عربية مقابلة موجودة لبعض المواضيع، لكن التكافؤ الدلالي والقانوني غير متحقق، وcanonical/alternate الحي غير متسق في كل الأزواج. صفحة `/en/` لا يجوز اعتبارها ترجمة لمجرد أنها تشير إلى `/`.

### حقائق يمكن نشرها الآن مع ضبط الصياغة

1. الموقع والنطاق المستخدمان علنًا: `brightai.live`.
2. اسم المشروع المتداول في مرجع المالك: «مؤسسة مُشرقة BRIGHT AI».
3. معنى AIGAS كما يرد في المرجع: AI Governance & Safety.
4. المنتجات الخمسة كما في التصور: Kernel, Firewall, Risk Engine, Human Gate, Ledger, Secure Chat (Kernel أساس مشترك؛ الأسماء الستة تشمل النواة وخمسة منتجات).
5. الحالة المتحققة من ملفات المشروع وتدقيقها: صفحات الموقع تصف تصورًا، ولا تثبت إتاحة تشغيلية أو تعاملًا تجاريًا للمنتجات.
6. الأدلة العملية القابلة للنشر بعد تنقية الأسرار: مستودع/تاريخ إصدار محدد، سجل تغييرات، اختبارات قابلة للتكرار، لقطات مختبر موسومة «محاكاة»، مواصفات API وعقودها، نتائج اختبارات مع حدودها، أمثلة اصطناعية، وقرارات تصميم موثقة. كل مثال يُربط بإصدار وتاريخ ونطاق وما لم يختبر.

- لكل شخص: الاسم، الموافقة، السيرة المصدرية، المؤهلات والجهة المانحة والتحقق منها، وحدود الدور. لا تنسب المراجعة أو التأليف لشخص بلا اعتماد.

## أدلة خبرة عملية بديلة عن السيرة العامة

الأفضل نشر **سجل عمل قابل للتكرار** لا صفة خبير:

1. سجل إصدار: SHA/وسم، تاريخ، نطاق، تغييرات مرئية، مراجعة، وأوامر تحقق ونتائجها.
2. بطاقات تحقق للمنتج: المدخلات الاصطناعية، الإجراء، expected/actual، نتائج سماح/حظر/تنقيح/موافقة، النطاق والقيود؛ اذكر بوضوح هل هي اختبارات محلية أو staging أو تشغيل عميل.
3. مختبرات موثقة: فيديو/صور من build معرف؛ banner دائم «محاكاة تعليمية» إذا لم يكن اتصالًا تشغيليًا؛ لا تعرض بيانات حقيقية أو أسرارًا.
4. دليل فني: API contract، نموذج تهديد، دورة حياة قرار، fixture اصطناعي، نتائج اختبارات RLS/tenant isolation، مع ذكر البيئة والعدد والتاريخ وعدم تعميمها إلى شهادة أمان.
5. سجل مصادر تنظيمي: اسم المستند والجهة والإصدار/المادة وتاريخ الوصول، وبيان هل المصدر إلزامي أم إرشادي، ومراجعة مختص موثقة.
6. حالة كل ادعاء: `planned / locally verified / staging verified / production verified / independently assessed`؛ لا تختصر الحالات إلى «متاح» أو «متوافق».
7. دراسات حالة مستقبلية: موافقة خطية قابلة للإلغاء، وصف الدور، حجم العينة والمنهج، baseline/after، عوامل الالتباس والحدود؛ وإلا لا تنشر أسماء أو نسب.
