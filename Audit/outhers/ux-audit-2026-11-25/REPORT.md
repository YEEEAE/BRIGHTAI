# تدقيق تجربة BRIGHTAI

## UX scorecard

التقييم مراجعة تصميم من 5، بنقطة لكل معيار: وضوح الغرض، وجود إجراء رئيسي، وجود إجراء ثانوي واضح، بيان الحالة عند الحاجة، ووجود طريق متابعة أو تعافٍ. الدرجة تخص واجهة المسار التي ظهرت محليًا.

| الصفحة | قبل → بعد | الإجراء الرئيسي | الإجراء الثانوي | الملاحظة والتعديل |
|---|---:|---|---|---|
| الرئيسية | 5 → 5 | استكشف المنتجات | ناقش احتياجك | الإجراءان واضحان في المقدمة. اختُصر نص الإجراء التجاري. |
| المنتجات | 4 → 5 | جرّب شكوى عميل | اختر مختبرًا | اختُصر تكرار روابط الرحلة إلى رابط باسم المنتج. بقي Firewall بارزًا برسمه، وعُرضت المنتجات الأخرى في صفوف. أضيف دليل مراحل الوصول. |
| Firewall | 3 → 5 | ابدأ المثال | اطلب الوصول لهذا المنتج | يظهر سياق المحاكاة بجوار اسم المنتج قبل إجراءات الفحص. |
| Risk Engine | 3 → 5 | ابدأ المثال | اطلب الوصول لهذا المنتج | يميّز CTA بين فتح أدوات تقييم المثال وطلب إتاحة المنتج. |
| Human Gate | 3 → 5 | ابدأ المثال | اطلب الوصول لهذا المنتج | يسبق وصف المحاكاة خطوات اتخاذ القرار، ويستقل رابط الوصول عن الإجراء داخل المختبر. |
| Ledger | 3 → 5 | ابدأ المثال | اطلب الوصول لهذا المنتج | صار ترتيب العنوان والمختبر مطابقًا لترتيب المستند. تبقى حالات التحقق في واجهة الدليل. |
| Secure Chat | 3 → 5 | ابدأ المثال | اطلب الوصول لهذا المنتج | تظهر مرحلة DEMO عند اسم المنتج. يظل النموذج العام محاكاة. |
| Kernel | 4 → 5 | ابدأ محاكاة السياسة | خيارات الوصول المؤسسي | يبدأ المسار عند حقل الأصل، وتميّز الشارة المختبر العام قبل قراءة نتيجة السياسة. |
| Pricing | 4 → 5 | جهّز طلب عرض سعر | قارن مراحل الوصول | تظهر الإجراءات بجوار المقدمة وتظهر حدود المعاينة والتجربة والتشغيل في دليل مشترك. |
| Trust | 3 → 5 | راجع حالة الأدلة | اطلب مستندات النطاق | يصل القارئ مباشرة إلى جدول الأدلة أو قناة الطلب. بقي تنبيه البيانات والادعاءات الأمنية. |
| Contact | 3 → 5 | جهّز مسودة | اختر قناة التواصل | المسودة اختيارية، والحالات تعطي خطوة تعافٍ واضحة، والقناة الخارجية لا تستلم النص تلقائيًا. |
| 404 | 5 → 5 | العودة للرئيسية | استعرض المنتجات | قُلّصت وجهات التعافي إلى رابطين، واختُبر عنوان مفقود فعلي. |
| Auth — دخول وإنشاء حساب | 4 → 4 | خيارات طلب الوصول عند عدم الإتاحة | تواصل معنا | راجعت واجهة التعافي المحلية وإعادة توجيه الدخول. الحقول والأكواد في الحالة المهيأة خارج دليل هذه الجولة. |
| App — Kernel وتجربة 48 ساعة | 3 → 3 | مسار الوصول من واجهة عدم الإتاحة | حالة النظام | التطبيق أعاد 503 في البيئة المحلية. الدرجة تخص واجهة عدم الإتاحة فقط. |

## Accessibility issues

| الشدة | الموضع | المعيار ذو الصلة | الدليل والإصلاح |
|---|---|---|---|
| كبيرة | Ledger | ترتيب ذو معنى 1.3.2، ترتيب التركيز 2.4.3 | كان CSS يقدّم المختبر والتنقل بصريًا بترتيب يخالف DOM. أزيلت قواعد إعادة الترتيب. |
| متوسطة | Contact | تحديد الخطأ 3.3.1، اقتراح التصحيح 3.3.3، رسائل الحالة 4.1.3 | أصبح الإدخال الفارغ مرتبطًا برسالة مسماة عبر `aria-errormessage`. حالات النسخ تستخدم منطقة إعلان ثابتة ويُحدد النص للتعافي من الرفض أو الفشل. |
| تحسين | المنتجات وKernel والأسعار | استخدام اللون 1.4.1 | المرحلة مكتوبة بالعربية والإنجليزية، والحدود مختلفة في الشكل. يصف الدليل شروط كل مرحلة، ولا يحمل أي منتج عام شارة تشغيل مؤسسي. |
| تحسين | الروابط الداخلية | ترتيب التركيز 2.4.3 | روابط البدء والمقارنة والأدلة تتجه إلى أهداف قابلة للتركيز؛ أضيفت مسافة تمرير في المواضع المتأثرة. |
| تحسين | الحركة | الحركة الناتجة عن التفاعل 2.3.3 (AAA) | وسّع تفضيل تقليل الحركة الحالي لإيقاف التمرير السلس في العناصر المتداخلة. |

## حالات التفاعل

| الحالة | العرض والسلوك |
|---|---|
| Loading | «جارٍ نسخ المسودة…»، يظل التركيز على الزر ويُمنع تكرار الطلب أثناء النسخ. |
| Empty | توجيه لكتابة وصف أو فتح القناة مباشرة، مع تركيز حقل المسودة. |
| Success | تأكيد نسخ المسودة وتعليمات لصقها قبل الإرسال. |
| Error | تحديد المسودة وطلب نسخها يدويًا. |
| Denied | تحديد المسودة مع رسالة صريحة عن رفض إذن الحافظة. مختبر Kernel يعرض قرار منع السياسة داخل نتيجة المثال. |
| Offline | إعلان مستقل قرب قنوات التواصل، مع إمكانية تحرير المسودة ونسخها محليًا. يختفي الإعلان عند عودة الاتصال. |

بُنيت الحالات على تفاعل موجود. مختبرات المنتجات تحتفظ بعقودها الخاصة ونتائجها الحالية.

## إعادة الاختبار

```sh
npm run build
HOST=127.0.0.1 PORT=4321 npm start
BASE_URL=http://127.0.0.1:4321 UX_OUTPUT=/tmp/brightai-ux node tests/ux-audit.mjs
```

اضبط `BASE_URL` على عنوان خادم Node المحلي. أزل `UX_OUTPUT` لتشغيل الاختبار دون إنشاء الصور والملفات. تقرأ أدلة التسميات من شجرة الوصول في Chromium وتُشغّل قواعد axe المحددة عند 375 بكسل. النطاق يشمل لوحة المفاتيح والتجاوز إلى المحتوى والقائمة المتنقلة ومسار Kernel ونسخ المسودة. لا تغطي الجولة نطق VoiceOver/NVDA أو تشغيل Auth/App مع مزود مصادقة وبيانات مؤسسة مهيأة.

## نتيجة التحقق المحلي

- `npm run build` نجح. ظهرت تحذيرات Astro عن قراءة ترويسات الطلب في صفحات مولّدة مسبقًا في البناءين.
- Playwright أكمل 64 فحص صفحة × مقاس بلا إخفاق، إضافة إلى سيناريوهات القائمة والمراحل وKernel والحالات الست في Contact. لم يسجل axe مخالفات ضمن القواعد المشغلة على الصفحات الـ16 عند 375 بكسل.
- قورنت 64 لقطة قبل و64 بعد، وأضيفت سبع لقطات لدليل المراحل وحالات التواصل. يشمل التقرير مسار ‎404‎ برمز HTTP حقيقي. أعاد App رمز ‎503‎، ووصل Tab إلى رابط التعافي الأول في صفحة البوابة البسيطة.
- الاختبارات محلية، والنشر خارج هذه الجولة.
