# الأيام 12–21 | عقود الربط بين منتجات AIGAS

**الحالة PARTIAL** · 24 نوفمبر 2026 · نسخة العمل فوق `60a8c790`. استخدمت مصفوفة التكامل في [كتالوج المنتجات](../../docs/PRODUCT-MASTER-CATALOG.yaml)، ومواصفات [Firewall](../../docs/products/firewall/PRODUCT-SPEC.md)، و[Ledger](../../docs/products/ledger/PRODUCT-SPEC.md)، و[Human Gate](../../docs/products/human-gate/PRODUCT-SPEC.md)، و[Risk Engine](../../docs/products/risk-engine/PRODUCT-SPEC.md)، و[Secure Chat](../../docs/products/secure-chat/PRODUCT-SPEC.md)، و[عقد سياسة Kernel](../../docs/AIGAS-KERNEL-POLICY-HIERARCHY-AND-ENFORCEMENT.md). المسارات أدناه هي المسارات الموجودة في التطبيق. واجهات `/v1` في ملفات `API-CONTRACT.yaml` تصف العقود المستهدفة.

**بيئة الإثبات** · Node 22.22.2، وPostgreSQL 18.6 مؤقت على loopback بمخطط Auth اصطناعي ودور فعلي `aigas_runtime` بلا SUPERUSER أو BYPASSRLS. اختبارات HTTP تستدعي المعالجات الفعلية بهوية اصطناعية محقونة. اختبار بناء Astro مستقل على الاعتمادات من القفل. جميع المدخلات اصطناعية.

## مصفوفة الكتالوج

مسارات API في الجدول تُقرأ من جذر `/app/api/`. لكل صف تصنيف يخص الانتقال المذكور وحدّه.

| العقد | نقطة الدخول ← API ← الحفظ ← النتيجة الظاهرة | الحالة والدليل |
|---|---|---|
| INT-01 · Firewall → Risk Engine | من وضع التنفيذ في `/app/firewall/` إلى `firewall/guarded-executions/`. يقيّم Kernel وقواعد Firewall ويحفظ `aigas_fw_decisions`. حقل الاعتماد يصف Risk Engine بأنه خارج الفحص الأساسي. سجل الأصول والتقييمات مستقل. | **غير متحقق** لربط تقييم أصل معين بطلب Firewall. لا توجد علاقة موثوقة بين الطلب والأصل في هذا المسار. |
| INT-02 · Firewall → Human Gate | تنفيذ Firewall يثبت قرار `ESCALATE` بعد `ALLOW` من Kernel. مع إتاحة المنتج وسياسة المؤسسة المفعلة ينشئ `aigas_hg_requests` و`CREATED` مع القرار في معاملة واحدة. تظهر إحالة برقم المراجعة، وتُقرأ في `human-gate/requests/?workspace=…&request=…` ضمن العرض والصلاحيات. يثبت المراجع `APPROVED` أو `REJECTED` عبر `decide/`. | **مثبت في HTTP وPostgreSQL محليين** لطلب واحد تحت التزامن، وقرار واحد، ومنع مراجعة الذات، وعزل العرض، والربط بنسختي السياستين وبصمة قرار Firewall، ورفض الربط القديم بعد تغير القاعدة. `execute/` يعيد `409 EXECUTION_INTEGRATION_NOT_CONFIGURED` للإذن الصالح. **غير متحقق** لاستئناف استدعاء مزود. |
| INT-03 · Firewall → Ledger | المعاملة نفسها تسجل الحد الأدنى في `aigas_audit_events`. عند إتاحة Ledger يضيف الكاتب `firewall.decision.recorded` إلى `aigas_ld_events` بمرجع القرار، وضع LAB/GUARD، الإجراء والقاعدة وبصمة القرار. تُقرأ الأدلة عبر `ledger/events/` وتُفحص من واجهة Ledger. | **مثبت في HTTP وPostgreSQL محليين** لصف دليل واحد مرتبط بقرار التصعيد وقراءة Ledger والتحقق من البصمة. البصمة تغطي بيانات القرار المرتبطة بالسياق، ولا تشمل النص. |
| INT-04 · Risk Engine → Human Gate → Risk Engine | `/app/risk-engine/` → `risk-engine/assets/:assetId/assessments/` → `aigas_re_assessments`. يحيل `0039` تقييم HIGH الحالي عندما تكون إتاحة المنتج والسياسة ساريتين. تُحفظ إحالة واحدة لكل تقييم بمرجع الأصل ونسخته وإصدار المنهج. يظهر رابط الطلب وحالة المراجعة في تاريخ تقييمات مقدم الطلب بعد إعادة القراءة. | **مثبت في HTTP وخدمة Human Gate وPostgreSQL محليًا** للإحالة، وقبول قرار مستقل واحد تحت التزامن، والرفض، وإبطال أهلية التقييم الذي تجاوزه تقييم أحدث. القرار يبقى مثبتًا في `aigas_hg_decisions`، وتبقى درجة الخطر كما حسبها المنهج. الإجراء `execute/` تحجبه الخدمة بـ`REVIEW_ONLY`، ولا يصدر إذن تنفيذ. |
| INT-05 · Human Gate → Ledger | سجل الطلب والقرار في Human Gate وKernel، ثم `kernel.audit.recorded` المربوط بمرجع التدقيق لإحالات Firewall وRisk. تدقيق اسم مساحة العمل يتبع مسار Kernel. الملاحظة التجريبية لها أنواع Human Gate الاصطناعية الخاصة. واجهة `/app/ledger/` تعرض مصدر الدليل وبياناته المسموحة. | **مثبت في HTTP وPostgreSQL محليين** لزوج إنشاء وموافقة مرتبطين بكل إحالة اختبار. التدقيق الأساسي يعمل مع غياب منحة Ledger. الدليل الاختياري يضيف مراجع وصفية، وتتعطل المعاملة إذا أوجبت سياسة أدلة سارية حدثًا تعذر حفظه. |
| INT-06 · Secure Chat → Firewall وKernel | `/app/secure-chat/` → `secure-chat/messages/` يتحقق من النموذج المعتمد والحصة، ثم `authorizeChatContext` يقرأ قرار Kernel وقواعد Firewall ويحفظ `aigas_kernel_policy_decisions` وAudit قبل الخروج. يُفحص السياق في كل دور، ويعاد فحص الرد قبل عرضه. غياب نموذج معتمد يعرض حالة إيقاف. | **مثبت في PostgreSQL محليًا** للسماح والتنقيح والرفض قبل الخروج، حتى من دون منحة Firewall في العينة. يتطلب التنفيذ الحالي قواعد صالحة للإرسال. **غير متحقق** لاتصال مزود أو رحلة رد حقيقي أو ملكية سياسة Firewall المتقدم كإضافة مستقلة. |
| INT-07 · Secure Chat → Ledger | عند حجب طلب في طبقة الإعداد أو حماية المحتوى أو اتخاذ قرار سياسة، يكتب Chat سجل Kernel ثم مرآة `kernel.audit.recorded` بواسطة كاتب Ledger المعتمد. يحمل الحدث رمز الإجراء ومرجع التدقيق، ويظهر ضمن مصدر Kernel في Ledger. | **مثبت في PostgreSQL محليًا** لرفض واحد مع Ledger، ولمسار تدقيق أساسي مع غياب Ledger. تحققت قائمة حقول الحدث واستبعاد متن السياق. **غير متحقق** لأدلة اكتمال مزود حقيقي. |

## الانتقالات الإضافية المستخرجة من مواصفات المنتجات

| الانتقال | نقطة الدخول والحفظ والقراءة | الحالة |
|---|---|---|
| Kernel `REQUEST_APPROVAL` → Human Gate | نشر السياسة يبدأ من `/app/kernel/` و`kernel/policies/`. تقرأها `evaluateKernelPolicy` عند الطلب المحكوم. التزام الموافقة غير المنفّذ يُرجع توقفًا آمنًا، ويُحفظ قرار السياسة في مسار الإنفاذ. | **مثبت في HTTP وPostgreSQL محليين** لعودة `403` بلا إحالة أو إرسال، حتى مع قاعدة تصعيد وإتاحة Human Gate. **غير متحقق** كإحالة عامة. إنشاء مراجعة Firewall يبدأ حاليًا بإجراء Firewall نفسه بعد `ALLOW` من Kernel. موافقة نشر نسخة سياسة Kernel عملية مستقلة عن مراجعة تشغيل طلب فعلي. |
| Human Gate → Kernel، استئناف تغيير الاسم | من نموذج Human Gate إلى `requests/` ثم `decide/` ثم `execute/`. بعد إعادة فحص نسخة الاسم والسياسة وصلاحية الطرفين، يحدّث `aigas_tenants` ويستهلك الإذن ذريًا، ويظهر التنفيذ في بطاقة Human Gate ويُقرأ الاسم الجديد في Kernel. | **مثبت في HTTP وPostgreSQL محليين** لاستئنافين متزامنين ينتجان أثرًا واحدًا، وإذنًا مستهلكًا واحدًا، ورفض إعادة التنفيذ وانتهاء الصلاحية وتغيّر السياسة والهدف والصلاحية، والتراجع عند فشل التدقيق. |
| Risk Engine → Ledger | واجهة الأصول والتقييمات → `risk-engine/assets/` و`assessments/` → سجل أصول وتقييمات وإصدارات. الكاتب يثبت `risk_engine.asset.created/updated` و`risk_engine.assessment.created` كمراجع ونسخ ودرجة ومنهج يمكن قراءتها في Ledger. | **مثبت في PostgreSQL محليًا** للسجل ومراجع تقييم المخاطر. القبول الإداري للمعالجة مسار Risk Engine المستقل؛ موافقة Human Gate في هذا الربط لا تعدّل المعالجة ولا تمنح تصريح نشر. |
| Human Gate أو Risk → Secure Chat | سياسة Chat تفحص كل طلب وتطبق الحجب الحالي. لا يجلب Chat إذن Human Gate، ولا يعيد الطلب المحجوب عند قبول مراجعة Firewall أو Risk. | **غير متحقق** لعمل مؤثر مستأنف داخل Chat. عقد Chat يشترط إجراءً مأذونًا ومربوطًا، وتظل محادثة أو إجابة النموذج خارج سلطة التنفيذ. |
| موصل التفسير وموصلات المنتجات الخارجية | `risk-engine/assist/` يملك اختبارًا بمزوّد محقون، وFirewall له محوّل اصطناعي محلي لتقييم مسار ALLOW/REDACT ورفض محوّل خارجي محقون. | **نموذج** للمزوّد. **غير متحقق** لـGroq/Qwen 3.8 27B أو أي استدلال حي، وSSO/MFA الحقيقيين، والتكاملات المؤسسية SIEM/SOAR/ITSM/CMDB، وعقود SDK/MCP الخارجية. |

## إعداد الإحالة المحلية

يضيف `0039` الخيار `risk_assessment_review_enabled` مع قيمة ابتدائية `false`، من دون تغيير أعلام المؤسسات أو منح المنتجات. اختبارات الإحالة فعّلت الخيارين فقط في قاعدة الاختبار. إخراج Risk Engine يبقى متاحًا مع غياب التكامل. يسجّل Human Gate مراجعة مستقلة أحادية المرحلة؛ قرار المراجعة وبصمة الربط محفوظان داخليًا، والإثبات القابل للتصدير أو التوقيع الخارجي خارج هذا المسار. إعادة طلب من واجهة Firewall بمعرّف سابق تُرفض بدل إعادة التقييم أو الإرسال. تقييمان جديدان مستقلان في Risk Engine يملكان مرجعين؛ الثاني يجعل مراجعة الأول قديمة.

## التحقق وحدوده

- **مثبت — اختبارات محلية**. نجحت 59 حالة وحدة و17 حالة مركزة تشمل HTTP وPostgreSQL وترتيب الترحيل، بصفر فشل أو تخطٍ. تشمل الحزمة `tests/firewall-review-binding.test.mjs` و`tests/human-gate-db.test.mjs` و`tests/risk-engine-db.test.mjs` و`tests/secure-chat-db.test.mjs`. عمليات الاختبار حجبت الاتصالات خارج loopback.
- **مثبت — ترحيل محلي**. نجح مسار فارغ بـ35 إيصالًا ومسار ترقية تاريخي بـ36 إيصالًا حتى `0039`، ونجحت 13 حالة حراسة في `scripts/db-migration-rehearsal.mjs`. لا يملك `authenticated` أو `anonymous` حق تنفيذ أي من الدوال الثلاث في `0039` على كلا المسارين.
- **مثبت — بناء محلي**. نجح Astro 6.4.8 في بناء 64 صفحة عامة. تطابق HTML الرئيسية والملفات المحلية المرتبطة به بايتًا ببايت عبر 17 ملفًا إجمالًا، منها CSS المشترك وملفات الحركة والخطوط.
- **مثبت — Chrome محلي، 390×844**. استخدم المتصفح التطبيق المبني وواجهاته الفعلية. من المؤسسة الثانية فتح رابط Firewall المراجعة الصحيحة، وظهر قرار الموافقة مع توقف الاستئناف. فتح رابط Risk Engine المراجعة وظهر الرفض في تاريخ التقييم بعد الرجوع. عُطّل إرسال Secure Chat ورفضت API محاولة مباشرة بـ`503 NO_APPROVED_MODEL` بلا حجز طلب. ظهر أثر الرفض في تفاصيل Ledger، وطابقت القاعدة ثمانية أحداث موزعة على Firewall (1) وKernel (5) وRisk Engine (2).
- **نموذج — هوية المتصفح**. جلسة HTTPS ومفاتيح JWKS ورموز JWT اصطناعية محلية. تحقق التطبيق من التوقيع ومحدد المؤسسة. اتخذ المراجع قراري المتصفح عبر HTTP المحلي بهوية مستقلة. مزوّد الهوية الحقيقي خارج القياس.
- **نموذج — المزوّد**. اجتاز محوّل Firewall الاصطناعي `8/8` في `scripts/firewall-local-verify.mjs`، بما فيها تمرير النص المسموح أو المنقّح وإيقاف الحجب أو التصعيد أو التحذير قبل الاستدعاء. محوّل تقييم المخاطر محقون في الاختبار أيضًا.
- **غير متحقق — البيئة المستهدفة**. لم تُطبّق الترحيلات على بيئة مشتركة. لا دليل على Neon Auth أو المزود في البيئة المستهدفة أو على استئناف إجراء خارجي. Groq/Qwen 3.8 27B بقي ضمن بيانات التقييم فقط. لا نشر أو إجراء باسم المالك.
- **حدود العمل التجاري**. سعر الورشة التمثيلي في المسودة غير معتمد، و1,000 دولار هدف صافٍ طموح دون ضمان. لا أثر تجاري يُستنتج من هذه الاختبارات.

**القرار التالي** · تثبيت عقد محلي واحد لـ`Kernel REQUEST_APPROVAL` يحدد نقطة الاستئناف والعملية المسموح بها وبصمتها ومالكها وفشلها، ثم استخدامه لاختبار إجراء اصطناعي يستهلك الإذن مرة واحدة. يبقى استئناف Firewall وSecure Chat إلى مزود خارجي مرتبطًا بتعريف إجراء واعتماد منفصلين. يحتاج INT-01 مرجع ربط موثوقًا بين نقطة التحكم وأصل المخاطر قبل استخدام تقييمه في قرار الحماية.
