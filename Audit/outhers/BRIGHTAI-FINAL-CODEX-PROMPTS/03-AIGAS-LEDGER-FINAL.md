## نقطة الانطلاق المثبتة من الفحص

- `src/server/ledger/service.mjs` يسجل أحداثًا من `ledger.synthetic-lab` فقط ويستخدم SHA-256 لكل صف، مع استعراض وتصفية وتصدير JSON. القيد الحالي صريح: ليس توقيعًا مستقلًا ولا دليلًا قانونيًا غير قابل للتلاعب إداريًا.
- `0003_aigas_ledger.sql` يتضمن جدول `aigas_ld_events` ومانع UPDATE/DELETE على الصفوف، وهو غير موجود بعد في Neon المفحوصة.
- Kernel لديه `aigas_audit_events` مستقل. شراء Ledger لا يجوز أن يكون شرطًا لاحتفاظ Kernel بالتدقيق الأساسي.

## نفّذ الآن — بالترتيب

1. **المخطط والنسخ:** حدّث migration 0003 بإضافات بسيطة قابلة للتتبع لتحمل مصادر الأحداث المؤسسية الموثوقة (`firewall`, `human-gate`, `risk-engine`, `kernel`) بجانب المصدر الاصطناعي، مع `tenant_id`, `event_id`, نوع الحدث، actor/id مرجعي، وقت خادم، إصدار السياسة، metadata allowlist، والبصمة. لا تحفظ prompt أو نصوص محادثات أو بيانات كاملة افتراضيًا. لا تنفذ migration في قاعدة إنتاج دون موافقة.
2. **واجهة كتابة داخلية موثوقة:** أضف خدمة Server-side تستقبل أحداثًا من مسارات التطبيقات الخادمية الموجودة فقط، وليس من عميل يحدد actor أو tenant بنفسه. وفّر idempotency key بسيطًا للأحداث القادمة من عمليات محددة، وتسجيلًا داخل transaction حيث يتطلب المسار دليلًا إلزاميًا. فشل التسجيل الإلزامي يوقف العملية المعنية بدل تأكيد نجاح بلا دليل.
3. **تتبع سلامة أقوى دون مبالغة:** حافظ على SHA-256 الحالي، وأضف ربطًا متسلسلًا أو رقم تسلسل داخل نطاق المؤسسة/السجل عند الحاجة بطريقة تحقق مستقرة وواضحة، مع فحص سلامة السلسلة عند العرض والتصدير. ابنِ ملف JSON يحتوي event + canonical hash inputs + version + hash references، وموثّقًا بصيغة يمكن التحقق منها دون الاتصال بخادم التطبيق. لا تسوّق هذا على أنه توقيع خارجي أو مقاوم لمسؤول قاعدة البيانات.
4. **واجهة الأدلة العملية:** صفحة `/app/ledger/` تعرض الأحداث من المصادر الفعلية، والبحث/التصفية، والتفاصيل، وحالة سلامة كل حدث أو حزمة، وزر تنزيل JSON من الخادم بعد صلاحية وتسجيل audit لعملية التصدير. امنع العضو غير المخول من التصدير، وأظهر مصدر الحدث وإصدار طريقة البصمة.
5. **تكامل لا يعتمد عليه كل منتج:** استخدم قنوات Ledger اختياريًا للمنتجات التي فعّلت ترخيصه، مع استمرار audit Kernel الأساسي بدون Ledger. إذا كانت سياسات مهمة تستلزم evidence ولم يتوفر Ledger ولا الاحتياطي الموافق عليه، امنع العملية الحساسة وأظهر السبب؛ لا تحول غياب ترخيص Ledger إلى إيقاف شامل للنظام.
