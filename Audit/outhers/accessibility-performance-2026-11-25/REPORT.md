# تدقيق الوصول والأداء — BRIGHTAI

**الحالة: PARTIAL — تدقيق محلي مكتمل للمسارات المستجيبة؛ بوابة التجربة الحقيقية وقياسات الإنتاج غير متحققة.**

## الملخص التنفيذي

- فُحصت 11 استجابة محددة بـPlaywright 1.65.1 و`@axe-core/playwright` 4.14.1 في Chrome 158.0.8127.38، عند 1280×900، بتاريخ 2026-11-25 (توقيت الرياض).
- لم يسجل Axe أي مخالفة في المسارات المفحوصة، ولم تسجل اختبارات smoke أي إخفاق. وُجد 20 نتيجة `incomplete` مجمعة عبر المسارات العشرة التي وصلت إلى صفحات الموقع؛ هذه نتائج تتطلب مراجعة يدوية وليست مخالفات مؤكدة.
- تسلسل العناوين، وجود landmark رئيسي، تسميات الحقول، واتجاه RTL اجتازت الفحوص الآلية في الصفحات المتاحة. اجتاز مثال نافذة التصميم تدوير التركيز، واجتاز حقل البريد غير الصالح ربط رسالة الخطأ المرئية.
- `/app/trial/` أعاد HTTP 503 بسبب عدم توافر اعتماديات التشغيل في بيئة التدقيق. فُحصت صفحة الخطأ فقط؛ لم تُفحص بوابة التطبيق أو رحلة التجربة الحقيقية.
- قياسات LCP وCLS وTTFB محلية ومختبرية. قيمة INP المعروضة أدناه وكيل اصطناعي لتوقيت تفاعل واحد وليست INP ميدانية. لا توجد درجات Lighthouse أو بيانات CrUX/RUM إنتاجية.

## ما تم فحصه

- **Axe:** وسوم WCAG 2.0/2.1 A وAA وWCAG 2.2 AA. لم تظهر مخالفات؛ النتائج `incomplete` لم تُراجع بصريًا/يدويًا بندًا بندًا، لذلك لا يُستنتج امتثال WCAG كامل.
- **البنية:** فُرض وجود `h1` واحد وتسلسل بلا تخطٍ في مستويات العناوين، ووجود landmark رئيسي، وتسميات الحقول. اجتازت الصفحات المتاحة هذه الشروط.
- **التشغيل بلوحة المفاتيح:** رُصدت أول ست محطات Tab في كل صفحة، وكان مؤشر التركيز ظاهرًا. اختبار نافذة `/docs/design-system/` أثبت انتقال التركيز إلى الداخل واحتجازه عند طرفي Tab وShift+Tab. هذا مثال مكوّن منفصل عن قائمة المسارات الأساسية.
- **الأخطاء والحقول:** لا توجد عناصر `aria-invalid` على مسارات الفحص الأساسية في حالتها الافتراضية. اختُبر مثال `#ds-email` في صفحة نظام التصميم: `aria-invalid=true`، ورسالة الخطأ موجودة ومرئية ومرتبطة عبر `aria-describedby`. لم تُنفّذ رحلة إرسال تسجيل حقيقية أو اختبار أخطاء backend.
- **RTL وتقليل الحركة:** الصفحات المتاحة تحمل `lang=ar` و`dir=rtl`. حاكى المتصفح `prefers-reduced-motion: reduce`، وكانت `scroll-behavior:auto` ولم تُرصد حركات CSS/WAAPI جارية أطول من 10ms. صفحة 503 مستثناة من فحص عقد RTL للبوابة.
- **التباين:** لم يسجل Axe إخفاقات تباين مؤكدة؛ لكن فحص التباين اليدوي عبر الخلفيات والصور والحالات التفاعلية لم يُجرَ. لا تُعد نتيجة Axe وحدها إثباتًا للتباين الكامل.

## الأداء والأصول

- جُمعت LCP وCLS من PerformanceObserver وTTFB من Navigation Timing، واستخدم CDP لالتقاط استعمال قواعد CSS. لا تمثل هذه قراءة خادمية/إنتاجية.
- تغيّرت قياسات CLS بين تشغيلات المختبر: التشغيل النهائي سجل 0.145 لـLedger و0.209 لـContact، بينما سجلات تشغيل كامل سابق ضمن التدقيق سجلت 0.000 لهما. هذه النتيجة غير المستقرة تستحق إعادة قياس في بيئة ثابتة وفحصًا بصريًا؛ لا تُعامل كقيمة ميدانية مستقرة.
- `*وكيل INP` مأخوذ من Event Timing لتفاعل اصطناعي واحد (غالبًا فتح `details/summary`) ويظهر فقط عند توفره. ليس INP حسب تعريف Core Web Vitals الذي يحتاج توزيع تفاعلات مستخدمين حقيقيين عند الشريحة المئوية 75.
- TTFB المحلي (1–37ms في آخر تشغيل للمسارات العامة، و4ms لصفحة 503) لا يعكس الشبكة أو الخادم العام. LCP المحلي يتراوح في التشغيل النهائي بين 40 و2032ms، ويتأثر بآلة الاختبار وترتيب تحميل الموارد.
- نسب CSS غير المستخدم هي لقطات CDP لحالة/مسار واحد، وليست قائمة آمنة للحذف؛ تراوحت 49.8–92.6% في الصفحات العاملة (و13.7% لصفحة 503). ظهر على `/products/` ملف `PageShell` بحجم 72,489 بايت مع نحو 91.7% غير مستخدم في تلك اللقطة، وعلى `/docs/` بلغت النسبة الإجمالية نحو 92.6%. محاولة جعل CSS الحركة مشروطًا لم تخفض الحجم المرصود؛ بقيت CSS مشتركة/مجمعة، لذلك لم يُدّعَ إصلاح كامل للمشكلة. يلزم تقسيم CSS حسب عائلات الصفحات مع اختبارات مرئية مستقلة.
- صور الصفحات الملتقطة كانت WebP ولم يتجاوز مورد صورة نقطي 100KB في النقل؛ لم يُعد ضغط الصور دون دليل على حاجة. الموارد الكبيرة نسبيًا التي رصدها القياس شملت ملف `/visuals/neural-particles.bin` بحوالي 100.3KB على الرئيسية، وحزم JavaScript بحوالي 126.6KB في `/docs/` و160.7KB في `/auth/sign-up/`.
- استُبدلت مراجع خطوط Plex Arabic إلى WOFF2 وأُضيف preload للوزن 400. مجموع الملفات صار 212,372 بايت بدل 672,112 بايت لملفات TTF المقابلة (توفير يقارب 68.4%). بقيت ملفات TTF الأصلية.

## التغييرات المنفذة

- إضافة `tests/accessibility-performance-smoke.mjs` مع Playwright وaxe، وفحوص البنية والتسميات والأخطاء ولوحة المفاتيح واحتجاز التركيز وتقليل الحركة ومؤشرات الأداء ولقطة استعمال CSS.
- إضافة الأمر `npm run test:accessibility:smoke` وworkflow في `.github/workflows/accessibility-performance.yml` لتشغيل `npm ci` ثم البناء وتثبيت Chrome وتشغيل smoke على Node 22.x.
- إصلاح accessible name في مصفوفة Risk Engine بإزالة الاسم المضاف الذي يتعارض مع النص المرئي.
- تحسين احتجاز Tab/Shift+Tab في مثال الحوار ضمن صفحة نظام التصميم.
- استخدام WOFF2 للخطوط العامة والبوابة وSecure Chat، وإضافة preload لخط 400.

## الحدود والحالة المتبقية

- عقد المشروع يطلب Node 22.x؛ البيئة المحلية كانت Node 24.20.0 وnpm 11.19.0. البناء المحلي نجح مع تحذيرات Astro المعتادة في prerender، لكن هذا لا يثبت سلوك Node 22.
- `npm ci` لم يكتمل محليًا بسبب `ENOTFOUND registry.npmjs.org`، لذا إعادة إنشاء `node_modules` من القفل غير متحققة في هذه البيئة. `npm ls --depth=0` والبناء والـsmoke نجحت باستخدام الاعتماديات الموجودة محليًا.
- `/app/trial/` أعاد 503؛ backend/runtime الحقيقي وبيانات الدخول لم تتوفر. لا ادعاء بتغطية البوابة الحقيقية أو رحلة إنشاء حساب كاملة.
- لا اختبار قارئ شاشة فعلي، ولا مراجعة بشرية كاملة للتباين، ولا اختبار عدة متصفحات/أحجام شاشات، ولا بيانات أداء حقلية أو Lighthouse production. لا يمثل هذا التقرير شهادة امتثال أو جاهزية إصدار.
- الأولوية التالية: تهيئة اعتماديات runtime للاختبار، إعادة قياس CLS على تكرارات وبيئة مستقرة، ثم تقسيم CSS المتبقية والتحقق المرئي لكل عائلة صفحات قبل حذف أي قواعد.
