# الأيام 8–17 — تحقق تشغيل AIGAS محليًا

**النطاق** — نسخة العمل فوق `ee7f9d29a45fabf341b1f576d336ffbd702f0ea3`، ضمن دورة 18–19 نوفمبر 2026. الاختبارات على loopback فقط، ببيانات `example.test` وPostgreSQL 18.6 مؤقت. لم تُحمّل ملفات البيئة أو بيانات عملاء. إصلاحات Git محلية في ملفات العمل ولم تُنشر.

## الإصلاحان

- تحت `aigas_runtime` كانت قائمة الدعوات فارغة للمدعو قبل العضوية، وكان قبول الدعوة يرجع `503 INVITATION_BOOTSTRAP_REQUIRED`. يضيف `0038` قائمة مرتبطة ببريد الفاعل الموثّق، ويصل مسار HTTP بالقبول المقيّد. تتحقق الدالة من حالة الدعوة ومدة صلاحيتها وربط المؤسسة وصلاحية الداعي. تسجّل القبول والعضوية والتدقيق في معاملة واحدة. بقي توقيع دالة `0036` متاحًا لمستدعيها الحاليين.
- كان فحص Kernel يقرأ مخطط الإدارة بصلاحيات حساب الاتصال `NOINHERIT` ويرجع `degraded`. صار يجري داخل المعاملة التي تستخدمها طلبات التطبيق ويُفعّل دور التشغيل نفسه.

## مثبت — PostgreSQL وAstro محليًا

| النطاق | ما قيس |
|---|---|
| الترحيل | تثبيت فارغ `34/34`، وإعادة مسار الترقية التاريخي `35/35` شاملًا 11 إيصال خط أساس و24 ترحيل Delta حتى `0038`. اجتازت بروفة الترحيل 13 حالة حراسة. تحققت بصمات إيصالات التثبيت الفارغ مع الملفات وأعاد فحص الاستئناف قائمة فارغة. |
| الصلاحيات وRLS | مصفوفة `90/90`، تشمل رؤية الدعوة للمستلم فقط، منع وصول أدوار العميل إلى الدوال، وإعادة القبول من دون إنشاء حدث تدقيق ثانٍ. حساب اتصال منفصل `NOINHERIT` بدور فعلي `aigas_runtime` و`NOSUPERUSER NOBYPASSRLS`. |
| الجلسة | عبر Chrome وخادم Node المبني، فُتحت جلسة اصطناعية ثم أعاد تسجيل الخروج نموذج الدخول. رفض المُدقّق JWT منتهيًا بـ`401` بعد محاولة تحديث واحدة، أُزيلت بطاقات التجربة، ورُفض طلب الكتابة المحمي بـ`401`. |
| الدعوات | القائمة تعرض الدعوة لصاحبها فقط، وتعرض المنتهية دون زر قبول. قبِل المتصفح الدعوة الصالحة، وفتح Kernel بعد `200`. أثبتت القاعدة عضوية `MEMBER` وحدث تدقيق واحد. المنتهية `410`، والهوية الأخرى `403`، والقبول قبل إثبات Auth `409`. |
| التجربة | بدأت من المتصفح بعد OTP اصطناعي بخمسة نطاقات قراءة لمدة 48 ساعة. عند تقديم انتهاء المنح في قاعدة الاختبار، تعطّلت الأزرار الخمسة. قراءة Ledger رجعت `200` قبل الحد و`403 EXPLORATION_EXPIRED` بعده. إعادة البدء أعادت المساحة نفسها بلا تمديد. |
| العزل بالاتجاهين | عاد الطلب لنطاقه بـ`200`، وأعاد طلب لوحة Kernel والأعضاء للمستأجر الآخر `403`. أزال المتصفح محدد المساحة المرفوضة في الاتجاهين. أعاد دور التشغيل صفر صفوف للجداول المقاسة في النطاق الأجنبي. |
| الصحة والاستعادة | صحة Kernel والجاهزية `200` مع فحص JWKS الاصطناعي مفعّل، و`/healthz/` يدعم HEAD. توقفت جاهزية الخادم بـ`503` عند إيقاف قاعدة الاختبار. استعاد `pg_restore` النسخة المنطقية على مثيل PostgreSQL جديد خلال 203 مللي ثانية في هذه العينة. تطابقت 34 بصمة وبيانات 6 جداول، وتكرر رفض القراءة الأجنبية بعد الاستعادة. |
| الاختبارات المركزة | `17/17` للهوية والتجربة والجاهزية وترتيب الترحيل وإتاحة التسجيل. |
| حراسة الواجهة الرئيسية | خرج بناء Astro 6.4.8 على Node 22.22.3 بـ64 صفحة عامة. تطابق HTML للرئيسية و13 ملفًا محليًا تشير إليه الصفحة بايتًا ببايت قبل الإصلاح وبعده. |

النتائج المسجلة في [evidence.json](evidence.json). ظهر تحذير ViewTransition في Chrome أثناء التنقل، واستمرت الرحلات إلى الحالات المتوقعة. مسار التحقق المتكرر للترحيلات هو `scripts/db-migration-rehearsal.mjs --json <path>`، ولـRLS هو `scripts/verify-runtime-rls.mjs --json <path>`، مع PostgreSQL 18 محليًا. دليل المتصفح من خادم `scripts/server.mjs` والصفحات المضمّنة في البناء.

## نموذج — تكامل الهوية

بديل Auth محلي عبر HTTPS يحاكي جلسة البريد وكلمة المرور وOTP وقبول المؤسسة. مفتاح Ed25519 مؤقت يوقّع رموزًا اصطناعية، والخادم المبني يستخدم مدقق JWT وJWKS ومسارات التطبيق الفعلية. بيانات انتهاء التجربة حُرّكت في PostgreSQL المؤقت لاختبار الحد من دون انتظار 48 ساعة. لم يخرج بريد أو طلب استدلال من الاختبار.

## غير متحقق — البيئة المستهدفة

- اعتماد المالك لبيئة Staging قابلة للإتلاف، والتحقق من هوية البناء، ودور مالك الدوال، وعضوية Pooler وصلاحيات `SET ROLE`، ودفتر الترحيلات الفعلي وبصماته قبل اختيار مسار الترقية. التحقق من تعطيل Data API أو انعدام وصول أدوار العميل فيها يحتاج مصدر البيئة نفسها.
- التحقق من Neon Auth الفعلي وإعداد الأصل وJWKS ورموز الجلسات، وتوثيق البريد وOTP وتسليم الدعوات. التحقق المحلي شمل المُصدِر والتوقيع ووقت الانتهاء. عقد الجمهور `aud` وإبطال جلسة المزوّد يتطلبان تحققًا مستقلًا. لا دليل تشغيل لـMFA/SSO.
- الاستعادة المنطقية المحلية لا تقيس استعادة Neon إلى نقطة زمنية أو RPO أو RTO على الهدف. تحتاج استعادة الهدف ومراجعة بصمات الدفتر والصلاحيات وإعادة رحلة المستأجرين قرار المالك.
- Groq وQwen خارج رحلة الهوية والعزل. لم تُفعّل أي إعدادات للمزوّد أو تُجرَ اتصالات استدلال.

**القرار التالي** — يراجع المالك تغييرات `0038` ويحدد بيئة Staging معزولة ومسار ترحيل معتمد بناءً على دفترها الفعلي. تبقى بوابة التشغيل على البيئة المستهدفة معلّقة حتى توثيق الاستعادة ورحلة الدخول والدعوة وانتهاء التجربة والعزل بالاتجاهين هناك.
