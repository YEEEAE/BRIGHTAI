# خطة القبول واختبار الاستعادة المعزول

**الحالة:** `NOT RUN` | لا بيئة معزولة مصرّح بها، ولا تفويض لتنفيذ تثبيت أو استعادة.

## 1. الشروط المسبقة

- بيئة معزولة بموافقة المالك: قاعدة بيانات وobject store منفصلان تمامًا عن الإنتاج، بلا بيانات عملاء.
- checkout على SHA مثبّت والتحقق من `SHA256SUMS.txt` داخل بيئة التثبيت.
- أسرار تجريبية منفصلة، بلا أسرار إنتاج، وبلا مسارات JWKS أو Groq حقيقية.
- مراجع مستقل لتسجيل النتيجة، ورقم تغيير/حادث معتمد.

## 2. خطوات التثبيت (لم تُنفّذ)

1. `npm ci` → `npm run build` → `npm start` مع `AIGAS_APP_ENABLED=false`.
2. `GET /healthz/` و`GET /readyz/` مع تعطيل فحص JWKS البعيد في البيئة المعزولة.
3. توثيق نتيجة كل خطوة برقم التغيير وSHA ومعرّف Deploy.

## 3. خطوات الاستعادة (لم تُنفّذ)

1. جرد هوية المصدر والهدف والتجزئات وفق `docs/NEON-BRANCH-PROTECTION-RUNBOOK.md`.
2. استعادة الأرشيف في قاعدة هدف فارغة معزولة فقط؛ لا ترحيل تلقائي ولا تحويل إلى إنتاج.
3. التحقق من سلامة البيانات والوثائق والسجلات، وتسجيل نتيجة مستقلة منفصلة عن تجزئة الأرشيف.
4. إثبات عدم تغيير المصدر، ومسح الأسرار من الأدلة، وإبطال بيانات الاعتماد المؤقتة.

## 4. فحص عدم التسريب

- لا بيانات مستأجرين أو عملاء في البيئة أو الأدلة.
- مراقبة egress لإثبات عدم اتصال بـJWKS أو Groq أو أي مزود خارجي.
- فحص السجلات والأدلة بحثًا عن مفاتيح أو كلمات مرور أو روابط خاصة.
