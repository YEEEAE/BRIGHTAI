## أساس بناء هذه الحزمة
هذه برومبتات لتطوير النظام التشغيلي الحالي بعد مراجعة مباشرة لملفات GitHub وقاعدة Neon. تُشغّل بالتسلسل 01 إلى 06، مع بقاء التعديلات محلية دون كتابة إلى GitHub/Neon. تحقق أولًا من أن ملفات docs موجودة محليًا وأن الـAgent يملك مشروع Neon الصحيح. لا تتجاهل الحاجة لموافقة قبل أي migration أو تعديل بيانات فعلية.

### خلاصة الحالة المثبتة
- قاعدة Neon: أربع جداول AIGAS مشتركة فقط (فارغة وقت القراءة) مع Neon Auth، ولا توجد جداول المنتجات الأربعة.
- migrations 0002–0005 موجودة في GitHub ومعلّمة REVIEW ONLY.
- Secure Chat لا يملك نموذجًا معتمدًا؛ `NO_APPROVED_MODEL` حالة مقصودة.
- الموقع العام والبوابة المحمية ليسا دليلًا على اكتمال التشغيل بمجرد ظهور الصفحات.

## ترتيب التنفيذ
1. Kernel: استقرار الجلسات والمؤسسات واللوحة
2. Firewall: قواعد/قرارات DB ومسار تقييم محدود
3. Ledger: أحداث قابلة للتصدير وفحص سلامتها
4. Human Gate: الطلبات والفصل بين المراجع وصاحب الطلب
5. Risk Engine: سجل الأصول والتقييمات الأولية
6. Secure Chat: تدفق محادثة حقيقي مشروط بمزود معتمد

### حد المرحلة
هذه ليست خطة Go-Live أو أمن سيبراني شامل أو تدقيق قانوني. تعالج الاستخدام الأساسي، تكاملات DB في بيئة مصرح بها، وحالات UX، وتترك المتقدم للمرحلة النهائية.

### الفحص البصري
- تم تفقد الصفحة الرئيسية والمنتجات وKernel المنشورة، وكلها 200.
- `/app/` والستة `/app/*/` أعادت HTTP 404، فلا تعتبر وظائف النظام متاحة للجمهور.
- شخّص فروقات البناء والاستضافة والتوجيه محليًا، مع بقاء النشر محظورًا.
