## تعليمات تنفيذ مشتركة — إلزامية

أنت Codex تعمل على النسخة المحلية من `YEEEAE/BRIGHTAI`. **المطلوب كود تشغيلي للوحة `/app/`، وليس صفحة تعريفية أو محاكاة UI.** هذه مرحلة **قبل نهائية** وليست إطلاقًا نهائيًا؛ أكمل المتاح فقط ضمن نطاق البرومبت. اقرأ أولًا `AGENTS.md` و`.agents/mind/01-mind-latest.md` والوثائق المركزية وملفات المنتج الستة ضمن `docs/products/firewall/` إن وجدت. اعمل وفق أحدث قرارات المالك. استكشف Skills وMCP المناسبة المتاحة فعلًا، خصوصًا Neon MCP، واستخدمها للفحص وتحديد الفرع والجداول، ولا تدّع استخدام أداة غير متصلة.

**ممنوع:** تعديل GitHub البعيد أو `commit/push/PR` أو نشر إنتاج أو تغيير الخدمة الحية؛ العبث بصفحة الرئيسية/Hero/Constellation/الهيدر والمكوّنات المحمية أو محو عمل قائم؛ تسريب متغيرات `.env` أو المفاتيح في المتصفح أو logs أو تقارير التنفيذ؛ اختلاق جاهزية أو قيم قياسية/امتثال؛ استبدال Auth أو قاعدة البيانات القائمة من الصفر. استعمل متغيرات البيئة الموجودة محليًا بدون عرض قيمها، وانشئ `.env.example` بأسماء المتغيرات فقط إذا لزم. كل تغييرات الكود محلية فقط.

**Neon:** المشروع المستهدف `young-frog-60183055`، وقاعدة `neondb`. **مهم: اتضح أن قاعدة Neon الحالية فيها فقط أربع جداول تشغيلية مشتركة:** `aigas_tenants`, `aigas_memberships`, `aigas_product_access`, `aigas_audit_events`، إلى جانب `neon_auth.*`. كلها بلا سجلات تشغيلية عند الفحص. توجد migrations `0002`–`0005` في GitHub لكنها غير مطبقة في قاعدة البيانات المفحوصة. فرع Neon الحالي افتراضي، غير محمي، فلا تُجرِ تعديل SQL عليه من تلقاء نفسك. افحص المخطط عبر Neon MCP read-only؛ جهّز/صحّح migrations ككود محلي، واعرض خطة تطبيق وحالة BLOCKED إذا احتاج التطبيق على Neon موافقة صريحة وفرع تطوير معتمد. لا تستخدم بيانات عملاء حقيقية في التجارب. لا تزرع مؤسسات أو مستخدمين داخل الإنتاج، ولا تعرض أسرارًا.


**نتيجة الفحص البصري المنشور (01-11-2026):** `https://brightai.live/` و`/products/` و`/kernel/` تعمل (200)، لكن `/app/` وكل المسارات الست `/app/{...}/` أعادت 404 على الدومين الحالي رغم وجودها في المستودع. **قبل الادعاء بأن لوحة النظام منشورة، شخّص محليًا إعداد Astro adapter/server vs prerender وملفات الاستضافة والـrouting والـdeploy artifact وترابط الـdomain؛ جهز التوصية والإصلاح المحلي الآمن عند الحاجة. لا تنشر ولا تغير إعداد الخدمة الخارجية بنفسك.** هذا فحص لنسخة الموقع الحي، وليس اختبارًا لجلسة مصادقة أو استخدام فعلي.

**تصميم النظام:** حافظ على RTL والهوية الرسمية (أسود، أبيض، بنفسجي، كهرماني)، أعِد استعمال `AppLayout` والمكوّنات الموجودة؛ لا تنشئ موقعًا ثانيًا أو توسّع الاعتماديات دون داع. كل تفاعل حقيقي يبدأ من عميل ويصل إلى API خادم يحقق الهوية وعضوية المؤسسة والصلاحية ويُعيد نجاحًا/خطأً حقيقيًا. أظهر حالات loading/empty/error/unauthorized/disabled، مع تصميم متجاوب ووصول لوحة مفاتيح. فصل مؤسسة عن أخرى مطلوب server-side. لا ترخّص منتجًا آخر كشرط لاستخدام الوظيفة الأساسية. لا تخدع المستخدم بـmock أو “تم الحفظ” قبل نجاح الحفظ.

**إيقاع التنفيذ:** افحص ثم أصلح ثم تحقق بشكل مركز بدون تصوير شاشة كثير أو سلسلة اختبارات غير لازمة. حافظ على التعديلات الصغيرة القابلة للمراجعة، ولا تُؤجل كل المهمة لمجرد وجود ميزة متقدمة غير مطلوبة. إذا وجدت عائقًا خارجيًا، أكمل الكود المحلي المحيط وقدّم blocker محددًا. في النهاية أعط تقريرًا موجزًا: ملفات الكود المعدّلة محليًا، المسارات العاملة، أي endpoint ما يزال غير متصل، حالة migrations، ما تحققت منه وكيف، والمعلق لما قبل الإنتاج. لا تزعم نجاحًا لم تتحقق منه.


## نتائج التدقيق التي يجب الانطلاق منها
- موجود: `/app/firewall/`, `/app/api/firewall/rules`, `/app/api/firewall/evaluate`, خدمات `src/server/firewall/`, و`migrations/0002_aigas_firewall.sql`.
- لا تظهر جدولا `aigas_fw_rules` و`aigas_fw_decisions` في قاعدة Neon التي فُحصت؛ لذلك الحفظ والفحص المعتمد عليهما غير مثبتين على قاعدة البيانات الحالية.
- النسخة الحالية تؤسس 3 قرارات مبسطة ALLOW/BLOCK/REDACT عبر قواعد نصية، وليست Proxy عامًّا لنماذج AI.

## التنفيذ المحدد — 4 وحدات
1. **جاهزية الجداول والتكامل:** افحص migration 0002 مع Kernel، الصلاحيات وقيود uniqueness وRLS. جهّز طريقة تطبيق آمنة على فرع تطوير معتمد، ولا تُشغّلها على الفرع القائم دون إذن. تأكد من معالجة كود API لغياب الجداول برمز واضح لا 500 مبهم.
2. **سياسات قابلة للإدارة:** حسّن واجهة القائمة/إضافة/تعديل/تفعيل قواعد بسيطة بحسب صلاحية المؤسسة، مع validation server-side، ترتيب/أولوية واضحة إن كانت مدعومة، وحفظ حقيقي وربط الإصدار. لا تجعل المستخدم يكتب RegExp خطير أو يختبر ببيانات حقيقية افتراضيًا.
3. **مختبر فحص فعلي محدود:** أرسل نصًا اصطناعيًا من الواجهة إلى `/app/api/firewall/evaluate`؛ اعرض ALLOW/BLOCK/REDACT وسبب القرار واسم القاعدة والنسخة، ولا تعرض نصوصًا محرمة أو تحفظ النصوص افتراضيًا. وضّح إنفاذ القواعد **داخل هذا المسار فقط** وليس على جميع تطبيقات العميل. لا تقل “تم حظر طلب لدى المزود” إن كان الفحص منفصلًا عن المرور الحقيقي.
4. **سجل القرارات والتعامل مع الأعطال:** لوحة آخر قرارات مبسطة من القاعدة حسب المؤسسة مع بحث/تصفية خفيفة؛ عالج حالة لا توجد قواعد/قاعدة غير جاهزة/صلاحية مفقودة. فشل سياسة إلزامية يجب أن يغلق بأمان في المسار المعني بدل سماح صامت.

## معيار الإنجاز
- بعد توفير بيئة قاعدة معتمدة، قواعد حقيقية محفوظة وقرارات من الخادم مرتبطة بالعضوية وتظهر في السجل. لا تقرر أن المنتج Enterprise Firewall جاهز؛ Proxy شامل وفحص أدوات ونماذج وتكاملات DLP المتقدمة مؤجلة.
