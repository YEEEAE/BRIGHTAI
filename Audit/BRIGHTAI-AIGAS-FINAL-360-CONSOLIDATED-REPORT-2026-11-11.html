Firewall

يوجد فرق بين تقييم داخلي LAB يطبقه الخادم ضمن قيود بيانات اصطناعية، وبين تنفيذ خارجي متصل بمزود. المصدر يدعم منطق التقييم وقواعد القرار والحفظ، لكن مزودي Firewall غير معتمدين وقائمة المراجعة البشرية للتصعيد غير مهيأة. يجب أن يعرض UI القرار ونطاقه ومرجع السياسة دون الادعاء بإرسال خارجي لم يحدث.

Ledger

المصدر يدعم إنشاء Event، التسلسل والبصمات والتصدير وفحص السلسلة. مستوى الضمان الظاهر INTEGRITY_ONLY_NO_SIGNATURE؛ أي سلامة سلسلة بلا ادعاء توقيع رقمي. لا يمكن عرض VERIFIED إلا بعد تحقق ناجح بالفعل.

Human Gate

توجد آليات لسياسات الموافقات وفصل المهام والتفويضات ومنع إعادة تنفيذ طلب مكتمل. لكن لا توجد دورة حية مثبتة بطالب ومراجع مستقل، وربط التصعيد التلقائي من Firewall غير مهيأ.

Risk Engine

المصدر يدعم الأصول، التقييمات، النسخ والإجراءات والعلاج وقبول المخاطر. deployment_authorized:false يُظهر فصلًا صحيحًا بين قبول الخطر وإذن النشر. لم يثبت سجل حي متكامل للأصل والتقييم والعلاج.

Secure Chat

القائمة APPROVED_MODELS فارغة وsendable=false، وتعيد requireChatPolicyIntegration() خطأ CHAT_POLICY_INTEGRATION_REQUIRED. لذلك هذه ليست مجرد Feature Flag يحتاج تشغيلًا؛ هي وظيفة غير مهيأة للمزود والسياسة والحصص بعد.

16. ثمانية برومبتات تنفيذية ختامية

ضابط جميع البرومبتات: احمِ Hero الرئيسية حرفيًا؛ لا تغيّر GitHub عن بُعد أو Neon أو Render أو DNS؛ لا Deploy ولا Push ولا Merge؛ لا تغير أسرار الإنتاج أو بيانات العملاء. عند عدم توفر صلاحية العمل المحلي المصرح بها، قدّم Patch مقترحًا وخطة أدلة فقط.

البرومبتات أدناه مأخوذة من التقرير الثالث، ومقسّمة حسب العلة لمنع التكرار. يمكن فتح كل برومبت ونسخه للاستخدام لاحقًا داخل وكيل التطوير، وليس هذا إذنًا للتنفيذ في المستودع.

PROMPT 01 Legacy Solutions Experience

افحص سبب وجود /solutions/ بتصميم وهوية مختلفة، رغم عدم وجود مسار مطابق له في شيفرة Astro الحالية. تتبّع أصل المحتوى وإعدادات التوجيه والنشر قراءة فقط. حدد سبب التباين، والمحتوى الذي يجب الحفاظ عليه، والروابط الداخلية والخارجية المتأثرة. اقترح أصغر حل لتوحيد الهوية وبنية التنقل، أو إعادة التوجيه بعد الموافقة. لا تحذف صفحة أو تنقل محتوى قبل إثبات ملكيته وتأثيره على SEO. المخرج: Root Cause + Route Matrix + Local Remediation Plan + Acceptance Criteria.

PROMPT 02 Public-to-Product Journey

راجع رحلة المستخدم من الصفحة العامة إلى المنتج ثم التجربة، مع فصل الشرح التعليمي عن العمليات الحقيقية. صمّم رحلة واضحة لكل منتج نحو تسجيل الدخول والتجربة المصرح بها. لا تعالج غياب /app/* بتزييف نتائج الواجهة أو تعطيل ضوابط الأمان. اربط المتطلبات بواقع Astro SSR وRender وNeon، وافصل تحسين UX عن قرار تفعيل الخدمة. المخرج: Journey Maps للمنتجات الخمسة + حالات الوصول والفشل + خطة تنفيذ معزولة.

PROMPT 03 Five Distinct Product Experiences

طوّر مقترحات تصميمية مختلفة لكل من Firewall وLedger وHuman Gate وRisk Engine وSecure Chat. استخرج وظائفها وحالاتها من الشيفرة الحقيقية. لكل منتج اختر تصور بيانات وتفاعل يناسبه؛ لا تكرر قالب بطاقات واحدًا. استخدم مخططات SVG ومكونات Astro خفيفة. لا تعرض محاكاة على أنها عملية خادم. المخرج: Screen Architecture + Component Map + Data Binding Contract + Mobile Layout + Evidence Checklist.

PROMPT 04 Mobile Navigation & Responsive Repair

حلّل تداخل قائمة «داخل الصفحة» مع المحتوى على 390px. راجع سلوكها مع Footer والأزرار والنماذج والتكبير ولوحة المفاتيح. قدّم حلًا يحافظ على فائدتها دون حجب المحتوى. افحص أيضًا أشرطة تنقل Kernel والمنتجات الداخلية على 320 و390 و768 و1024 و1440 و1728px، وميّز بين النتائج المقاسة والمخاطر المشتقة من CSS. المخرج: Collision Register + Responsive Specifications + Proposed Scoped CSS + Verification Plan.

PROMPT 05 Accessibility, States & Contrast

راجع حالات Default وHover وFocus وActive وDisabled وLoading وError لجميع عناصر التحكم خارج Hero المحمي. عالج تباين Hover للزر البنفسجي، وافحص إعلان حالة الاختيار في الأمثلة التفاعلية، والتنقل بلوحة المفاتيح، وحالات Dialog وDisclosure. لا تغيّر Hero أو قواعده المشتركة دون إذن مستقل؛ سجل أي تعارض مع WCAG كاستثناء مفتوح. المخرج: WCAG Findings + Exact Selectors + Scoped Fix Plan + Evidence Per State.

PROMPT 06 Kernel Enterprise UX

راجع واجهات Kernel وإدارة المؤسسات والأعضاء والسياسات والمنتجات وحالات المصادقة والرفض والتجربة والمشغل. اقترح Command Center موجّهًا للمهمة: سياق المؤسسة، الصلاحية، حالة المنتج، القرار التالي، والأدلة. استخدم بيانات الخادم فقط. لا تخترع حالة اتصال أو صلاحية أو تحقق. حافظ على Auth وRLS وعزل المستأجرين. المخرج: Task Flows + Navigation Hierarchy + Role-based Screen States + Read-only Component Plan.

PROMPT 07 Knowledge Center & Arabic Editorial UX

راجع مركز المعرفة ومقالاته الـ32 وأصول البحث الحالية ونماذج MagicPath السابقة بوصفها مراجع، وليس كودًا جاهزًا للنقل. حسّن التصفح والقراءة والفلاتر ومعاينة المقالات، مع الحفاظ على عناوين URL والبحث والإتاحة الحالية. تعامل مع النص العربي وBidi والجداول والمراجع الطويلة بعناية. لا تغيّر ادعاءً تنظيميًا أو قانونيًا دون مراجعة المحتوى. المخرج: Information Architecture + Reading Patterns + Source-preserving Implementation Plan.

PROMPT 08 Independent Design Acceptance

بعد وجود نسخة محلية مصرح بها، نفّذ تدقيقًا مستقلاً قبل/بعد على كل Route وحالة واجهة ضمن النطاق. تحقق عند 320 و390 و768 و1024 و1440 و1728px، بما يشمل RTL وKeyboard وWCAG AA وMotion وJavaScript disabled وLCP وCLS وINP. افصل فشل النشر عن فشل التصميم. أثبت أن Hero المحمي مطابق للمرجع البصري والسلوكي وأن الوظائف الأمنية لم تتغير. المخرج: Coverage Register + Before/After Evidence + Defect Severity + Measured Performance + GO/NO-GO Decision.
