# CODEX EXECUTION PROMPT 02 — AIGAS Firewall — صفحة الحماية والقرارات الخمسة

**المهمة:** طوّر `/products/firewall/` لتصبح تجربة منتج مؤسسية قوية، فريدة بصريًا، تقنع العميل بفهم دور Firewall وحدوده من خلال مختبر تعليمي لقرارات السماح والتحذير والتنقيح والمراجعة والحظر، دون الادعاء بوجود محرك متصل.
**النسخة:** صفحة عامة موجودة في مستودع `YEEEAE/BRIGHTAI` — نفّذ في نسخة العمل المحلية.
**المنع:** لا تعديل للمستودع البعيد أو نشر الموقع.

## قواعد تنفيذ إلزامية — اقرأها قبل تعديل أي ملف

1. اقرأ `AGENTS.md` و`.agents/mind/01-mind-latest.md` والتعليمات المحلية المنطبقة كاملًا، ثم راجع `docs/MASTER-PROJECT-BLUEPRINT.md` و`docs/MASTER-AGENT-CONTEXT.md` و`docs/PRODUCT-MASTER-CATALOG.yaml` و`docs/BRAND-AND-DESIGN-SYSTEM.md` و`docs/WEBSITE-PAGE-REGISTRY.yaml` إذا وُجدت؛ راجع `docs/PLATFORM-ARCHITECTURE.md` وسياسات الخصوصية والتجارب عند ملاءمتها. أحدث توجيه للمالك مقدّم عند التعارض، دون تجاوز تعليمات النظام.
2. اكتشف Skills وMCP وConnectors والإضافات المتاحة فعليًا واستخدم الأنسب للمهمة (مثل browser/Chrome DevTools/Playwright، أدوات تصميم إن كانت متصلة، وGitHub للقراءة فقط). لا تتطلب أو تدّعي أداة غير متاحة، ولا تثبّت مكتبات/خدمات مدفوعة لمجرد تحسين الشكل. استخدم ما يلزم فقط.
3. افحص `git status` والكود الحالي ومكوّنات Astro المشتركة قبل التعديل. احفظ عمل المستخدم القائم وامتثل إلى صلاحيات Codex المحلية. **لا commit، لا push، لا PR، لا merge، لا تعديل عبر GitHub API، لا نشر، لا تغيير لبيئة إنتاجية.** العمل على ملفات النسخة المحلية فقط.
4. **ممنوع تغيير الصفحة الرئيسية `/` أو هيروها أو Constellation أو Header أو Footer أو BaseLayout أو CSS العام إذا نتج عنه تغيير الرئيسية؛** افصل التنسيق والحركة في مكونات/ملفات scoped تخص الصفحات المطلوبة. لا تعِد بناء النظام البصري من الصفر، ولا تمسح نصوصًا أو أقسامًا سابقة دون سبب موثق وتعليمات صريحة.
5. الهوية: عربية سعودية RTL، خلفية سوداء `#000000`، نص أبيض، بنفسجي `#8052FF`، زعفراني `#FFB829`، أخضر `#15846E` في موضعه، وخط الموقع الحالي وشعاره من `src/data/brand.ts`. لا تستخدم شعارات مزيفة أو صور عملاء أو شهادات أو أسعارًا أو مدد احتفاظ مخترعة.
6. **النطاق صفحات وتجارب أمامية Frontend، لا تنفيذ Backend أو APIs تشغيلية.** أي رسوم/قرارات/أحداث داخل الصفحة تكون تعليمية ببيانات اصطناعية، وعليها وسم ظاهر «توضيحي — لا يتصل بخدمة فعلية». لا ترسل مدخلات المستخدم لنموذج أو إلى خادم. لا تعرض نجاح إجراء فعلي أو تخزين سجل أو موافقة أمنية دون تنفيذ مثبت.
7. حافظ على SSR/HTML الأولي وSEO والمحتوى دون JavaScript، والتنقل بلوحة المفاتيح، والتباين، و`prefers-reduced-motion`. لا انزلاق أفقي على 360/768/1440، ولا مؤثرات ثقيلة أو timers دائمة، ولا مكتبات حركات جديدة إلا بعد تفويض. أخفِ الحركة في وضع تقليل الحركة واترك المعلومات نفسها ظاهرة.
8. أي زر أو قائمة/فلتر يجب أن يؤدي وظيفته فعلًا داخل الواجهة. إذا كانت الوظيفة التشغيلية غير متاحة، استخدم روابط طلب المعلومات أو عنصرًا غير مفعّل مع سبب واضح؛ لا تصنع زرًا يوهم أنه ينفذ حماية أو اعتمادًا أو يحجز تجربة.
9. أنشئ تقريرًا نهائيًا بالعربية يلخص الملفات المحلية المعدلة، الأقسام المنفذة، الروابط، الأدوات المستخدمة فعليًا، ما تم التحقق منه، الموانع، والفجوات. لا تسمِّ `BUILD PASS` «جاهزية منتج». ابدأ بالتنفيذ بعد مراجعة السياق ولا تتوقف عند خطة أو Mockup.

## هوية التجربة البصرية

- ألوان القرارات الدلالية مقترحة، ويجب فحص تباينها وتجنب الاعتماد على اللون وحده.

## بنية الصفحة التفصيلية — نفّذ الأقسام جميعًا

1. Hero «كل طلب يمر بسياسة، قبل أن يمر إلى النموذج» مع وصف نطاق نقاط التكامل، وشارة «منتج مخطط — التشغيل غير مثبت».
2. سيناريو المشكلة: بيانات حساسة، Prompt Injection، استدعاءات أدوات، وتوجيه لمزوّد خارجي؛ ليس جدار شبكة شاملًا.
3. **مختبر القرارات الخمسة:** مخطط `DecisionCircuit` بمسار SVG نشط، وخمس بطاقات تفاعلية: السماح، التحذير، التنقيح، انتظار مراجعة بشرية، الحظر. لكل حالة مثال اصطناعي، سبب القرار، ما يجري *افتراضيًا* وما لا يحدث حاليًا.
4. **قبل/بعد:** مشهد عربي لطلب يحتوي معرفًا اصطناعيًا يتغير إلى `[بيانات منقحة]` عند اختيار حالة التنقيح؛ لا تقبل بيانات شخصية حقيقية.
5. دورة حماية الطلب: الهوية → سياسة الجهة → فحص المدخلات → إجراء → مراجعة المخرجات → حدث تدقيق أساسي؛ ملاحظة أن الكشف غير مضمون بالكامل.
6. حدود الحماية: لا تغطية لطلبات لا تمر عبر نقطة تكامل مفوضة، ولا تجاوز لقيد حظر إلزامي حتى مع مراجعة بشرية.
7. تكاملات API / SDK / Proxy كخيارات **مستهدفة فقط**، دون إعلان مسارات أو تكامل منشور؛ مخطط بيئات SaaS / On-Premise / Air-Gapped.
8. الفشل الآمن: ثلاث حالات توضيحية للمزوّد غير المصرح، لتعذر السياسة، ولانقطاع مسار تدقيق إلزامي.
9. التكاملات الاختيارية مع Human Gate وRisk Engine وLedger مع عدم فرض شراء إضافي للوظيفة الأساسية.
10. رحلة 48 ساعة *المخططة* ومتى يناسبها Pilot، دون زر تفعيل غير موجود.
11. قائمة تحقق شراء، FAQ، CTA صادق للاستفسار، وروابط Ledger وHuman Gate والخصوصية.

## سلوك التفاعلات والتفاصيل الهندسية

- حافظ على الشرح السابق والأمثلة، وحسّنها تدريجيًا بدل استبدالها بديكور. يجب أن تعمل جميع أزرار قرارات المثال وتحدّث `aria-pressed` والنص والرسمة بتناغم.
- يظهر المحتوى والحالات الخمس دون JavaScript كقائمة نصية؛ في reduced-motion تغيّر الحالة فوريًا بلا حركة.
- إن كان عقد API يتضمن المسارات المقترحة، لا تستدعها من المتصفح. **قرار توضيحي != enforcement**؛ وضّح ذلك في نفس نطاق المختبر.

## حدود الحقيقة والمنتج والتكامل

- الوظائف التشغيلية `FW-01..FW-08` لم يثبت تشغيلها؛ لا تعرض badge «نشط» أو logging حقيقي أو نسبة كشف أو شهادة.
- لا تعتمد تشغيل Firewall الأساسي على شراء Risk Engine أو Human Gate أو Ledger؛ التسجيل الأدنى من Kernel.
- لا تُفعّل زر «احمِ الآن» أو تجربة نشطة ما لم توجد خدمة مثبتة وموافقة من المالك.
