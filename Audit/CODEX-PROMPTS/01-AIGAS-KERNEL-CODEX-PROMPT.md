# CODEX EXECUTION PROMPT 01 — AIGAS Kernel — صفحة المنظومة والمنتجات

**المهمة:** حوّل `/kernel/` من صفحة حجب توضيحية قصيرة إلى صفحة تعريفية مؤسسية غنية، تمثّل Kernel بوصفها النواة الأساسية المشتركة لمنتجات AIGAS الخمسة، وبطاقات تنقل واضحة لكل منتج، مع إبقاء المحاكاة التعليمية القائمة وعدم تحويلها إلى خدمة وهمية.
**النسخة:** صفحة عامة موجودة في مستودع `YEEEAE/BRIGHTAI` — نفّذ في نسخة العمل المحلية.
**المنع:** لا تعديل للمستودع البعيد أو نشر الموقع.

## قواعد تنفيذ إلزامية — اقرأها قبل تعديل أي ملف

1. اقرأ `AGENTS.md` و`.agents/mind/01-mind-latest.md` والتعليمات المحلية المنطبقة كاملًا، ثم راجع `docs/MASTER-PROJECT-BLUEPRINT.md` و`docs/MASTER-AGENT-CONTEXT.md` و`docs/PRODUCT-MASTER-CATALOG.yaml` و`docs/BRAND-AND-DESIGN-SYSTEM.md` و`docs/WEBSITE-PAGE-REGISTRY.yaml` إذا وُجدت؛ راجع `docs/PLATFORM-ARCHITECTURE.md` وسياسات الخصوصية والتجارب عند ملاءمتها. أحدث توجيه للمالك مقدّم عند التعارض، دون تجاوز تعليمات النظام.
2. اكتشف Skills وMCP وConnectors والإضافات المتاحة فعليًا واستخدم الأنسب للمهمة (مثل browser/Chrome DevTools/Playwright، أدوات تصميم إن كانت متصلة، وGitHub للقراءة فقط). لا تتطلب أو تدّعي أداة غير متاحة، ولا تثبّت مكتبات/خدمات مدفوعة لمجرد تحسين الشكل. استخدم ما يلزم فقط.
3. افحص `git status` والكود الحالي ومكوّنات Astro المشتركة قبل التعديل. احفظ عمل المستخدم القائم وامتثل إلى صلاحيات Codex المحلية. **لا commit، لا push، لا PR، لا merge، لا تعديل عبر GitHub API، لا نشر، لا تغيير لبيئة إنتاجية.** العمل على ملفات النسخة المحلية فقط.
4. **ممنوع تغيير الصفحة الرئيسية `/` أو هيروها أو Constellation أو Header أو Footer أو BaseLayout أو CSS العام إذا نتج عنه تغيير الرئيسية؛** افصل التنسيق والحركة في مكونات/ملفات scoped تخص الصفحات المطلوبة. لا تعِد بناء النظام البصري من الصفر، ولا تمسح نصوصًا أو أقسامًا سابقة دون سبب موثق وتعليمات صريحة.
5. الهوية: عربية سعودية RTL، خلفية سوداء `#000000`، نص أبيض، بنفسجي `#8052FF`، زعفراني `#FFB829`، أخضر `#15846E` في موضعه، وخط الموقع الحالي وشعاره من `src/data/brand.ts`. لا تستخدم شعارات مزيفة أو صور عملاء أو شهادات أو أسعارًا أو مدد احتفاظ مخترعة.
6. **النطاق صفحات وتجارب أمامية Frontend، لا تنفيذ Backend أو APIs تشغيلية.** أي رسوم/قرارات/أحداث داخل الصفحة تكون تعليمية ببيانات اصطناعية، وعليها وسم ظاهر «توضيحي — لا يتصل بخدمة فعلية». لا ترسل مدخلات المستخدم لنموذج أو إلى خادم. لا تعرض نجاح إجراء فعلي أو تخزين سجل أو موافقة أمنية دون تنفيذ مثبت.
7. حافظ على SSR/HTML الأولي وSEO والمحتوى دون JavaScript، والتنقل بلوحة المفاتيح، والتباين، و`prefers-reduced-motion`. لا انزلاق أفقي على 360/768/1440، ولا مؤثرات ثقيلة أو timers دائمة، ولا مكتبات حركات جديدة إلا بعد تفويض. أخفِ الحركة في وضع تقليل الحركة واترك المعلومات نفسها ظاهرة.
8. أي زر أو قائمة/فلتر يجب أن يؤدي وظيفته فعلًا داخل الواجهة. إذا كانت الوظيفة التشغيلية غير متاحة، استخدم روابط طلب المعلومات أو عنصرًا غير مفعّل مع سبب واضح؛ لا تصنع زرًا يوهم أنه ينفذ حماية أو اعتمادًا أو يحجز تجربة.
9. أنشئ تقريرًا نهائيًا بالعربية يلخص الملفات المحلية المعدلة، الأقسام المنفذة، الروابط، الأدوات المستخدمة فعليًا، ما تم التحقق منه، الموانع، والفجوات. لا تسمِّ `BUILD PASS` «جاهزية منتج». ابدأ بالتنفيذ بعد مراجعة السياق ولا تتوقف عند خطة أو Mockup.

## هوية التجربة البصرية

- تصميم editorial enterprise / systems engineering: Hero قوي، شبكة عقد SVG أصلية، خطوط دقيقة وإضاءات هادئة، لا كتل بطاقات متشابهة مملة.
- اعرض Kernel بوضوح كـ «الأساس المشترك وليس المنتج السادس»، وتميّز بين هوية المؤسسة وقرارات السياسة والتراخيص والسجل الأدنى.
- تعمّد تنوع شكل بطاقات المنتجات الخمسة وأيقوناتها وشارات موجة التنفيذ من دون أن تصبح الشارات إعلان إتاحة تشغيلية.

## بنية الصفحة التفصيلية — نفّذ الأقسام جميعًا

1. **Hero:** عنوان مقترح «حوكمة مشتركة. ومنتجات تشتغل باستقلالية.» مع وصف دقيق أن Kernel إطار مستهدف للهوية والسياسات والحماية والتراخيص والتدقيق الأساسي. CTA «تعرّف على المنتجات» إلى `#products` والثاني «استفسر عن المنظومة» إلى `/contact/`.
2. **سياق المشكلة:** كيف تنشأ فجوات الحوكمة عندما تتفرق السياسات بين تطبيقات AI؛ ثلاث نقاط صريحة عن الهوية، السياق، قابلية المساءلة.
3. **معمارية Kernel:** رسم تفاعلي accessible يشرح: `Tenant / Identity → Policy & Authorization → Safety / Quotas → Decision & Basic Audit → Approved Provider / Local Model`، مع إبراز أن المنتجات تتصل بعقود واضحة لا بترخيص مجبَر.
4. **سبع ركائز وظيفية:** الهوية والعزل، السياسة الهرمية، الأسرار والمفاتيح، التراخيص والحصص، التدقيق الأساسي، الحماية الأساسية، صحة الخدمة/العمل المعزول. كل ركيزة: القيمة، حدودها، مثال افتراضي، وما يحتاج إثباتًا.
5. **قسم المنتجات الخمسة `#products`:** خمس بطاقات معمّقة لـFirewall، Ledger، Human Gate (الموجة الأولى)، Risk Engine وSecure Chat (الموجة الثانية). لكل بطاقة الاسم، الدور، مشكلة تحلها، 2–3 قدرات، حالة موثوقة «مخطط/غير مثبت تشغيليًا»، وصلة حقيقية لصفحة المنتج. لا تسقط أي منتج أو تكرر محتواه في صفحة Kernel.
6. **كيف تتكامل؟** سيناريو سردي واحد ببيانات اصطناعية: طلب AI يمر عبر الضوابط المشتركة؛ Firewall يحكم المرور، Human Gate يراجع عند الحاجة، Ledger يضيف أدلة متقدمة، Risk Engine يحلل السياق، وSecure Chat يقدّم واجهة محادثة. وضّح أن التكاملات اختيارية وأن Kernel يوفر وظائف أساسية حتى بدون ترخيص المنتجات الأخرى.
7. **التجربة التعليمية الموجودة:** احتفظ بمثال الحجب الحالي و`KernelSequence`، وسهّل الإعادة/تخطي الحركة، مع إيضاح أنه لا يتصل بخدمة فعلية.
8. **طرق التشغيل:** SaaS سعودي افتراضيًا كمطلب مستهدف، On-Premise، Air-Gapped؛ ثلاث بطاقات مقارنة لا تدّعي أنها منشورة أو معتمدة.
9. **حماية البيانات والحوكمة:** أقل بيانات، No-Training، مراجعة مناطق المعالجة، مفاتيح وهوية؛ كلها سياسات مستهدفة تحتاج أدلة.
10. **48 ساعة ومستقبل الإطلاق:** شرح Proof of Value المخطط دون زر «ابدأ التجربة» إذا غير مفعل؛ CTA إلى الاستفسار مع بيان أن التجربة غير مفعّلة.
11. **FAQ + CTA ختامي:** أسئلة صعبة عن استقلال المنتجات، وجود Kernel ضمن الترخيص، فرق Ledger عن Audit الأساسي، وكفاءة Air-Gapped؛ روابط داخلية لصفحات المنتجات والثقة والخصوصية.

## سلوك التفاعلات والتفاصيل الهندسية

- أنشئ واجهة تنقل قابلة للاستخدام من لوحة المفاتيح، وروابط anchors مستقرة، ومخطط SVG بديل وصفي نصّي متاح.
- أعد استخدام `ProductIcon` و`SystemMap` إن كان ذلك لا يفرض تعديلًا على الصفحة الرئيسية أو على باقي الصفحات بشكل غير مقصود. وإلا أنشئ `KernelProductGrid.astro` وCSS scoped مستقل.
- اجعل بطاقات المنتجات responsive 1/2/3 أعمدة بحسب المساحة، دون نقص عرض للمحتوى العربي والإنجليزي.
- ثبّت أن بطاقة كل منتج تقود إلى `/products/{slug}/`، وأن كل CTA يذهب إلى مسار موجود.
- اجعل الصفحة مختلفة بصريًا عن `/products/`؛ Kernel تشرح «البنية المشتركة»، بينما catalog يشرح «اختيار المنتج». لا تكرر الصفحة بحذافيرها.

## حدود الحقيقة والمنتج والتكامل

- لا تعلن Kernel متاحًا أو مستقلًا للبيع؛ لا رسوم ترخيص مستقلة، ووجوده لا يثبت جاهزية أي منتج.

- لا تغيّر GA4/Google Search Console أو إعدادات الخصوصية أو قواعد فهرسة `/kernel/` دون قرار مناسب.
