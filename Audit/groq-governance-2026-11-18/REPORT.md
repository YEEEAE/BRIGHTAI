التدفقات أدناه **مثبتة في المصدر المحلي** إلى حدود الاستدعاء. أحكام الإبقاء والإيقاف **قرارات مقترحة**.

| المنتج أو المسار | التدفق في المصدر | القرار والدليل المطلوب قبل إعادة النظر |
|---|---|---|
| **Secure Chat المؤسسي** | `/app/api/secure-chat/messages` ← مصادقة، عضوية وإتاحة ← إقرار اصطناعي وسجل نموذج للمستأجر ← حماية السياق وحجز كامل لسقف الرموز في PostgreSQL ← Kernel وFirewall على كامل السياق النهائي وتدقيق القرار ← موصل وبوابة Groq ← فحص الرد كاملًا ← تسوية وتدقيق قبل عرضه. | **الإرسال مغلق.** `APPROVED_MODELS` فارغ. عند إعادة التقييم يلزم اعتماد المستأجر، وإثبات حجز الحصة وتدقيقها وتسويتها تحت دور قاعدة البيانات الفعلي والتزامن وتوقف السجل. `WARN` و`ESCALATE` يحجبان خروج النص في Chat حاليًا. المراجعة البشرية يدوية دون استئناف تلقائي. |

| **sandbox العام** | محاكاة متصفح افتراضية. المسار الاختياري `/api/public-demo/groq-sandbox` ← علم تفعيل صريح وفحص المصدر وعنوان الزائر وإقرار اصطناعي ← حد 400 حرف وتنقيح ← 3 طلبات لكل IP ولكل جلسة خلال 10 دقائق + سقف طلبات يومي لكل عملية ← اتصال Groq مباشر باستخدام `GROQ_MODEL` وحد إخراج 250 ← فحص الرد أو إتاحة المحاكاة. | **المحاكاة فقط.** الطلب المباشر يتجاوز سجل الموافقات ودفتر البوابة. السقف يزول بإعادة الإنشاء، وتأكيد الزائر لا يثبت أن محتواه اصطناعي. يلزم قرار مستقل للمسار العام، ومدخلات اصطناعية ثابتة من الخادم، وعدّ مشترك لا يعتمد على ذاكرة العملية، وفصل هوية المشروع عن المؤسسي مع سقف مركزي إن اشتركا في الحساب. |
| **Risk Engine** | `/app/api/risk-engine/assist` ← مصادقة وإتاحة ودور OWNER/ADMIN وإقرار اصطناعي ← غرض منقح وتصنيف ← اختيار نموذج من سجل Chat ← البوابة ← مسودة JSON مدققة ومحدودة، بلا أثر على الدرجة أو القبول. | **الصياغة اليدوية والحساب الحتمي.** قبل أي تقييم مستقل يلزم تصريح غرض للمستأجر منفصل عن Chat، وحدود خاصة، ومراجعة إنسان للمسودة قبل نقلها إلى حقول تقييم. المصدر الحالي يستدعي البوابة داخل callback لمعاملة قاعدة البيانات. يلزم إثبات حدود المهلة والاعتماد والتدقيق دون ربط القبول بالرد. |
| **Firewall** | Kernel والقواعد الحتمية ← سماح/تنقيح/تحذير/تصعيد/منع ← مراجعة Human Gate مرتبطة عند تهيئتها. التنفيذ الخارجي له سجل `approvedProviders` مستقل وفارغ. مساعد شرح Groq يرسل رمز القرار وسببه فقط وله مستدعٍ اختباري في الشجرة المفحوصة. | **القرار الحتمي والتصعيد البشري.** يُرفض الربط التلقائي؛ الشرح المحلي التجريبي لا يغيّر القرار أو يصرّح بالتنفيذ. اعتماد المستأجر ومسار الموافقة الدقيقة والتدقيق وفحص الرد والاستئناف الفعلي أدلة منفصلة. |
| **Human Gate** | طلب مقيّد بالمستأجر والسياسة ← مراجع مستقل ← قرار بشري موثق ← إعادة تحقق من شروط التنفيذ. لا استدعاء Groq مباشر في مصدره المفحوص. | **صفر طلبات ورموز.** تبقى الموافقة بشرية وتربط بالطلب والعملية والإصدار والصلاحية. اختبار الربط المحلي لا يثبت دورة المراجعة في قاعدة مشتركة. |
| **Ledger** | حدث وصفي مقيّد بالمستأجر ← إلحاق وتسلسل وربط تجزئة ← تحقق/تصدير مخوّل. سجل Kernel المستخدم في Chat ودفتر ميزانية Groq وسجل Ledger ثلاثة مخازن مختلفة. | **صفر طلبات ورموز.** لا إدخال من Groq ولا ملء سجل. إثبات متطلبات Ledger الإلزامية يتبع سياسة المنتج، وفحص عطل دفتر الميزانية لا يثبت ذلك المسار. |

## الدليل وحدوده والقرار التالي

**مثبت — اختبار محلي.** 45 نجاحًا، صفر فشل، وحالة تكامل Firewall/Human Gate واحدة متخطاة لغياب قاعدة اختبار معزولة في هذا التشغيل. استخدمنا `env -i` مع حقن مزوّد وهمي وحظر `fetch` الحقيقي واتصالات TCP ومقابس UDP وعمليات lookup في عملية Node. تعذّر فرض `sandbox-exec` داخل البيئة، فأُجري الحظر داخل العملية. اختُبرت السياسات وسجل Kernel ببديل استعلامات، وبوابة Groq بدفتر مؤقت ومزوّد وهمي، وsandbox بدالة `fetcher` محقونة.

## نتائج تنفيذ القرار

**مثبت — مصدر محلي عند `26e7e201` والتغييرات فوقه.** ترفض البوابة دفترًا لا يطابق الحقول الخمسة المعروفة، ومفاتيح الأيام والأشهر غير الصالحة، والقيم السالبة أو غير الرقمية، والمصفوفات. يجري الفحص قبل الحجز وقبل كتابة الحالة بعد تعديلها. الفقد أو فساد البنية أو تعذّر القفل من أسباب إيقاف الطلب. سجل Secure Chat وسجل مزوّدي Firewall فارغان. مسار POST العام يعيد `503 DISABLED` مع `fallback: true` حتى مع علم التفعيل القديم. تجربة النقل السابقة متاحة في الاختبارات بتهيئة ومزوّد محقونين. الواجهة والهيرو وCSS خارج التعديل.
