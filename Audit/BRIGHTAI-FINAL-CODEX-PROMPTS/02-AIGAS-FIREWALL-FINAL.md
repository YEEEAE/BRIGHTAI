**نطاق الصلاحيات:** عدّل الملفات في مساحة عمل Codex المحلية فقط. GitHub للقراءة فقط؛ لا `git add/commit/push` ولا PR ولا تعديل المستودع البعيد. لا تنشر على الموقع ولا تعدّل DNS أو إعدادات الإنتاج بنفسك. لا تلمس الصفحة الرئيسية/Hero/Constellation أو الهيدر المحمي. حافظ على العربية وRTL وهوية BRIGHT AI، واستعمل `AppLayout` والـroutes الموجودة.

**قاعدة البيانات:** Neon project `young-frog-60183055`، قاعدة `neondb`. أحدث فحص موثق أظهر `aigas_tenants` و`aigas_memberships` و`aigas_product_access` و`aigas_audit_events` فقط في `public`، بينما ترحيلات `0002`–`0005` موجودة في الكود وغير مطبّقة. اقرأ المخطط الفعلي مجددًا عبر Neon MCP قبل تقرير المطلوب. نفّذ تعديل المخطط فقط على بيئة تطوير معتمدة ومخصصة، مع migrations مرتبة وقابلة لإعادة الفهم؛ لا تُنشئ بيانات تجريبية ولا تعدّل فرع الإنتاج الافتراضي دون موافقة صريحة. إذا لم تتوفر الصلاحية، جهّز migrations والكود المكمل واذكر عائق التطبيق تحديدًا، ولا تتوقف عن إنجاز بقية المهمة. لا تطبع كلمات المرور أو روابط الاتصال السرية؛ استخدم `.env` المحلي الموجود واحتفظ بالأسرار Server-side فقط.

**إلزامي — التنفيذ فقط:** لا تنشئ/تعدّل ملفات tests ولا تشغّل unit/integration/E2E/Playwright أو `npm test` أو `npm run build` أو lint أو typecheck أو فحص smoke أو screenshots أو تسجيل شاشة أو أداة browser. لا تُنشئ تقارير تدقيق أو قوائم إثبات أو خطة اختبار؛ ركّز على ملفات التطبيق، SQL الضروري، وتجربة المستخدم مباشرة. لا تطوّل في الاستكشاف بعد فهم البنية. في النهاية ردّ مختصر جدًا بملخص ما عدّلته محليًا وبأي عائق خارجي قائم، دون الادعاء أن النظام منشور أو مُتحقَّق منه.

**قواعد الوظائف:** كل حفظ فعلي عبر API مع هوية مستخدم وعضوية مؤسسة وصلاحية خادم. لا تُظهر نجاحًا قبل نتيجة الخادم. اعرض loading / empty / forbidden / unavailable بشكل عربي مفهوم. لا تخترع أسعارًا أو حصصًا أو شروط مزود AI أو امتثالًا معتمدًا، ولا تسمح باستخدام بيانات عميل حقيقية افتراضيًا. لا تجعل شراء منتج آخر شرطًا للوظيفة الأساسية للمنتج. لا ترسل البيانات الحساسة إلى Analytics أو Console أو Logs. حافظ على سياسة عدم تدريب بيانات العميل. استكمل المسارات الموجودة بدل تكرار الـEndpoints أو إنشاء بنية ثانية.


## نقطة الانطلاق المثبتة من الفحص

- الموجود: `src/server/firewall/{core,http,service}.mjs`، و`/app/api/firewall/{rules,evaluate}`، وواجهة `/app/firewall/`، وقواعد حرفية مخصصة أو قوالب محفوظة بأولوية وإصدار، وسجل قرارات metadata-only.
- المحرك الحالي يدعم `ALLOW/BLOCK/REDACT` ويضع `NO_ACTIVE_POLICY` و`INVALID_POLICY` في الحظر؛ لكن `NO_MATCH_LAB_ONLY` يبيّن أن عدم المطابقة ليس حكم سلامة. لا يوجد دليل على Proxy/AI Gateway يمر منه كل طلبات العملاء.
- `migrations/0002_aigas_firewall.sql` عُدّل لدعم أسماء وأولويات وقواعد مخصصة، لكنه غير مطبق على Neon المستهدفة.

## نفّذ الآن — بالترتيب

1. **استكمال مخطط البيانات:** طابق جداول `aigas_fw_rules`, `aigas_fw_decisions` مع الخدمة الحالية، وأصلح migration 0002 والقيود إذا لزم. جهّز التنفيذ على فرع تطوير معتمد، ولا تنفذ على production دون موافقة؛ لا تحوّل تخزين نصوص الفحص إلى سجلات افتراضية.
2. **واجهة إدارة سياسة منتج:** اجعل OWNER/ADMIN ينشئ قاعدة حرفية ويعدلها ويوقفها ويغيّر الأولوية ويستعرض إصدارها، مع منع تعارضات التعديل والسماح لعضو مشاهد بالقراءة وفق الدور. وضّح الفرق بين القوالب المحمية والقواعد المخصصة، وحدود عدد القواعد الحالية، ولا تضف regex معقّد.
3. **نقطة إنفاذ خادمية محددة:** أضف `guard` أو endpoint تكامل داخل server يقيّم النص قبل استدعاء وجهة AI اختيارية معتمدة. عندما يكون `BLOCK` لا يمرر الطلب أصلًا؛ عند `REDACT` يمرر النص المنقّح فقط؛ و`ALLOW` يسمح بالتمرير للجهة المهيأة مع استمرار شروط المزود. إذا لا توجد جهة معتمدة، أرجع `PROVIDER_NOT_CONFIGURED` ولا ترسل الطلب ولا تعرض نجاحًا كاذبًا. لا تعتبر واجهة المختبر نفسها إنفاذًا عامًا خارج هذا المسار.
4. **ربط القرار بالسجل:** احفظ decision id ونوع القرار ورمز السبب ونسخة القاعدة فقط، وأظهر التاريخ والتصفية داخل نفس المؤسسة. ارفض الطلب عند تعذر حفظ القرار الإلزامي أو غياب سياسة مفروضة على مسار الإنفاذ؛ حافظ على عدم تسريب النص أو قيمة مطابقة حساسة.
5. **تجربة استخدام مكتملة:** لوحة سياسات + تقييم تفاعلي حقيقي بالـAPI + سجل قرارات + حالة مزود ومؤسسة. استعمل RTL وAppLayout وحالات عدم التهيئة/الرفض/المعالجة. اجعل CTA يعكس النتيجة الفعلية بدل حركة شكلية؛ حافظ على تسميات الفحص التجريبي إذا كان الهدف غير متصل.
6. **الحدود:** لا تطور DLP مؤسسي شامل أو حماية prompt-injection بالذكاء الاصطناعي من دون مواصفات معتمدة. الإجراء الأساسي للمنتج لا يحتاج اشتراك Ledger، ويستخدم audit Kernel تلقائيًا.
