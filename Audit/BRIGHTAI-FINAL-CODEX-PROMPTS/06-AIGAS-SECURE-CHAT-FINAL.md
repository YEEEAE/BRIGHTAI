## نقطة الانطلاق المثبتة من الفحص

- `/app/secure-chat/`, `src/scripts/secure-chat.ts`, `/app/api/secure-chat/models` و`messages` موجودة. `src/server/secure-chat/models.mjs` يحتوي `APPROVED_MODELS=[]`؛ مسار الرسائل الآن يرد `NO_APPROVED_MODEL` أو `PROVIDER_NOT_CONFIGURED` من دون استدعاء مزود.
- الواجهة الحالية فيها composer واختيار نموذج ولوحة جلسات، لكن جلسات المحادثة ليست محفوظة ولا يوجد تنفيذ provider adapter مفعّل. لا توجد جداول Secure Chat في Neon المفحوصة.
- المستند المعتمد يمنع مشاركة/تصدير/رفع ملفات/RAG افتراضيًا، ويفصل بيانات المحادثات عن سجلات Kernel الأساسية، ولا يسمح لمدير المؤسسة بقراءة نصوص موظفيه افتراضيًا.

## نفّذ الآن — بالترتيب

1. **Registry + Adapter عملي:** احتفظ بـ`APPROVED_MODELS` كقائمة تسمح بالنماذج المعتمدة فقط. أضف واجهة provider adapter Server-side تتعامل مع مزود موجود مصرح به بعد التأكد من الموافقة وإعداد `API_KEY` آمن، أو Neon AI Gateway إذا كانت شروط الاستخدام وسياسات الاحتفاظ ومنع التدريب معتمدة صراحة. لا تختر نموذجًا أو شروطًا نيابة عن المالك. إذا لم يتوفر اعتماد بعد، أكمل الـadapter ومسارات الحالة وأبقِ الإرسال مغلقًا برسالة مفهومة؛ لا تضع نموذجًا عامًا وهميًا.
2. **حماية خط الإرسال:** تحقق من session/tenant/user/access/model server-side، واتبع قواعد Kernel الأساسية حتى لو Firewall غير مشترى. طبّق حدود الرسالة الحالية، وحظر النموذج غير المعتمد، وتصنيف/تنقيح أولي للمدخلات الحساسة وفق سياسة بسيطة محددة قابلة للتعديل، وتعامل مع timeout/error/cancel بلا تسجيل محتوى المحادثة في error logs. امنع توجيه الرسائل إلى مزود آخر عند الفشل دون تصريح.
3. **جلسات خاصة وبيانات محكومة:** صمّم migrations تطويرية بسيطة لجلسات ورسائل المستخدم عند تفعيل ميزة حفظ المحادثات: `tenant_id`, `user_id`, conversation/message ids, created_at, model ref, وأقل محتوى لازم حسب سياسة الاحتفاظ؛ الوصول للنص لصاحب الجلسة فقط في API وليس OWNER/ADMIN بمجرد الدور. إذا لم تعتمد سياسة الاحتفاظ أو حماية البيانات، أبقِ الجلسات غير محفوظة، وقل ذلك في الواجهة بوضوح. لا تخزّن النص في audit، ولا تطبق حفظًا صامتًا.
4. **واجهة الاستخدام النهائية:** أكمل نموذج الاختيار المعتمد، composer، حالة الإرسال، رد النموذج الحقيقي، إلغاء وإعادة المحاولة، تبديل الجلسة عندما تكون محفوظة، حد الإدخال الواضح، وعداد استخدام بسيط فقط إذا كان يعتمد على tokens/usage فعلية من المزود؛ وإلا أظهر `غير متاح` بدل أرقام تخمينية.
5. **حماية الاستخدام والتكاليف:** أضف Rate limit عمليًا للمؤسسة/المستخدم عند توفر تخزين الخادم، وحد تكلفة/حصص لا يفرض رقمًا تجاريًا مخترعًا؛ اجعل القيم configurable محليًا وتظل معطلة حتى اعتمادها. لا تُنشئ مشاركة أو تصدير أو مرفقات أو RAG في هذا الإصدار، ولا تدّع تشفيرًا طرفيًا أو شروط عدم التدريب لدى مزود لم تثبت رسميًا.
