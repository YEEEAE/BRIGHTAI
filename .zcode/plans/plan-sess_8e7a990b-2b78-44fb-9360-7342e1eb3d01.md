## خطة العمل — تقسيم `evidence.astro` وفق النمط الكنوني للـ kernel

### التشخيص (مؤكد بالبيانات)

`src/pages/kernel/evidence.astro` = **86,638 bytes / 1849 سطر** — أكبر من التقدير الأصلي (67KB). المشكلة الفعلية **عكس** وصف المهمة: الملف مو "mixed responsibilities عشوائي"، بل **ينحرف عن النمط الكنوني للـ kernel**. كل صفحات kernel الشقيقة (approvals/replay/stats/reports/audit) تفصل البيانات في `src/data/kernel-X.ts` + mirror في `public/js/kernel-X-data.js` + engine في `public/js/kernel-X.js` + verify gate في `scripts/verify-X.mjs`. `evidence.astro` يحتوي البيانات (12 عنصر inline سطر 103-320) والمحرّك (~52KB inline script سطر 1283-1849) داخله، بدون data layer ولا verify gate.

قرارات المستخدم الموافق عليها: (1) النمط الكنوني للـ kernel، (2) حتمي كامل (mulberry32 + seed، لا Math.random/Date.now)، (3) 12 عنصر مطابقة للمنشور.

### الـ Contract المستهدف (مطابق لـ approvals نموذجًا)

```
src/data/kernel-evidence.ts          ← مولّد حتمي (seed + mulberry32 + FNV-1a chain)
public/js/kernel-evidence-data.js    ← UMD mirror (browser/worker/node)
public/js/kernel-evidence.js         ← vanilla engine (filters/preview/export/verify/batch/empty)
scripts/verify-evidence.mjs          ← gate (determinism/count/parity/chain/hygiene)
src/pages/kernel/evidence.astro      ← نحيف (~500 سطر): SSR + script tags فقط
package.json                         ← إضافة "verify:evidence"
```

**Count matrix مؤكد**: `total=12, allowed=7, blocked=2, pending_approval=2, approved=1, draft=1`.

### المرحلة 1 — إنشاء `src/data/kernel-evidence.ts` (المولّد الحتمي)

**الهدف**: مولّد حتمي ينتج **بالضبط نفس الـ 12 عنصر المنشورة** (نفس IDs `EVD-2026-10493...10465`، نفس traceIds، نفس الـ fields) مع hash chain FNV-1a من genesis `0x00000000`.

**البنية** (مستنسخة من `kernel-approvals.ts` حرفيًا):
- Header comment يوثّق الـ contract (seed, counts, chain, determinism, M22 reference).
- Types: `EvidenceStatus`, `EvidenceRiskLevel`, `EvidenceItem` (16 fields مطابقة للـ interface الحالي + `prevHash`).
- Constants: `EVIDENCE_SEED` (ثابت جديد)، `EVIDENCE_TOTAL=12`، count constants (`EVIDENCE_ALLOWED=7` إلخ)، `EVIDENCE_NOW`، `SECTORS`/`COMPLIANCE_PACKS`/`TAGS` pools، `PACK_LABEL`/`SECTOR_LABEL` maps.
- Helpers: `mulberry32`، `fnv1a`، `shuffle`، `pad2` (منسوخة byte-identical من approvals)، `formatArabicDate` يدوي (لا toLocaleString).
- `evidenceCanonical(item)`: joins decision-relevant fields بـ `|` (يستثني `hash`/`prevHash`/display labels) — يحدد الـ hash.
- `buildEvidenceRows()`: يبني الـ 12 عنصر بترتيب حتمي، يفرزهم بترتيب الـ IDs تنازليًا (مطابق للترتيب المنشور 10493→10465)، يبني hash chain.
- `buildEvidenceStats(rows)`: tally للحالات + إجمالي الحجم + عدد الحزم.

**القرار الحرج**: بدل إعادة "توليد" العناصر عشوائيًا من seed (اللي ينتج قيم مختلفة عن المنشورة)، الـ generator **يلفّ الـ 12 عنصر المنشورة كمصفوفة seed ثابتة** ثم يبني الـ hash chain حتميًا فوقها. هذا يضمن: (أ) المحتوى المنشور يتطابق 100%، (ب) الـ hash chain حتمي وقابل للتحقق، (ج) الـ determinism check ينجح (نفس seed = نفس chain دائمًا). `EVIDENCE_SEED` يُستخدم لـ `mulberry32` المستقبل (مثلاً للـ batch generation الحتمي) مو لإعادة إنتاج القيم الحرفية.

**التحقق**: `tsc --noEmit` على الملف، `buildEvidenceRows().length === 12`، كل IDs مطابقة للمنشورة.

### المرحلة 3 — إنشاء `public/js/kernel-evidence.js` (vanilla engine)

**الهدف**: نقل الـ ~52KB inline script من `evidence.astro` لملف منفصل، مع تحويل `generateNew()` و `bindBatch()` لـ **حتمية** (mulberry32 بدل Math.random).

**البنية** (IIFE CSP-safe، مثل `kernel-approvals.js`):
- `(function(){ 'use strict'; ... })();`
- كل الدوال الحالية منقولة: `applyFilters`, `openPreview`, `closePreview`, `downloadFor`, `openJson`, `verifyInModal`, `bindTamper`, `bindDropzone`, `renderEvidencePreview`, `bindItemButtons`, `bindModal`, `bindFilters`, `bindGenerate`, `bindBatch`, `applyLinkParams`.
- **التغيير الحتمي**: `generateNew()` يستخدم `KernelEvidenceData.mulberry32(seed + counter)` لاختيار sector/pack/risk/hash بدل `Math.random`. الـ counter يتزايد لكل استدعاء (عناصر متتابعة من السلسلة). الـ timestamps من `EVIDENCE_NOW` + offset حتمي بدل `new Date()`. الـ Arabic time formatting يدوي.
- **التغيير الحتمي**: `bindBatch()` progress bar يتزايد بحتمية بدل `5 + Math.floor(Math.random()*12)`.
- `window.__kernelEvidencePdf` bridge يبقى في الـ astro page (لأنه module import من `src/scripts/kernel-evidence-pdf-lite`).
- التحميل في الـ page: `<script type="module" src="/js/kernel-evidence-data.js"></script>` + `<script type="module" src="/js/kernel-evidence.js"></script>`.

**التحقق**: `node --check public/js/kernel-evidence.js` exit 0. لا Math.random/Date.now/toLocaleString/fetch (بعد تجريد التعليقات والـ strings).

**الهدف**: gate يثبت الـ contract مطابق لـ `verify-approvals.mjs` (بدون SLA group لأن evidence ما عندها SLA).

**البنية** (مستنسخة من `verify-approvals.mjs` مع التعديلات):

- TS load: `await import(pathToFileURL(tsSourcePath).href + '?t=' + Date.now())` (يعتمد على `--experimental-strip-types` + `--import test-ts-loader.mjs` من npm script).
- JS load: UMD-in-VM pattern (`vm.createContext({module:{exports:{}}, exports:{}})`).
- **5 groups** (مو 6 — حذف SLA):
  1. **Determinism**: `buildRowsFromTs()` مرتين → `JSON.stringify` متطابق.
  2. **Count matrix**: `total=12, allowed=7, blocked=2, pending_approval=2, approved=1, draft=1`.
  3. **TS↔JS parity**: كل الصفوف متطابقة + final hash متطابق.
  4. **Chain validity**: كل `hash === fnv1a(prevHash + '|' + evidenceCanonical(row))`، genesis `0x00000000`، final hash مثبت.
