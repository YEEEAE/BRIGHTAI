## خطة العمل — تجربة مقارنة إعادة التشغيل (Replay Comparison UX)

### المشكلة
صفحة `/kernel/replay/` والـ Trace Drawer ما تجاوبان على سؤال المستخدم الحرج: **«ليش تغيّر الحكم على هذا الطلب؟»**

- الـ `KernelReplay.compareRuns()` غني (matchStatus, diffReason, verdict before/after, riskBand, scoreDeltas) بس ما يُعرض في أي مكان.
- تبويب المحاكاة يعطي aggregate + جدول بـ verdict flip، بس لما تفتح الـ trace في الدرج، الـ seed ضعيف (user/dept/model/verdict فقط) — ما فيه policy/model version ولا before/after result.
- تبويب التحقيق يعطي timeline بس بدون عنصر "التغيير".
- ما في side-by-side result diff ولا export evidence مخصص للمقارنة.

### الحل (Drawer mode فقط — حسب اختيارك)
أضيف قسم جديد في الـ Trace Drawer اسمه **«لماذا تغيّر الحكم؟»** (`data-kernel-drawer-compare`) يظهر **فقط** لما الدرج يُفتح من سياق replay بـ seed فيه `compare`. باقي الصفحات (audit/approvals/playground) ما تتأثر لأن القسم يُفعّل بشرط.

### المرحلة 1 — تغذية الـ drawer بسياق المقارنة (kernel-time-machine.js)

**الملف:** `public/js/kernel-time-machine.js`

**التغيير:** لما الـ trace link يُفتح من جدول الطلبات المتأثرة (`bindAffectedTraceLinks`, line 470) أو من تبويب التحقيق (`bindInvestDrawer`, line 679)، أبني seed أغنى يحوي:

```js
var seed = {
  user: req, dept: dept, model: 'NVIDIA NIM', time: '—',
  verdict: after, status: ..., action: ...,
  // NEW — replay comparison context:
  compare: {
    before: r.before,           // 'allowed' | 'blocked'
    after: r.after,             // 'allowed' | 'blocked'
    policyId: r.policy,         // e.g. 'p-pii-export'
    policyName: policyName(r.policy),   // 'حظر تصدير قوائم العملاء (PII)'
    policyVersion: 'v2',        // deterministic stub from policy list index
    modelVersion: 'v1.4',       // deterministic stub
    inputUnchanged: true,       // البيانات التاريخية ما تغيّرت
    inputSummary: r.req,        // نص الطلب (الثابت)
    matchStatus: flip ? 'material' : 'exact-match',
    diffReason: flip ? ['policy-changed'] : [],
    falsePos: r.falsePos,
  }
};
```

أضيف helper `policyName(id)` يرجّع الاسم العربي من `REPLAY_POLICIES`. الـ before/after نأخذها من بيانات الـ row المتأثر (موجودة في `res.affected`). لما نفتح من تبويب التحقيق، نلفّ على `fullRows` ونلقى الـ row بنفس `traceId` عشان نأخذ before/after/policy.

**التحقق:** `npm run build` + `node scripts/verify-replay.mjs` (لا لمس الـ data module → ما يتأثر الـ determinism contract).

### المرحلة 5 — Playwright verification script جديد

**الملف الجديد:** `scripts/playwright/verify-replay-comparison.mjs`

يغطي **حالات الاختبار المطلوبة** (acceptance: «user can identify why outcome changed»):

1. **Missing trace** — أدخل Trace ID غير موجود في الـ dataset (مثل `AI-2026-99999`) في تبويب التحقيق: تأكد إن الـ timeline يطلع + الـ drawer إما ما يفتح أو يفتح بدون compare section.
2. **Partial replay** — شغّل محاكاة بسياسة واحدة فقط، افتح trace متأثر من الجدول: تأكد إن الـ compare section يظهر + الحكم قبل/بعد صحيح + نص السبب يذكر السياسة بالاسم.
3. **Provider failure** — فعّل وضع "مزوّد خارجي" بدون موافقة: تأكد إن بوابة الموافقة تطلع + ما يصير simulation (consent gate)، وبعد الموافقة الـ compare section يشتغل.
4. **Non-replay context** — افتح الـ drawer من صفحة `/kernel/audit/` (trace بدون compare seed): تأكد إن الـ compare section **ما يظهر** (ما كسرنا باقي الصفحات).
5. **Export evidence** — اضغط زر "صدّر دليل المقارنة": تأكد إنه يفتح نافذة طباعة بمحتوى المقارنة.

الـ script يستخدم `chromium.launch()` + `page.goto('http://localhost:4321/kernel/replay/')` + assertions على DOM. Exit 0 = نجاح.
