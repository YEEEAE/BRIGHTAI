### المرحلة 2 — chat.astro JS: معالجة كاملة لكل states (~35 دقيقة)

**الهدف**: كل ناتج من `/api/ai/chat` يصير له state صريح + badge + إجراء تالي.

**الملف**: `src/pages/kernel/chat.astro` (الـ `<script is:inline>` من 1008-2162).

**التغييرات** (كلها داخل `init()` + `sendMessage()`):

1. **إضافة `lastUserMessage` variable** (يخزّن آخر رسالة مستخدم للـ retry).

2. **دالة `attachSourceBadge(article, source, provider)`**: تضيف/يحدّث `.kernel-source-badge` أسفل كل AI `<article>`. تُستدعى من: SSE consumer, JSON path, demo fallback, blocked path.

3. **معالجة HTTP 451 (firewall block) و 428 (require_approval) — فرع جديد في `fetch().then()`**:
   ```
   if (res.status === 451 || res.status === 428) {
     return res.json().then(data => {
       renderBlockedMessage(data);  // يعرض bubble + badge محظور + suggested phrasing
       return null;
     });
   }
   ```
   `renderBlockedMessage()` يستخدم ناتج الـ API (`reply`, `traceId`, `findings`) + يبني `.kernel-chat-suggestion` مع `whyModified` من `findings`. يعيد استخدام الـ pattern الموجود في الـ seed (lines 475-491) بس ديناميكي من الـ API.

4. **معالجة HTTP 200 + `X-Stream-Status: all_providers_failed`**:
   ```
   if (res.status === 200 && res.headers.get('X-Stream-Status') === 'all_providers_failed') {
     showChatError('provider_failed');
     attachRetryToBanner(lastUserMessage);
     return null;
   }
   ```

5. **تحديث `showChatError(type)`**: يضيف زر retry داخل الـ banner (button `[data-kernel-retry]`). الـ retry يعيد `sendMessage(lastUserMessage)` صامتًا.

6. **تحديث `runDemoReply()`**: يستدعي `attachSourceBadge(aiMsg.article, 'demo')` قبل `streamInto`.

7. **تحديث SSE `consumeSSE`**: يستدعي `attachSourceBadge(aiMsg.article, 'live', lastProvider)` عند `done` event. لو `error` event mid-stream → badge يتحول لـ `unavailable` + retry.

8. **تحديث JSON path**: نفس الشيء، `attachSourceBadge(aiMsg.article, 'live', data.provider)`.

9. **زر Cancel — ربط `composerAbort`**:
   - في `sendMessage()`: بعد `sendBtn.disabled = true`، أبدل محتوى `sendBtn` لأيقونة ⏹ + نص "إيقاف"، أضف class `kernel-chat-composer__btn--cancel`، أزل `disabled`.
   - أربط `sendBtn` بـ click handler مؤقت: `composerAbort.abort()`.
   - في `finalizeIdle()` + كل مسارات النهاية: أرجع `sendBtn` لحالته الأصلية (أيقونة send + نص "إرسال" + أزل `--cancel`).
   - في الـ catch path لـ AbortError (موجود:1591): يخلي الـ partial reply + يضيف badge "مُلغى" + زر retry.

10. **تعديل `createMessage()`**: يضيف `<span class="kernel-source-badge" data-source="pending" hidden>` فارغ جنب الـ meta، جاهز للتحديث.

**التحقق**: `npm run build` → 0 أخطاء + فحص grep على الأنماط الجديدة في `dist/client/kernel/chat/index.html`.

### مخاطر متبقية + قرارات

1. **`findings` shape من الـ API**: الـ 451/428 response فيه `findings` (array of PII entities). الـ `whyModified` في الـ suggestion box بيبني من `findings.join()` — لو الـ API ما يرجّع findings النص يطلع عام. مقبول (graceful degradation).
2. **الـ demo reply بعد error**: حاليًا 404/502/504 يطلّعون error banner **+ demo reply**. هذي سياسة قديمة. الـ AC "user always knows what happened" يقول إن الـ demo reply بعد الـ error يربك المستخدم. **قرار**: أخلي الـ demo fallback فقط لحالة 404 (unavailable genuinely)، وألغيه لـ 502/504/503 (provider failed يجب يطّلع error + retry فقط بدون demo). هذا تغيير سلوك مقصود — راح أوثّقه في التقرير.
3. **`KernelChatError.astro` ما يُستورد في chat.astro**: مقصود — inline `showChatError()` للحركة الديناميكية. المكوّن يصير source-of-truth للـ types + النصوص، للاستخدام المستقبلي في صفحات ثانية.
4. **نصوص عربية جديدة** (retry "إعادة المحاولة", cancel "إيقاف", "مُلغى", "محظور بالسياسة", "مباشر", "تجريبي"): نصوص UI جديدة مو منشورة/mُفهرَسة → آمن إضافتها. كلها بالعامية/MSA الخفيف المتّسق مع المحتوى المنشور.
5. **لا commit** (per brain rule: المستخدم يلتزم). لا branch جديد (per brain rule).
