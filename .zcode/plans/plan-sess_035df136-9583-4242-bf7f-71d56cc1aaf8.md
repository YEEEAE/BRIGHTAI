### المرحلة 2 — GA4 Measurement Protocol server-side (الجزء الناقص فعلًا)
**ملف جديد**: `src/lib/ga4-server.ts`

```ts
// يبني POST لـ https://www.google-analytics.com/mp/collect
// best-effort: أي throw يمسكه caller، ما يفشل الـ lead enqueue.
// fallback آمن: لو GA4_API_SECRET فاضي → no-op + warning.
export async function sendServerEvent(opts: {
  events: Array<{ name: string; params?: Record<string, unknown> }>;
  clientId?: string;   // من _ga cookie أو IP+UA hash
}): Promise<void>
```

- يقرأ `process.env.GA4_API_SECRET` + `GA4_MEASUREMENT_SECRET` (Measurement ID). لو أي واحد فاضي → log warning + return.
- لو الـ secret موجود: POST لـ `/mp/collect?measurement_id=...&api_secret=...` مع body `{ client_id, events }`.
- timeout 3s + `AbortController`. أي خطأ → `console.warn` بس (best-effort).
- clientId: من `_ga` cookie pattern، fallback لـ sha256(ip + userAgent).slice(0,16) — ما يطلع PII برّه.

**التحقق**: `npx tsc --noEmit`

### المرحلة 3 — ربط `api/lead.ts` بـ GA4 server-side
**ملف**: `src/pages/api/lead.ts` (سطر ~275 بعد الـ enqueue الناجح، قبل `return jsonResponse`)

أضيف بعد استخراج `mode`:
```ts
// 7. Server-side GA4 conversion (best-effort). Covers client event loss
//    (adblocker, network drop after submit). Never blocks the lead.
try {
  const clientId = parseClientIdFromCookie(request.headers.get('cookie'))
    ?? sha256(`${ip}|${getUserAgentLocal(request)}`).slice(0, 16);
  await sendServerEvent({
    clientId,
    events: [{
      name: 'generate_lead',
      params: { source: lead.source ?? 'kernel', page: lead.page ?? null },
    }],
  });
} catch (e) {
  console.warn('[ga4-server] generate_lead failed', e);
}
```

الـ secret معروض فقط في Render env. لو محليًا فاضي → no-op + warning (ما يكسر dev).

**التحقق**: `npm run build` → 125 صفحة، 0 أخطاء.

### المخاطر المتبقية
1. **GA4_MEASUREMENT_SECRET + GA4_API_SECRET ما أُضيفت لـ Render** → الـ server-side `generate_lead` راح يكون no-op لحد ما تضيفها (الكود جاهز، fallback آمن شغّال).
2. **حجم الـ events في GA4 راح يزيد** (alias policy): كل form submit يطلق 3 أحداث (form_submit_attempt + lead_started + form_submit_success + lead_completed + generate_lead). هذا مقصود من قرار "alias".
3. **chat_completed يطلع بس على happy path حقيقي** — لو المستخدم يأخذ demo reply أو خطأ، ما يطلع chat_completed. هذا متعمّد (الـ event يعدّ reply فعلي موكتّب).
