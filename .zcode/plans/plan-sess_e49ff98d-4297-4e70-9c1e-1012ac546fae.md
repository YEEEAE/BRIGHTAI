## المرحلة 0 — Gate 0: إغلاق P0 الإنتاجية (أول شيء)
1. **Cloudflare (P0-A):** أكتب لك خطوات لوحة Cloudflare الدقيقة (AI Crawl Control → إيقاف Managed robots / فتح training + Purge Cache) → أنت تطبقها → أتحقق حيًا بعدها وأقفل الـ P0 بالتقرير.
2. **التحويلات (P0-B):** تشخيص جذري — هل البناء المنشور يحمل `dist/redirects.json` والـ listener المرقّع؟ أفحص خادم dist محليًا مقابل السلوك الحي، أحدد ROOT CAUSE وأصلحه محليًا (يشفى عند deploy قادم).
3. فحص حي كامل: الصفحات الست الاستراتيجية + عينات تحويلات + sitemap حي (عدد/URLs) + headers — جدول REPO/LIVE/EXPECTED/ROOT CAUSE/FIX.

## المرحلة 4 — تنفيذ: ترقية الأصول القابلة للربط (الأعلى قيمة)
1. **سجل مخاطر AI (`/tools/ai-risk-register/`)** — الأصل الأول: إضافة تصدير **CSV + JSON client-side** (vanilla JS في `public/js/`، متوافق CSP، progressive enhancement، الصفحة تظل كاملة بدون JS، الطباعة تبقى) + تحديث الـ contract test.
2. **التقييم (`/assessment/…`):** تقييم إضافة أبعاد vendor AI/agent governance — لمسة خفيفة فقط إذا استحقت، وإلا توثيق.
3. **Policy→Control Mapper:** التحقق أن `/solutions/policy-to-control-mapping/` يخدم النية — تحسين فقط عند وجود فجوة، بدون URL منافس.

## المرحلة 5 — تنفيذ: هندسة العناقيد والروابط الداخلية

- إصلاح غياب `/hub/security/` عن بطاقات فهرس `/hub/` (مسار موجود بالـ sitemap لكن غير مُدرج).
- مخرج: `audit/phase2/internal-authority-flow.csv` (TIER A/B/C/D) + تطبيق الروابط ذات الأولوية.
