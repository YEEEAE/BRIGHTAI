## M11 — Seed وإعادة الإنتاج (Reproducibility & Replay)

نفّذ Prompt 12 / Evaluation-environment §5 كاملًا، على نطاق **تشغيل حالة واحدة في الملعب** (موجود حاليًا؛ محرك M6/M9 الدفعي خارج النطاق). الواجهة = **زر Replay + درج جانبي في `/kernel/playground/`**. لا ألمس `/kernel/replay/` الحالية (آلة الزمن — مفهوم مختلف).

### الاكتشافات المعمارية المؤكدة
- `KernelEvalStore` (`public/js/kernel-eval-store.js`) موجود لكن **الملعب ما يستدعيه إطلاقًا** — `analyze()` يرجّع كائن ولا يكتب Run. لازم أربط الاثنين.
- `RunSetup` فيه بالفعل `seed?/temperature?/topP?` + كل الإصدارات. `EvaluationRun` فيه `inputHash/outputHash/runHash` لكنها **placeholders غير حتمية** (`simpleHash(now + Math.random())`).
- FNV-1a **مكرّر 3 مرات**: `kernel-datasets.ts` (TS), `kernel-datasets.js` (browser), `kernel-playground.js:hashStr` (يرجع number لـ seed). ولاحدة مركزية.
- لا يوجد `parentRunId` / `reproducibility` / `matchStatus` / `diffReason` في أي مكان.
- `EvaluationCertificate` (النوع فقط، M13 لسه ما اتبنى) ما عنده slot لـ reproducibility.

### التنفيذ — 9 ملفات (4 جديد + 5 معدّل)

#### ج──── جديد (4)
1. **`public/js/kernel-hash.js`** — أداة الهاش الموحدة (ES module خارجي، CSP-safe):
   - `fnv1a(str)` → `'0x' + 8-hex` (يتطابق مع `kernel-datasets.ts`).
   - `fnv1aNumber(str)` → عدد صحيح (يحل محل `hashStr` في playground **بنفس الخوارزمية بالضبط** عشان ما يتغير سلوك الـ determinism الموجود — trace IDs, risks, latencies).
   - `canonicalizeSetup(setup)` → سطر canon موحّد (dataset id+ver | model id+ver+provider | prompt ver | policy ver | scorers id+ver مرتّبة | env | seed | temp | topP | runtime).
   - `inputHash(text, setup)` / `outputHash(result, setup)` / `runHash(inputHash, outputHash, setup)` — كلها حتمية 100%، لا timestamp ولا random.

2. **`public/js/kernel-replay.js`** — محرك Replay + التصنيف:
   - `replay(originalRun, mode, overrides, executor)` حيث `executor` يأخذ (setup, inputText) ويرجّع ناتج analyze (المحرك يبقى في playground؛ المتجر منفصل).
   - `classify(old, new)` → `{ matchStatus: 'exact-match'|'acceptable'|'material'|'non-reproducible', diffReason[] }`:
     - **exact-match**: outputHash متطابق.
     - **acceptable**: verdict + score ثابتان، النص اختلف.
     - **material**: تغيّر verdict أو risk level.
     - **non-reproducible**: البيئة/الـ setup تغيّرت بشكل يمنع إعادة التشغيل، أو الـ input ما عاد متاحًا.
   - `diffReason(old, new)` → مصفوفة من: `provider-changed|model-changed|policy-changed|dataset-changed|scorer-changed|environment-changed|stochastic-variance` (يقارن كل حقل setup، وإن تطابقت كلها + اختلف الـ output = stochastic).
   - `compareRuns(aId, bId)` — يرجّع كائن مقارنة قبل/بعد كامل (setup diff + result diff + verdict flips + score deltas).

3. **`kernel/assets/css/pages/playground-replay.css`** — هوية درج Replay: بتنفس توكنز الكيرنل، حالات التصنيف الأربع بألوان (أخضر exact / أزرق acceptable / عنبري material / رمادي non-reproducible)، شارات أسباب الاختلاف، diff table قبل/بعد. يحترم `prefers-reduced-motion`.

4. **`scripts/playwright/verify-kernel-m11-replay.mjs`** — 20+ فحص runtime (منفذ 4422، يخدم dist/client): كل حقول الـ provenance محفوظة، `replayRun` ينشئ Run جديد، `parentRunId` مرتبط، **الأصل ما تعدّل**، الأنواع الأربعة للتصنيف، أسباب الفرق السبعة، diff قبل/بعد، reproducibility في الشهادة، hashes حتمية (نفس المدخل ← نفس الهاش مرتين).

#### ب──── معدّل (5)
5. **`src/data/kernel-evaluation.ts`** — أضيف الأنواع:
   - `DiffReason` union (السبعة أسباب).
   - `ReproducibilityResult { matchStatus; diffReason[]; comparedRunId?; comparedAt? }`.
   - `EvaluationRun.parentRunId?: string` + `EvaluationRun.reproducibility?: ReproducibilityResult`.
   - `EvaluationRun.runtimeVersion?: string` + `EvaluationRun.promptVersionHash?` (مفقود حاليًا — لأ completeness الـ provenance).
   - `EvaluationCertificate.reproducibility?: { seed; temperature; topP; parentRunId?; matchStatus?; diffReason?[] }`.

6. **`public/js/kernel-eval-store.js`** — تعديلات جوهرية:
   - **يستورد `fnv1a`/`inputHash`/`outputHash`/`runHash` من kernel-hash.js** (يحل محل `simpleHash`).
   - `createRun` يحسب الهاشات **حتميًا** (لا now، لا random)، وينسخ `parentRunId`/`reproducibility`/`runtimeVersion` من draft.
   - `cloneRun` يحافظ على `parentRunId: undefined` (نسخة عادية، ليست replay).
   - **`replayRun(id, { mode, overrides })`** جديد: يقرأ الأصل → يجهّز draft بـ `parentRunId = originalId` + overrides → **ما يعدّل الأصل** → يرجّع draft للملعب للتشغيل → الملعب يستدعي `finalizeReplay(newId, result)`.
   - **`listReplayableRuns()`** جديد: Runs مكتملة/منشورة فقط.
   - **`getRunLineage(id)`** جديد: يبني سلسلة parentRunId للعرض.

7. **`public/js/kernel-playground.js`** — ربط الملعب بالمتجر:
   - بعد كل `analyze()` ناجح → يبني `EvaluationRun` draft ويستدعي `KernelEvalStore.createRun` (يخزّن Run حقيقي الآن؛ أساس أي Replay).
   - `hashStr` → `fnv1aNumber` من kernel-hash.js (نفس الخوارزمية → نفس النتائج، ما أكسر شي).
   - زر **`#pg-replay-run`** جديد يفتح الدرج + يمرّر `lastResult` + `lastRunId`.
   - certificate stub (سطر 217) يأخذ `reproducibility` field (يُملأ بعد أول Replay).

8. **`src/pages/kernel/playground.astro`** — UI:
   - زر "Replay Run ▸" في منطقة أزرار النتيجة.
   - **Drawer Replay** (`#pg-replay-drawer`): مبدّل نوع Replay (كامل / حالة فاشلة / إعداد مختلف) + عرض seed/temp/topP/model/provider/policy/dataset/scorers/env/runtime (محفوظة من الأصل، قابلة للتعديل للإعداد المختلف) + زر "شغّل Replay" + منطقة النتيجة (تصنيف + أسباب الفرق + diff).
   - `<script type="module" src="/js/kernel-replay.js">` + استيراد `playground-replay.css`.
   - الجزر التقنية `dir="ltr"` للهاشات/الـ IDs.

9. **`src/layouts/KernelLayout.astro`** — أضيف `<script type="module" src="/js/kernel-hash.js">` **قبل** kernel-eval-store.js (eval-store يعتمد عليه). الترتيب: hash → eval-store → shell → drawer.

### المخاطر الموثّقة
- **خطر الـ determinism القائم**: `hashStr` في playground مستخدم في ~30 مكان لـ seed derivation. أحافظ على نفس الخوارزمية بالضبط في `fnv1aNumber`، وإلا تتغير كل الـ trace IDs/risks. (تغطية: Playwright يتحقق إن نفس المدخل → نفس الـ trace قبل وبعد التغيير.)
- **الـ blast radius على hashes**: تحويل `runHash` من random لـ deterministic قد يؤثر على عرض الـ demo. تحققت: runHash يُستخدم فقط للعرض + certificate. آمن.
- **الترتيب**: kernel-hash.js لازم يتحمّل قبل eval-store. أحطه في KernelLayout قبل eval-store.
