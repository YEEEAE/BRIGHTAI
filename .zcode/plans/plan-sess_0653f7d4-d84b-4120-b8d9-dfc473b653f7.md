## السياق المحقق من الريبو
- الجداول موجودة أصلًا من **migration 011**: `lab_test_templates` (status: DRAFT/ACTIVE/ARCHIVED + `current_version_id`) و`lab_test_template_versions` (version, default_sample_count, parameters_json, connector_choices_json, applicable_product_id, applicable_equipment_id, sop_id, wi_id, approved_by — UNIQUE(template_id, version)).
- `lab_test_records` فيه `template_version_id` + `template_snapshot_json` فقط — **ما فيه `template_id`** (مطلوب صراحة من المستخدم → migration جديدة).

- آخر migration = **016** → الجديدة **017**.

## 1) Migration `017_lab_template_equipment.sql`
- جدول ربط `lab_template_equipment (template_id, equipment_id)` PK مركّب + CASCADE بالاتجاهين + فهرس equipment — مكافئ `lab_product_equipment` (016) لتوافق الأجهزة المتعدد.
- `ALTER TABLE lab_test_records ADD COLUMN template_id INTEGER REFERENCES lab_test_templates(id) ON DELETE RESTRICT` — لتخزين `template_id` صراحة بجانب `template_version_id` الموجود (مطلب المستخدم).
- التسجيل في `src/lib/db.ts` (migration 17 + REQUIRED_TABLES/INDEXES)، مرآة `db/schema.sql`، عدّادات `scripts/{test-migrations,test.mjs,test-dashboard-reports}.mjs` (16→17).

## 2) `src/lib/lab/templates.ts` (الوحدة الوحيدة — نسخة من نمط products.ts)
- **بحث/فلاتر/فرز/ترقيم** بنمط testSearch: `parseLabTemplateSearchFilters` (q/type/status/product/sort/dir/page/per من الـ URL)، `buildLabTemplateWhere` مكمَّم بالكامل + `ESCAPE '\'`، فرز allowlist + tiebreaker `t.id DESC`، `COLLATE NOCASE` لتعارض code.
- **القراءة**: `getLabTemplateDetail(id)` (القالب + النسخة الحالية + كل النسخ + الأجهزة المرتبطة + عدّاد اختبارات مستخدمة)، `listLabTemplatesForForm()`، dropdowns (منتجات فاعلة، أجهزة غير مؤرشفة، SOP/WI بـ `status='APPROVED'` فقط — نفس قرار PROMPT 08).
- **الإنشاء** (ترانزاكشن واحدة): template DRAFT + version 1 (parameters_json يُسبق من `policy.ts` defaults: Standard Parameter / Acceptance Criteria / Holding Time / Actual Pressure Reference — قابلة للتحرير قبل الاعتماد) + ربط الأجهزة (dedup) + audit `CREATE` على `qc_audit_log` بكيان `LAB_TEMPLATE`.
- **التحرير — سيمانتيك الإصدارات**: نسخة DRAFT تُحرَّر في مكانها؛ تعديل قالب نسخته الحالية **معتمدة** → ينشئ version N+1 كـ DRAFT (النسخ المعتمدة immutable — قرار مطابق لدورة الوثائق §41 والعقد §30) + audit `VERSION`.
- **الإجراءات** (نفس ترانزاكشن + audit): `approve` → يرقّي النسخة الدفت إلى approved (approved_by من الجلسة أبدًا من البودي) + يحدّث current_version_id + template.status=ACTIVE + audit `APPROVE`؛ `archive` → status=ARCHIVED (يختفي من قوائم النماذج) + audit `ARCHIVE`. مؤرشف = read-only (نفس نمط is_active للمنتجات).
- **POST handlers** بنمط `handleLabProductFormPost`: getCurrentUser → صلاحية → requireCsrf → parseFormData → `equipment_ids` من الفورم الخام → فلاش + redirect. حقل `form_action` مخفي (save|approve|archive) للإجراءات من صفحة التفاصيل.
