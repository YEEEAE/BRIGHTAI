1. **Purpose & status** — عقد معماري ملزم لبرومبتات 02-39، قاعدة "repository is source of truth".
2. **Source documents & precedence** — المرجع > prompt4 > الأودت؛ مع توثيق الملفات المفقودة.
3. **Verified repository facts** — migration 010 هو الأخير (التالي 011)، `permissions.ts` مصدر RBAC، middleware guards، baseline: typecheck 0/0/13 + test 279/0 + e2e:acceptance أخضر.
4. **Integration contract (anti-duplication map)** — جدول: auth/session/RBAC/CSRF/validation/audit/notifications/dashboard/exports/workflow → الوحدة القائمة التي تُعاد (auth.ts, session.ts, permissions.ts, api-security.ts, validation.ts, qc-operations/audit, notifications.ts, dashboard.ts, reporting/writers, workflows pattern).
5. **Route tree & guards** — الجدول الكامل للمسارات المطلوبة (36 مسار /lab) → مسار الملف المقترح (`src/pages/lab/...`) → الحارس (middleware prefix guard جديد `/lab` + إعادة تحقق server-side في كل API) → الصلاحية المنطقية. **خرائط إعادة الاستخدام الموثقة**:
   - `/lab/notifications` = واجهة مختبرية لأنواع lab الجديدة عبر `notifications.ts` نفسها (لا نظام ثانٍ) + الجرس العام يشملها.

   - `/admin/templates` (قوالب المهام) ≠ `/lab/templates` (قوالب الاختبارات) — كيانان منفصلان، يوثَّق صراحة منع الخلط.
6. **Permission model** — أسماء LAB_* المنطقية (من المرجع §5) مرتبة على مصفوفة الأدوار الأربعة القائمة (admin/manager/supervisor/employee)، تُضاف إلى كائن `PERMISSIONS` في `permissions.ts` فقط (ممنوع إطار ثانٍ). قواعد: self-approval ممنوع للمراجع/المعتمد، التصحيح بأثر رجعي ممنوع.
7. **Entities & relationships** — الكيانات الـ17 من PROMPT 02 (lab_test_records, lab_test_samples, lab_products, lab_test_templates(+versions), lab_equipment, lab_equipment_maintenance, lab_equipment_calibration, lab_documents(+versions/links), lab_test_retests, snapshots, lab_sample_identifiers, lab_document_acknowledgements, lab_saved_views) مع FKs (`test.equipment_id → lab_equipment.id` — العلاقة بالـ id مو الاسم)، الفهارس، وقاعدة السجلات التاريخية (snapshots عند الاعتماد).
8. **Migration order** — سلسلة جديدة: `011_lab_core_master_data.sql` (products/equipment/calibration/maintenance + **توسيع CHECK في qc_audit_log** عبر إعادة بناء محافظة على الصفوف مع marker `-- brightai:allow-destructive` + auto-backup — لتجنب نظام تدقيق ثانٍ)، `012_lab_tests.sql` (tests/samples/retests/snapshots)، `013_lab_documents.sql` (documents/versions/links/acknowledgements)، `014_lab_views.sql` (saved views + فهارس بحث). كل migration يجب أن تُضاف أيضًا كـ `?raw` import في `db.ts` + تحديث `REQUIRED_TABLES`/`REQUIRED_INDEXES` + `types.ts` (عقد db.ts الموثق في العقل).
