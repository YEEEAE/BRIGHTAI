# التقرير الأول: BRIGHTAI Kernel UI/UX and Runtime Audit

## 1. ملخص تنفيذي
المشروع (`BRIGHTAI`) عبارة عن **High-Fidelity Prototype / Demo** متقدم جداً لمنصة حوكمة الذكاء الاصطناعي (Kernel). تم بناء الشِل (Shell) المشترك بكفاءة عالية باستخدام Astro و Vanilla JS Modules (`kernel-shell.js`, `kernel-drawer.js`, `kernel-eval-store.js`)، مما يوفر تجربة مستخدم سلسة، لوحة أوامر (Command Palette)، ودرج تتبع (Trace Drawer) تعمل بالكامل في المتصفح (Client-side) مع حفظ الحالة في `localStorage`.

**النتيجة الأساسية:** المنتج **Pre-sales-ready** و **Demo-ready**. الواجهة قوية جداً، الـ RTL ممتاز، والـ Accessibility مدعومة بشكل احترافي. ومع ذلك، **لا يوجد Backend حقيقي**؛ كل البيانات والتفاعلات في الصفحات الداخلية (Chat, Playground, Audit) تعتمد على Mock Data أو HTML مدمج من ملفات JSON (`migratedKernelPages.ts`).

---

## 2. حالة البيئة والـ Build
- **Framework:** Astro 6.x (Static Site Generation مع View Transitions).
- **Styling:** `kernel.css` (CSS Variables, Logical Properties for RTL).
- **State Management:** `kernel-eval-store.js` (Custom Vanilla JS Store over `localStorage`).
- **Scripts Available:** `build`, `dev`, `verify:all` (يشمل typecheck, lint, seo, headers), `a11y:scan`, `test:chat-session`.
- **Browser Automation:** Playwright متوفر في `devDependencies`، ولكن لم يتم تشغيله في هذه البيئة (Static Audit Only).

## 5. المشاكل الرئيسية (P0, P1, P2)

### P0: Blockers (تمنع الإطلاق كمنتج حقيقي)
1. **No Real Backend Integration**: كل صفحات Playground, Chat, Audit, Scenarios هي **Mockups** (HTML مدمج). لا يمكن تشغيل تقييم حقيقي أو حفظ Trace في قاعدة بيانات.
2. **Migrated Pages Architecture**: الاعتماد على `migratedKernelPages.ts` (JSON blobs) يجعل الصفحات ثقيلة ويمنع استخدام Astro Components التفاعلية (Islands) بشكل صحيح.

### P1: High Impact (تؤثر على تجربة العرض)
1. **Static KPIs**: الأرقام في `/kernel/` (مثل "0 سجل PII محجوب") ثابتة. يجب ربطها بـ `kernel-eval-store.js` لتتحدث عند تشغيل سيناريو في Playground.
2. **Trace Drawer Data Source**: الدرج يعمل، لكن إذا لم يكن الـ Trace في الـ Store، يعتمد على Seed. يجب توحيد أسماء الـ Traces بين كل الصفحات.
3. **Missing Page Implementations**: مسارات مثل `/kernel/replay/` و `/kernel/offline/` قد تكون 404 إذا لم تكن معرّفة في `astro.config.mjs` أو `kernelUnits`.

### P2: Polish (تحسينات)
1. **Loading States**: إضافة Skeletons عند فتح Trace Drawer أو تشغيل سيناريو.
2. **Empty States**: تحسين رسائل "لا توجد بيانات" في Audit و Reports.
3. **Export Functionality**: أزرار تصدير PDF/JSON في Reports و Evidence يجب أن تعمل فعلياً (توليد Blob من HTML/Store).

# التقرير الثاني: BRIGHTAI Kernel UI/UX Execution Prompts

## P0: Blockers

### Prompt A: إصلاح Shell العام وتوحيد الـ State
**الهدف:** ربط كل صفحات Kernel بـ `kernel-eval-store.js` لضمان أن أي إجراء في Playground أو Chat ينعكس فوراً في Audit و Trace Drawer.
**الملفات المتأثرة:** `src/layouts/KernelLayout.astro`, `public/js/kernel-shell.js`, `public/js/kernel-eval-store.js`
**المشكلة المثبتة:** الصفحات الداخلية تعتمد على HTML مدمج (JSON blobs) ولا تقرأ من الـ Store المشترك.
**نفّذ:**
1. إزالة الاعتماد على `migratedKernelPages.ts` للصفحات التفاعلية (Playground, Chat, Audit, Policies).
2. إنشاء Astro Islands (React/Vue/Svelte أو Vanilla JS) لكل صفحة تقرأ من `window.KernelEvalStore`.
3. إضافة Global Event Bus في `kernel-shell.js` (`window.dispatchEvent(new CustomEvent('kernel:run-created'))`) لتحديث الـ Sidebar badges (Approvals, Connectors) لحظياً.
**معايير القبول:**
- تشغيل سيناريو في Playground يضيف Trace جديد في Audit فوراً.
- Sidebar badges تتحدث بدون إعادة تحميل الصفحة.
**أمر التحقق:** `pnpm build && pnpm verify:all`

## P1: High Impact

### Prompt B: إصلاح Playground (Interactive Pipeline)
**الهدف:** تحويل Playground من Mockup إلى أداة تشغيلية حقيقية.
**الملفات المتأثرة:** `src/pages/kernel/playground/index.astro`, `src/components/kernel/PlaygroundPipeline.astro`
**المشكلة المثبتة:** الـ Pipeline عبارة عن HTML ثابت لا يتفاعل مع إدخال المستخدم.
**نفّذ:**
1. إنشاء `<PlaygroundPipeline />` كـ Astro Component.
2. ربط كل مرحلة (PII Scan, Risk Score, Policy Match) بـ JS محلي حتمي (مثل `kernel-drawer.js` logic).
3. عند الضغط على "Run"، استدعاء `KernelEvalStore.createRun()` وحفظ الـ Trace.
4. تفعيل أزرار "Export cURL/Python/TS" لتوليد الكود من إعدادات الـ Run الحالي.
**معايير القبول:**
- إدخال نص يحتوي على PII يفعّل مرحلة "فحص PII" ويعرض النتيجة.
- تغيير السياسات يغير نتيجة "مطابقة السياسات".
**أمر التحقق:** `pnpm test:playground` (يجب إنشاؤه)

### Prompt C: إصلاح Chat و Scenarios و Red Team
**الهدف:** إضافة Mock Provider حقيقي لمحاكاة استجابات AI.
**الملفات المتأثرة:** `src/pages/kernel/chat/index.astro`, `src/pages/kernel/scenarios/index.astro`
**نفّذ:**
1. إنشاء `MockAIProvider.js` يرجع استجابات متأخرة (setTimeout) مع درجات مخاطر.
2. في Chat، عند إرسال رسالة، إنشاء Trace في الـ Store وعرضه في الـ Thread.
3. في Scenarios، إضافة زر "Run All" يشغل كل الحالات ويحدث الـ Progress Bar.
**معايير القبول:**
- Chat يدعم Enter للإرسال و Shift+Enter لسطر جديد.
- Scenarios تظهر نتائج (Passed/Failed) حقيقية بناءً على الـ Mock Provider.

### Prompt D: إصلاح صفحات الرقابة (Policies, Audit, Approvals, Replay)
**الهدف:** ربط الجداول والفلاتر بالبيانات الحقيقية في `kernel-eval-store.js`.
**الملفات المتأثرة:** `src/pages/kernel/audit/index.astro`, `src/pages/kernel/approvals/index.astro`
**نفّذ:**
1. في Audit: قراءة `KernelEvalStore.listRuns()` وعرضها في جدول قابل للفرز.
2. في Approvals: تصفية الـ Runs التي حالتها `pending_approval`.
3. تفعيل زر "Approve/Reject" الذي يستدعي `KernelEvalStore.updateRun(id, { status: 'approved' })`.
4. في Replay: استخدام `KernelEvalStore.replayRun()` لإنشاء نسخة جديدة من الـ Run.
**معايير القبول:**
- رفض طلب موافقة يغير حالته في Audit فوراً.
- Replay ينشئ Run جديد بـ `parentRunId` صحيح.

### Prompt E: إصلاح صفحات الإثبات (Compliance, Evidence, Reports, Stats)
**الهدف:** تفعيل التصدير والتحقق من الأدلة.
**الملفات المتأثرة:** `src/pages/kernel/evidence/index.astro`, `src/pages/kernel/reports/index.astro`
**نفّذ:**
1. في Evidence: تفعيل زر "Download JSON" الذي يولد Blob من الـ Trace والـ Hash.
2. في Reports: تفعيل Dialog "إنشاء تقرير" الذي يجمع البيانات من الـ Store ويولد PDF (باستخدام `window.print()` أو مكتبة JS).
3. في Stats: ربط الـ KPIs بـ `KernelEvalStore.listRuns()` لحساب التكاليف والمخاطر الفعلية.
**معايير القبول:**
- تصدير Evidence يعطي ملف JSON صالح.
- Stats تتحدث عند تشغيل سيناريوهات جديدة.
