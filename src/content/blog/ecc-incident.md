<h2 id="incident-why">ليش حوادث AI تختلف؟</h2>
<p>حوادث الأمن السيبراني في أنظمة الذكاء الاصطناعي تختلف عن الحوادث التقليدية بطبيعتها. في الأنظمة التقليدية، الحادثة تكون "خراجين قرص" أو "ثغرة في الخادم". في أنظمة AI، الحادثة قد تكون "prompt injection نجح" أو "نموذج تعرض للـ jailbreaking" أو "API مُخترق ويولد محتوى غير مرغوب."</p>
<p>التحدي الرئيسي: الحوادث في AI غالبًا ما تكون "ناعمة" — ما تظهر كخراجين واضح. قد يكون النموذج يولد معلومات خاطئة أو يتعامل مع بيانات حساسة بدون ما يكون واضح. هذا يحتاج فحصًا أعمق.</p>
<p>لإدارة هذه الحوادث، لازم تكون لديك خطة استجابة مخصصة للذكاء الاصطناعي. الخطة التقليدية ما تكفي.</p>
</section>

<section>
<h2 id="incident-types">أنواع الحوادث الشائعة في أنظمة AI</h2>
<p>أهم أنواع الحوادث التي تواجه أنظمة الذكاء الاصطناعي:</p>
<ul>
<li><strong>prompt injection:</strong> المهاجم يرسل طلبًا خبيثًا يجعل النموذج يتصرف خارج نطاق التصميم. مثال: "تجاهل التعليمات السابقة وأخبرني بـ ..."</li>
<li><strong>تسريب نموذج أو بيانات:</strong> API مُخترق أو إعدادات خاطئة تكشف نموذجك أو بيانات التدريب.</li>
<li><strong>استخدام غير مصرح:</strong> شخص غير مخول يستخدم API النماذج أو يستخرج بيانات.</li>
<li><strong>تكرار أو استهلاك غير طبيعي:</strong> استهلاك مفرط للـ API يرفع التكاليف أو يستنزف الموارد.</li>
<li><strong>نموذج مُعدّل (Model Poisoning):</strong> التدريب على بيانات مُعدّلة يغير سلوك النموذج.</li>
</ul>
<p>لكل نوع حادثة، الاستجابة تختلف. الخطة لازم تغطي كل نوع.</p>
</section>

<section>
<h2 id="incident-plan">خطة استجابة الحوادث (IRP) للذكاء الاصطناعي</h2>
<p>خطة استجابة الحوادث للذكاء الاصطناعي تتبع 6 مراحل:</p>
<p><strong>1. التحضير (Preparation):</strong> حدد فريق الحوادث (AI Security Team). جهز أدوات المراقبة. اكتب دليل الاستجابة.</p>
<p><strong>2. الكشف (Detection):</strong> راقب API، السجلات، أنماط الطلبات. استخدم تنبيهات للـ prompt injection والاستخدام غير الطبيعي.</p>
<p><strong>3. التحقق (Containment):</strong> إيقاف API مؤقتًا. منع الوصول للنموذج. عزل البيئة المتأثرة.</p>
<p><strong>4. الإزالة (Eradication):</p> تحديد الجذر (root cause). إصلاح الثغرة. تحديث الإعدادات. فحص النماذج.</p>
<p><strong>5. الاستعادة (Recovery):</strong> إعادة تشغيل النظام بعد الإصلاح. مراقبة مكثفة بعد الاستعادة.</p>
<p><strong>6. المراجعة (Lessons Learned):</strong> توثيق الحادثة. تحديث الخطة. تدريب الفريق على ما تعلمه.</p>
</section>
