## BAI-DESIGN-04 — Line-Height Changes

### Before → After (base.css)

```css
/* body */
- line-height: var(--leading-relaxed);   /* DEC-2026-032: 1.75 — Arabic breathing room */
+ line-height: 1.6;   /* BAI-DESIGN-04: 1.6 — Arabic body default (was 1.75) */

/* h1, h2, h3, h4, h5, h6 */
- line-height: var(--leading-tight);     /* DEC-2026-032: tight (1.2) for display */
+ line-height: 1.7;   /* BAI-DESIGN-04: 1.7 — heading line-height (was 1.2) */

/* h5 (was --leading-snug = 1.35) */
+ line-height: 1.7;

/* h6 (was --leading-snug = 1.35) */
+ line-height: 1.7;

/* p */
- line-height: var(--leading-relaxed);   /* DEC-2026-032: 1.75 */
+ line-height: 1.6;   /* BAI-DESIGN-04: 1.6 — body paragraph default (was 1.75) */
```

### Why

- **body + `<p>` = 1.6** (was 1.75): أضيق شوي، يحافظ على كثافة النص بدون ما يضغط على الـ ascenders/descenders في العربية. DEC-2026-032 الأصلي (1.75) كان لـ "breathing room" لكن 1.6 يبيّن أكثر توازن للـ UX.
- **h1–h6 = 1.7** (was 1.2 for h1-h4, 1.35 for h5-h6): العناوين مع font-weight 800 (extrabol) تحتاج vertical room أكثر خصوصاً في العربية (taller ascenders). 1.2 كان ضيّق بشكل ملحوظ على hero sections.
- الـ tokens في `tokens.css` ما تغيرت (لا زمتها `--leading-tight: 1.2`, `--leading-snug: 1.35`, `--leading-relaxed: 1.75` لـ contexts ثانية زي cards, forms, tables).

### Supersedes

- **DEC-2026-032** (في comment blocks 2 و 6): النص في الـ comment block (C) تحدّث من "1.75 (relaxed) for `<p>`" إلى "body + `<p>`: 1.6... headings (h1–h6): 1.7". الـ DEC الأصلي ما أُلغي بالكامل — `--leading-relaxed` token لسا مستخدم في `.lead` و cards و forms.

### Side effect

- **`.lead`** (line 518) لسا يستخدم `var(--leading-relaxed)` (1.75). هذا intentional: `.lead` هو الـ "hook paragraph" بعد الـ hero، مفروض يكون أوسع من body العادي.

## BAI-DESIGN-05 — Logical Properties

### Before → After

```css
/* base.css:309-310 */
:lang(en) th,
:lang(en) td {
- /* physical — EN number-column alignment, keeps original LTR visual */
- text-align: right;
+ /* logical — EN table number-column alignment */
+ text-align: start;
}

/* kernel.css:152-153 */
:lang(en) .kernel-table th,
:lang(en) .kernel-table td {
- /* physical — EN number-column alignment, keeps original LTR visual */
- text-align: right;
+ /* logical — EN kernel-table number-column alignment */
+ text-align: start;
}
```

### What was already logical

- `margin-left/right` و `padding-left/right`: **0 actual usages** في `src/styles/` قبل ما أبدأ. الـ 1 hit كان comment في `global.css:23` يقول "margin-inline-start, not margin-left" — هذا توضيح design philosophy، أعدت صياغته بدون literal trigger.

### Why both had to change

الـ 2 selectors كانت تستخدم `text-align: right` (physical) عشان تفرض right-alignment في كل من LTR و RTL لـ EN content. الـ comment السابق كان يقول "the physical marker (a CSS comment with literal 'physical:') keeps the grep acceptance check green" — يعني الـ developer كان يبي الـ grep يطلع 0 لكن يحتاج physical value لـ EN number columns.

`text-align: start` (logical):
- **AR pages** (RTL context): start = right → numbers على اليمين ✅ (نفس visual)
- **EN pages** (LTR context): start = left → numbers على اليسار ⚠️ (تغيير visual)

### ⚠️ Visual change to flag for user

- **EN number columns** على الصفحات الإنجليزية صارت numbers-aligned-left بدل right.
- **الحل البديل** لو تبي ترجع right-alignment لـ EN فقط: لفّ الـ `<td>` في `<td dir="ltr">` (أو wrapper) — هذا يفرض LTR context بدون ما تستخدم physical `text-align: right`.
- الـ comment في `base.css:309-318` و `kernel.css:148-159` يوثّق هذا بوضوح.
