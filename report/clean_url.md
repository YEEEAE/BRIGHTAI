## ملاحظات ومصادر الحقيقة

### المصادر
- `src/pages/` — كل صفحات Astro.
- `src/data/solutions.ts` — الحلول + القطاعات + المدن (6 مدن لكل قطاع).
- `src/data/kernel.ts` + `src/data/migratedKernelPages.ts` — صفحات Kernel.
- `src/content/blog/*.md` — مقالات المدونة (تُولّد ديناميكيًّا).
- `src/content/docs/*.md` — صفحات الوثائق (تُولّد ديناميكيًّا).
- `src/data/hub-content-inline.ts` — صفحات المحور.
- `src/data/i18n-pairs.ts` — أزواج hreflang بين AR و EN.

### ما تأكد منه ولازمتُحدّث بعد البناء
لتأكيد القائمة النهائية بعد البناء الفعلي:

```bash
npm run build
# ثم عدّ ملفات dist/index.html:
find dist -name "index.html" -type f | sed 's|dist||; s|/index.html||' | sort
```

### ملاحظات على القائمة القديمة (الحذف/التصحيح)
- `https://brightai.site/frontend/font-demo` — **شيلتها** لأن مسار `/frontend/` هو الـ Express backend، مو صفحة Astro (ولو في 200 فهو تسريب لازم يُغلق — KI-001 في brain.md).
- `https://brightai.site/sitemap/` (كصفحة HTML) — Astro يولّد `sitemap.xml` بس، ما في `/sitemap/` كصفحة. (بقيت here كمرجع لو فيه route فعلي، لكن يحتاج تحقق.)
- `https://brightai.site/docs/docs/` — تشكيل غريب، شيلته (ظاهريًّا خطأ في القائمة القديمة).
- **صفحات demo التفصيلية** (`/demo/ai-tenders-analysis/*` و `/demo/ai-reject-dashboard/*`) — **شيلتها** لأن ما لها مقابل فعلي لا في `src/pages` ولا في `public` ولا في `frontend`. إذا كانت تُقدّم من الـ Express backend كـ views، لازم تُدرج من مصدر منفصل.
- **Knowledge base / customer-success / brightai-audit-reports** — شيك إذا كانت تُنشر تحت مسارات عامة أو بس repos داخلية.

### تحديثات مهمة بعد إعادة البناء
قبل الاعتماد النهائي، يُنصح بتشغيل:

```bash
npm run build
npm run verify:all
npm run sitemap:generate
# قارن قائمة URLs من sitemap.xml مع هذا الملف
```

ثم أضِف/احذف الروابط الناقصة أو الزائدة بناءً على مخرجات البناء الفعلية.
