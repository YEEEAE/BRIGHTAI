## 3. القرارات (DEC-A11Y-002, 003)

### 3.1 DEC-A11Y-002 — Form aria-describedby pattern

**النمط الموحّد** عبر `LeadForm.astro` و `KernelLeadForm.astro` و `contact/index.astro`:

```html
<input
  id="name"
  name="name"
  required
  aria-required="true"
  aria-describedby="name-error"
  ...
/>
<span id="name-error" class="form-field__error" role="alert" aria-live="polite" hidden></span>
```

**القرارات**:
- `id` ثابت على كل error span (نفس اسم الحقل + `-error` suffix)
- `aria-describedby` على الـ input يشير إلى الـ error span
- `role="alert"` + `aria-live="polite"` على الـ span — يخلي screen reader يقرأ النص تلقائياً لما يتغير (حتى لو الـ input ما هو في focus)
- `hidden` attribute ابتدائياً — ما يظهر في الـ DOM بصرياً إلا لما يحتوي نص خطأ
- `novalidate` على الـ form — نتحكم في رسائل الخطأ يدوياً عبر الـ JS (مو native browser validation اللي ما يدعم العربية بشكل كامل)

**تأثير**: screen reader users الحين يسمعون "Email, edit text, invalid entry, البريد الإلكتروني مطلوب" بدل ما يبقوا صامتين.

### 3.2 DEC-A11Y-003 — Shared focus trap helper

**المشكلة**: 3 modals في kernel + MobileNav كلها تحتاج focus trap. لو كررنا 60 سطر × 4 = 240 سطر.

**الحل**: helper module `src/scripts/focus-trap.js` يفعل 3 أشياء:
1. **Exports `createFocusTrap(modal, options)`** للاستخدام اليدوي
2. **Auto-applies** على كل `[role="dialog"][aria-modal="true"]` في الصفحة عبر MutationObserver
3. **Handles astro:page-load** تلقائياً (view transitions)

**الـ pattern**:
```js
// في BaseLayout.astro
<script>
  import '../scripts/focus-trap.js';
</script>

// في modal HTML
<div role="dialog" aria-modal="true">...</div>
// لا حاجة لأي JS إضافي — auto-applier يكتشفه
```

**التأثيرات الجانبية على MobileNav**:
- MobileNav عنده focus trap inline خاص فيه (موجود قبل). الـ auto-applier يحاول يطبق focus trap ثاني — قد يسبب تعارض.
- نختبر يدوياً بعد deploy. لو تعارض، نحذف الـ auto-applier من MobileNav (نخليه opt-in فقط) أو نحذف focus trap inline من MobileNav ونعتمد على الـ auto-applier.

### 3.3 DEC-A11Y-003 — aria-current في main nav

**النمط**: `aria-current="page"` على الـ active link فقط. الـ Astro template:
```astro
<a
  href={item.href}
  aria-current={isActive(item.href) ? 'page' : undefined}
>...</a>
```

`undefined` بدل `null` — Astro يحذف الـ attribute تماماً لما يطلع undefined. هذا أنظف من إضافة `aria-current="false"`.

**التغطية**:
- Header: dropdown trigger + dropdown link + single link (3 مواضع)
- MobileNav: accordion sub-link overview + sub-link + single link (3 مواضع)

**التأثير**: screen reader users يسمعون "current page" عند قراءة الـ active nav link.

## 4. قبل/بعد — أمثلة ملموسة

### 4.1 Form errors (LeadForm)

**قبل**:
```html
<input class="field" type="text" id="name" name="name" required aria-required="true" />
<!-- ما في error span مرتبط -->
```

**بعد**:
```html
<input
  class="field"
  type="text"
  id="name"
  name="name"
  required
  aria-required="true"
  aria-describedby="name-error"
  ...
/>
<span id="name-error" class="form-field__error" role="alert" aria-live="polite" hidden></span>
```

### 4.2 Focus trap (kernel modals)

**قبل**: Tab من داخل المودال يطلع لـ URL bar أو الصفحة الخارجية.

**بعد**: Tab/Shift+Tab يبقى داخل المودال. Escape يقفل. Focus يرجع للزر اللي فتح المودال. باقي الصفحة تصير `inert` (screen reader يتجاهلها).

### 4.3 aria-current (Header)

**قبل**:
```html
<a href="/solutions/" class="site-header__nav-link site-header__nav-link--active">الحلول</a>
```

**بعد**:
```html
<a
  href="/solutions/"
  class="site-header__nav-link site-header__nav-link--active"
  aria-current="page"
>الحلول</a>
```

## 6. المخاطر المتبقية

- **LOW**: MobileNav عنده focus trap inline + الـ auto-applier قد يحاول يطبق ثاني. نختبر بعد deploy. لو تعارض، نخلي MobileNav opt-out (نضيف `data-focus-trap="false"` أو نحذف الـ inline trap).
- **LOW**: aria-describedby يضيف ~150 بايت لكل form (5 حقول × ~30 بايت). تأثير performance ضئيل.
- **LOW**: focus-trap يطبق `inert` على siblings. لو في كود يستخدم `inert` بطريقة أخرى، قد يتعارض. نختبر.
- **LOW**: role="alert" مع aria-live="polite" — تكرار؟ لا. role="alert" = implicit aria-live="assertive" لكن aria-live="polite" يتجاوزه. الـ pattern الشائع: role="alert" + aria-live="polite" = error يظهر ويتلى بدون مقاطعة (مقابل assertive اللي يقاطع). صحيح.
