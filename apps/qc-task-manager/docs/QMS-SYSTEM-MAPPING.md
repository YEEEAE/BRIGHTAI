## Reading rule

This is an as-is engineering audit. It does not create, interpret, or import an
ISO, FDA, SFDA, GMP, GLP, GDP, or other external requirement. The four labels
below are mandatory:

- **CONTROLLED COMPANY REQUIREMENT** — a requirement is only stated here when a
  controlled company source is identified. If no source was found, the value is
  `SOURCE REQUIRED`.
- **CURRENT APPLICATION RULE** — behaviour evidenced by current code, schema, or
  a named test contract. It is not automatically a company requirement.
- **ENGINEERING RECOMMENDATION** — a proposed control, clarification, or design
  action. It is not encoded policy.
- **SOURCE REQUIRED** — the exact controlled source, owner, or decision still
  needed before the application should encode the rule.

No WI content was reconstructed. The WI catalogue remains limited to supplied
page 1/3 rows; pages 2/3 and 3/3 are not represented or inferred.

## Evidence boundary

The mapping is based on the current tree at HEAD `394be485` and the current
application files. Historical audit reports and earlier PASS statements are not
used as proof. The closure contract remains binding; this document does not

## Cross-process findings

### Missing digital controls

- Controlled source identity is captured for imported document rows, but source completeness is not a general release gate; WI pages 2/3 and 3/3 remain unavailable.
- FAIL/HOLD disposition, impact assessment, release authority, and linkage to finding/CAPA are not universal workflow controls.
- RCA adequacy review, CAPA effectiveness acceptance, maintenance release, and training competency are not distinct records.
- Equipment serial number is not unique in the current schema.
- Change requests do not have a universal impact/validation/rollback/effectiveness model.
- Retention is awareness-only; there is no archival/destruction workflow in the inspected retention module.

### Unnecessary or potentially over-broad controls

No control was removed or declared unnecessary as a company matter. The following
are application rules that should not be promoted to QMS requirements without a
source: five-year retention, calibration due-soon semantics, free-text
non-compliance tokens, sample-count range/default, retest eligible states, and
the requirement for a meaningful rejection note.

### Ambiguous workflow

- Test `final_result=HOLD` is not a dedicated lifecycle state and has no sourced release path.
- A FAIL does not automatically create a Finding, RCA, CAPA, or retest.
- RCA has no separate review state.
- CAPA approval is a text field; the application does not establish whether it is an e-signature.
- Maintenance completion is not the same as equipment release for use.
- Acknowledgement is not defined as training completion or competency.
- Report generation is auditable, but report approval and controlled-record status are not defined.

### Manual steps not represented

Impact assessment, product/sample disposition, investigation decision, method/specification review, training effectiveness, equipment release, document-content review against the controlled source, and human/operator/UAT evidence are outside the current digital rule set.

### Source-blocked functionality

The app must not complete WI catalogue coverage, invent missing WI pages, or
encode external signature/retention/FAIL-HOLD requirements until the relevant
controlled company source and owner decision are supplied.

### Policy encoded without source

The audit found application policy in code for: calibration status windows and
tokens, five-year retention awareness, retest eligibility/reasons, sample-count
limits/default, maintenance status values, document review windows, and some
approval/closure gates. These remain labelled **CURRENT APPLICATION RULE**;
they are not certified company requirements.

### Hidden compliance assumptions

- A hash seal is treated as strong record integrity, but it does not by itself prove the company’s signature meaning.
- `APPROVED` is treated as immutable, but approval authority and release meaning still need a controlled source.
- Acknowledging a document is treated as sufficient completion for the current feature, but training/competency expectations are unknown.
- A report audit row is treated as sufficient download evidence, but report review/approval and retention are not defined.
